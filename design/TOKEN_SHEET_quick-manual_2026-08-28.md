# クイックマニュアル（manual/quick.html）設計メモ＋トークンシート

2026-08-28・Claude。design-web スキルの手順で作成。対象は**テスター向けクイックマニュアル**
（プレゼン資料風・章ごと1ページ・実画像入り）。既存の冊子 `manual/manual.html` は
「深く引く用のベース」としてそのまま残す（本人指示）。

## 設計メモ（design-policy の5つの問い）

1. **誰が・どの場面で**: 招待されたテスターが、招待直後に最初に受け取る一枚。
   アプリを開く前の期待づくりと最低限の道案内。読了90秒を目標。
2. **どんな気分に**: 「開演前」。客電が落ち、幕が上がる直前の高揚。読み終えたら今すぐ開きたくなる。
3. **固有の核**: **劇場の暗闇と光**。各ページを「場（SCENE 00〜07）」に見立て、暗い舞台に
   主役をひとつだけ立てる（原則集の「集中」技法とスポットライト・チェックを文字どおり劇場でやる）。
   図版は描き起こしのモックではなく、**アプリが実際に描いた舞台の絵**（canvasから抜いた実画像）。
4. **踏襲と外し**: 踏襲＝1ページ1メッセージ・高ジャンプ率（プレゼンは「見る」機能優先）。
   外す＝白背景ビジネススライド・箇条書きの羅列・青系グラデ／ガラスカードのAI定型。
   冊子（昼の机・紙）に対し、こちらは**夜の舞台**として意図的に反転させる。同じ製品の昼と夜。
5. **機能条件**: 16:9横（1280×720）／印刷はA4横・1場1ページ→そのままPDF配布物／
   WCAG AA実測（下記・全て測定済み）／書体2種以内／動きは prefers-reduced-motion で無効化／
   認証内配信を想定し `manual/` 配下に置く。

**比較した3方向** → A採用。
A. 夜の劇場・スポットライト型（採用。核が題材そのもの）
B. 冊子の縮約（白地A4横）— 既存冊子と役割重複、高揚が出ない
C. ポスター・散乱系 — 楽しいが道案内の明快さを損なう。大胆なジャンプ率だけ借りる

**光の表現について**: グロー・グラデ装飾は使わない（design-policy／本体CSSの作法と同じ）。
劇場の光は**画像の中の舞台照明に語らせ**、スライド自体はフラットな暗幕＋規律で組む。
許すのは本体 body::before と同作法の減衰ビネット（不透明度0.05）のみ。

## 生成・再生成の手順（このMacでの実測手順）

1. ローカル配信: `python3 -m http.server 8765 -d /tmp/shosai-preview`（iCloud直下は
   プレビュー起動プロセスから読めないため /tmp へ rsync してから）
2. 図版の再撮影: `stage.html` を開き、照明3灯（月あかり=hang・袖のあかり=ss・顔あかり=front）を
   追加→名前札3種と〈見る位置の図〉をオフ→ `#stage-canvas` / `#stage-plan-canvas` の
   `toDataURL()` を一時受け口（/tmp/capture-server.py・port 8766）へPOSTして `manual/img/` に保存。
   幕の図は「前幕ひとそろい」を置き選択解除してから撮る。**undoでの状態戻しはしない**（照明まで消える）
3. PDF: `Google Chrome --headless=new --print-to-pdf=... --no-pdf-header-footer <quick.htmlのURL>`
   （@page 338.7×190.5mm ＝ 16:9。1場=1ページ）
