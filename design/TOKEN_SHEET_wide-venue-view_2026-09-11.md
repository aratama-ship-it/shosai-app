## 7. 3Dカメラ（FPV・stage-first-person.js）専用トークン（2026-09-12 追加）

同じ会場の器を、擬似パースの正面図（stage-house-view.js・6章まで）ではなく本物の透視投影で描くための値。
色は6章と同じものを流用し、3D特有の寸法だけをここに追加する。

| 用途 | 値 | 決めた理由 |
|---|---|---|
| 客席（回り込み含む）の生成元 | `bowlTiers`（stage-venue-lines.js）をそのまま使う。**新しい段の数値を作らない** | 正面図側と二重管理にしない |
| 左右スタンドの配置 | 正面の各行を90°回転し、x=±(舞台幅/2＋その行のdistanceM)、zは舞台前端(D/2)から**舞台奥行き＋左右スタンドの奥行き分**まで並べる（正面図側と同じ「舞台幅/2+通路4.0m」を内側の基準にする） | 実写の「左右に開けたスタンド」を再現。器のデータは1系統のまま、置き方だけ3D側で持つ |
| 向こう側（round）の配置 | 正面の各行をz軸で反転し、舞台の奥（-z側）に鏡像配置 | `three`は左右のみ、`round`だけ奥にも生成 |
| 天井のリブ（ドーム） | 同心の弧 7本（`apexM`〜`eaveM`を7分割した高さの緯線）＋放射16本（低い側から高い側へ`apexM`地点で収束する経線）。色は6章と同じ `rgba(156,130,63,0.28)`／補助 `rgba(156,130,63,0.16)` | 写真で最も「大きさ」を伝える要素を3Dでも見えるようにする |
| 天井のリブ（トラス） | 平行な梁8本。高さは`eaveM`〜`apexM`の間に均等割り、奥行き方向（z）に通す | ドームと同じ考え方をトラス形状に適用 |
| 屋根が無い会場 | `roofKind:"open"`（野外フェス）ではリブを描かない。空は既存のFPV屋外表現に任せる | 6章と同じ扱い |
| 床のブロック割り（3D） | 舞台前方の床（フィールド・アリーナ席の平土間）に、通路の暗い線（`rgba(0,0,0,0.45)`）を格子状に引く。格子は6章と同じ「左右5×奥行き3」 | 立体でも同じ手がかりを出す |
| 客席の生成範囲 | 器を持たない会場（劇場・サーカス）は**既存の固定13列モデルのまま**（触らない）。器を持つ会場だけ`bowlTiers`から生成する | 既存の操作感・見え方を変えない |
| 視点プリセットの俯角 | 前回追加した `bowl-*` プリセットと同じ式（`atan(目の高さ/距離)`）。左右・奥のプリセットは無し（正面のみ） | まずは正面方向の見晴らしを優先。左右プリセットは後段の検討 |

## 4. 動き

| 項目 | 値 |
|---|---|
| 席の切り替え | アニメーションなし・即時（既存の席切替と同じ）。比較のため行き来するので待ち時間を作らない |
| 首振り（既存） | そのまま。引きの席でも掴んで視線を動かせる。既定の俯角だけ席が持つ |
| 群衆 | 動かさない（静止）。席ごとのばらつきは毎フレーム同じ値であること |

## 5. 文言

- 数値は整数＋単位。距離は「62m」、高さは0.1m刻み。小数を判断に要らない場面で出さない。
- 到達性は1行で言い切る。例:「120m・上段最後方 — 表情は届かない（20m）／身体の動きも届かない（35m）／床は見える」。
- 「モデル計算」「仮の寸法」は隠さず明示する。実測と呼ばない。
