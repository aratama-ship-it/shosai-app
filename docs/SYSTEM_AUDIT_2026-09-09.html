中 A-2 SW更新修正に「新HTML＋旧JS」の版ずれ経路が残る 事実（再現済み・条件付き）

根拠
stage-sw.js（未コミット差分）。install は shell が揃った時だけ skipWaiting、activate は removePreviousCachesWhenReady で旧キャッシュを温存——ここは 9/7 レビュー1件目の対処として妥当。ただし fetch の navigate 分岐は オンラインで取れた stage.html を無条件に新 CACHE_NAME へ put する。新shellの JS（?v=319）が未取得のまま次にオフラインになると、cachedAppShellResponse は新キャッシュの stage.html を返し、その中の stage-sketch.js?v=319 は全キャッシュに無い（旧は ?v=318 のみ）。caches.keys() の順序保証も無い。
再現
docs/system-audit-2026-09-09/repro-a2-sw-mixed-version.mjs（stage-sw.js の実ソースを Node vm で実行）。caches.keys() が作成順＝旧が先: 旧HTML＋旧JSで整合（起動可）。新が先: 新HTML＋JS欠落＝起動不能。仕様上 keys() は作成順なので現状のブラウザでは顕在化しにくいが、「揃っているキャッシュ」を選ばず列挙順に頼る設計は脆い。高→中に下げた。
備考
9/7 の追加レビュー（RELEASE_FOLLOWUP_2026-09-07.html）自身が「旧HTMLと対応するJS/CSSがセットで残ることを検証する」と書いている。今の差分にその検証は無い。
提案
①navigate での put を「shell が揃っている時だけ」または「揃うまでは旧キャッシュ側へ」に変える。②cachedAppShellResponse で stage.html を返す時は「揃っているキャッシュ」を優先。③9/7 と同じ Node vm で「旧完備＋新不完備＋オンライン1回→オフライン」の再現テストを tests/stage-pwa-offline-warm.test.mjs に追加。
