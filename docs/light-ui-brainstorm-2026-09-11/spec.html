1. 一文の定義

舞台の絵の上で、見せたい光の形や動き、変わるタイミングを作り、再生できます。動きの動画と図、短い説明を照明担当者へ渡して、実現方法を相談できます。作るのは演出意図のスケッチです。灯体・回路・DMXの設計、実際の明るさや照射可否の検証、照明機器の操作は行いません。

見出し語は「照明を作る」ではなく「光の見え方と動きを作って伝える」。理由: 天平さんが挫折したのは照明ソフトの学習コスト（機材・数値中心）であり、そこへ戻らないため。

2. 設計メモ（design-web Step 1・5つの問い）

誰が・どの場面で演者・演出家が、稽古〜照明打合せ前に、iPad（横持ち）で自分の場面の「動く光」を作り、照明プランナーへLINE等で渡す。受け手はスマホで見る。
どんな気分に作っている間: 「動画を切り抜くより早く、思った動きになった」。渡した後: 「これは案だと伝わり、照明さんから代案が返ってくる」。
固有の核照明を作るのではなく「光の動きを演出の言葉で作る」。機材を持たないこと自体が核。舞台スケッチの「技術図面ではなく意思疎通のスケッチ」という既存の立場の延長。
踏襲／外す踏襲: 既存の側パネル語彙（真鍮見出し・乳白文字・44pxタップ）、意図カード、動線再生。外す: 照明卓風の数値UI、灯体アイコン、ビームの物理レンダリング、手描き風で「案」を装う演出。
守る機能条件PCの左パネル268px幅で1画面往復。全欄必須にしない。安全判定を与えない。既存データ（version 3／4）と往復できる。動画はiPadで生成→スマホで再生できる形式だけ採用。

照明語は表示名の横に薄く出すだけ。書き出しには演者向け表示名と説明文を載せ、照明語は括弧で併記。「fan」「wave」「fly」は現場で意味の幅があるため説明文を必須にする（一般知識・Codex指摘）。

調整項目は3つだけ: 本数（1／2）、範囲（小〜大）、速さ（ゆっくり／普通／速い、または拍）。光の関係（一緒に／向かい合わせ／順に）は複数本のときだけ表示。太さ・色は初期値固定で、2回目に開く。

4. タイミング（BPM）とストロボ

拍に合わせる

  • 1周期＝左端→右端→左端（往復）。片道は別の状態として保存。
  • 既定: 合図で端から開始、半周期で反対端、1周期で元の端、以後繰り返し。「中央から開始」「拍頭で折り返す」は2回目。
  • BPMは数値入力またはタップ。曲全体で一定として再生（途中のテンポ変化は未対応と明示）。舞台スケッチには現在BPMの概念が無い（コード確認済み）。
  • 1周期＝1／2／4／8拍。「速さ」と「拍に合わせる」は別の項目。
  • 複数本の時間差は自由指定せず、プリセットで固定（対称＝半周期、順に＝一定間隔）。

点滅（ストロボ）

  • 入力: 速さ（遅い／普通／速い、または1拍・2拍・8分・16分）、範囲（全体／一部／選んだ光）、長さ（1拍／2拍／合図まで）、きっかけ、点滅後（止まる／通常点灯／消える）。
  • 照度・周波数の数値・発光方式は入力させない。
  • 点滅を指定したときだけ質問を提案（下記文面）。プレビューは自動再生しない（突然の点滅を避ける操作上の配慮であり、安全判定ではない）。
点滅を含む案です。光過敏発作などへの影響は、
条件や人によって異なります。会場・照明担当者と、
実施条件・事前告知・代替表現を相談しますか。
舞台スケッチは安全性を判定しません。
［質問に追加］［今回は追加しない］

構成の理由

  • 上から「選ぶ→調整→再生→書き出す」の一方向。1画面で往復でき、中央の正面図は常に見える。
  • プリセットは2列グリッド・各44px以上（既存の「次のシーン作成モーダル」と同じタップ基準）。一覧は静止サムネ、選択中だけループ再生（6〜10個同時再生はiPadの負荷と視線散乱が勝つ、Codex推測）。動きを減らす設定では静止。
  • 「拍に合わせる」をオンにすると「1周期 1／2／4／8拍」「BPM 数値／タップ」「開始位置 端から」が下に開く。オフのときは既存の「速さ」で再生。
  • 「点滅 あり」で速さ・範囲・長さ・点滅後が開き、質問の提案が1回だけ出る。
  • 再生は明示ボタン。指を離した瞬間の自動再生や、一覧サムネの一斉再生はしない。
  • 現在地表現は既存語彙（真鍮の下線＋背景一段明るく）の2種。新しい色・角丸・影は足さない。
  • 末尾の注記は常時表示。書き出した動画と図にも同文を焼き込む。

正面図側の描画

  • 光線は既存の照明駒（灯体の丸＋プール）を使わない。出どころは「図の仮位置」として薄い点で示し、会場の設置候補には変換しない。
  • 実線＝いまの一瞬、破線＝動く範囲、矢印＝方向、ラベル「光の動き・案」。同時に見える本数と説明用の線を混ぜない。
  • 奥行きの編集は初回なし（正面図固定）。平面図は2回目。

6. 書き出し（順0で先に成立を確認）

動画短いループまたは指定回数。音声なし（初回）。「光の動きの案／灯体位置・DMX・安全性は示さない／シーン名・版・出力日」を焼き込む。形式はiPad Safariで生成→保存→LINE相当で受け渡し→iPhone/Androidで再生できたものだけ採用（MP4候補。舞台スケッチには録画コードが現在無い）。
1枚図同じ再生データから始め・折り返し・終わりを切り出し。凡例「実線＝一瞬の例、破線＝動く範囲」「灯体位置・照射可能範囲ではない」。
一文＋相談欄「細い光2本が舞台奥で互いに横切る。速さ普通、合図まで繰り返し。色・出どころ・本数は相談したい。」＋守りたい条件／変えてよいこと／相談したいこと。既存の打合せ用出力（キューシート拡張）へ同じ案IDで接続。

7. データ構造（骨子）

scene.lightingIntent.lightMotion = {
  version: 1,
  coordinateSpace: "front",            // "plan" は後から
  beams: [{ id, width, color, visible, presetId, relation,
            path: { kind: "line"|"circle"|"polyline", points: [...], loop: "once"|"ping-pong"|"untilCue" } }],
  timing: { mode: "free"|"fixed-bpm"|"tap", bpm, cycleBeats: 1|2|4|8, startPhase: "edge", repeat },
  flash:  { enabled, beatDivision, scope, durationBeats, after: "hold"|"normal"|"off" },
  cues:   [{ triggerType, triggerRef, action: "start"|"stop"|"hold"|"flash" }],
  references: [{ ref, range, focus }],
  notes:  { keep, flexible, ask },
  origin: { kind: "standalone"|"scene", sceneId, revision }
}
  • 正本は意図カード内。動画・PNG・GIFは派生物。
  • 時間の正本は秒ではなく位相／拍。BPM→秒は再生時に導出。durationMs を正本にしない。再生位置は保存・Undoの対象にしない（既存の音源処理と同じ方針）。
  • 舞台登録なし入口は「最小プロジェクト（空ステージ＋シーン1）」として同じ形式で保存。既存ショーへは「新しいシーンとして追加／選択シーンの案へコピー／別案として追加」を本人が選ぶ。自動上書きしない。同じシーンに既存の案があれば置換でなく別案。
  • 単独入口で作らないもの: 独自アカウント、独自共有基盤、機材DB、独自会場形式、専用保存形式。

9. 既存コードとの接続点（実装者向け）

  • normalizeScene()／normalizeLightingIntent()（stage-sketch.js 391付近）: lightMotion を落とさず、version 3／4と往復。
  • 保存・読込・Undo／Redo: 意図カードと同じ経路（checkpoint()・persistSoon()）。
  • 正面図レンダラー（drawFrontVenue 系）: 光線の描画と再生。既存の動線再生（requestAnimationFrameのrun.rafループ・16594付近）の補間を再利用できるか確認。
  • 音楽パネル: BPM参照の入口だけ。再生位置を正本化しない（4772付近の設計と同じ）。
  • 打合せ出力: 既存キューシート（17612付近）を拡張し、動画・図・一文・相談欄・返答を同じ案IDへ。
  • stage-i18n.js: 演者向け語を主、照明語は補助。i18n-prep のGLOSSARYと矛盾させない。
  • Service Worker・?v=: 製品へ組み込むときだけ全箇所一括で上げる（既存の運用ノート）。
  • テスト: 新旧データ往復／複数光線の順序と位相／1周期の端点定義／BPM導出の再現性／点滅設定の保存／3点出力の同一リビジョン／単独→既存シーンの明示的取り込み／既存の意図・照明駒・音楽を上書きしないこと。
