# ブレスト依頼: 舞台スケッチの「照明」UI/UX再設計（照明さんとのコミュニケーションツールとして）

あなたはClaude（私）とユーザー（元サーカスアーティストのショー制作者・演出家）の壁打ち相手です。
目的は「別の角度からの案」と「Claude案への厳しい批評」。同意の羅列は不要。

## 背景（自己完結の要約）
- 対象: Webアプリ「舞台スケッチ」(Stage Sketch)。演出家・演者が舞台を組み、演者・セット・照明の駒を平面図／正面図／3Dに置き、シーンを並べて共有するスケッチ道具。主用途は演劇を含むサーカス。技術図面・安全検証は作らない方針（LPにも明記）。iPad横持ちの側パネル＋中央キャンバス構成。
- 今回の発端: 利用者から「ムービングライトなど照明機器のUI/UX」の要望が出た。ただしユーザーの判断は「専門性（DMX・灯体データ・パン/チルト）が欲しいのではなく、**照明さんとのコミュニケーションツールとして優秀である必要がある**」。これを軸に照明まわりのUI/UXを再設計したい。
- 現状の照明機能:
  1. 照明駒4種＝「どこから来る光か」で分類: 吊り(バトン真下)／SS(袖から横切る)／前明かり(客席上から顔へ)／転がし(床置き)。各駒は灯体位置と当たる輪(プール)を別々に掴んで動かせ、直径・強さ(シーンごと)・色を持つ。光の動線を引くと灯体は固定でプールだけ移動する（＝原始的な「動く光」は既にある）。
  2. プリセット: 基本の3照明(地明かり＋バック＋ブッチ)／バック8台＋AC／トップサス／サイド3段／ライトカーテン／3台口バーライト等を一括で組む。組は一体で動き「ばらす」で個別化。
  3. 「光の意図カード」(シーン単位・実装済み): 意図→視線→見せ分け(演者/背景/空間: 見せる/柔らかく/隠す/シルエット/分離/変容)→変化(合図: 場面頭/動作/台詞/音楽/時間/手動、種類: hold/fade-in/fade-out/snap/crossfade/blackout、体感速度: 即/速い/呼吸/ゆっくり)→任意(雰囲気/参照/実装候補=「要照明担当者確認」表示/safetyStatus常にnot-assessed)。カードは図上に作図の印として重ねられる。設計原則: 機材より先に知覚を書く／雰囲気だけで終わらせない／配置と意図を一方向に固定しない／安全判断を偽装しない。
  4. 印刷: 明かりのキューシート（シーンごとに 点く／消える／強さ変化 の表）。
  5. 前日(2026-09-11)の別ブレストの結論: 技術プロット・照明映像プロットは「作らない・受け取る・薄く繋ぐ」。MVR読み込みは需要次第の低優先。現場向けには役割別ビュー(照明/音響/舞監)構想があり、役割ごとの現場メモ・共有済み/個人メモの分離・正本を直接編集させない注釈レイヤー、という開発方針が既にある。
- 制約: 灯体名・回路・DMXを必須入力にしない。安全認定を与えない。側パネルの幅・高さ・連続操作に収める（書類の見た目で構成しない）。詩的コピー禁止・具体的な文言。既存駒・プリセット・意図カードの意味は壊さない（拡張はよい）。日本の小劇場〜中劇場のサーカス／演劇の現場慣行（きっかけ表・香盤表・照明打合せ・仕込み・シュート・場当たり）を前提にする。

## Claude(私)の案 — 「機材ではなく、光の振る舞いと合意の記録を単位にする」
A. **「振る舞い」軸を足す**: 現行4種は「どこから」。追加するのは「どう動く/変わる」: 止まる／人を追う(フォロー)／空間を走る(スイープ)／色が変わる／点滅・ストロボ／光線が見える(ヘイズ前提)。ムービングライトは機材名として置かず「追う光」「走る光」として置く。それをムービング・ピンスポ・手動フォローのどれで実現するかは照明さんが決める（書き出しでは「実現候補: ムービング／フォロースポット」と併記）。
B. **「照明さんへの打合せシート」出力**: 既存キューシート(点く/消える/強さ)を拡張し、シーン順に 意図カード要約＋平面図サムネ＋変化の合図＋NG事項＋優先度(必須/できれば)＋質問 を1枚に。演出家が口頭で説明する代わりに渡す。印刷/PDF/共有リンク。
C. **「やってほしくないこと(NG)」を一級市民に**: サーカス固有(空中芸の演者の目に前明かりを入れない、ディアボロの紐が背景に溶けないよう背景の明度、床置きの機材を動線に置かない等)。意図カードの任意欄でなく、図上に「暗く保つ領域」「眩しさNG方向」として描ける。
D. **照明さんの返答を同じ場所に記録**: できる／できない／代替案、状態(未確認/確認済/変更あり)。役割別ビューの「照明」でそのまま見て返せる。safetyStatus=not-assessed の設計を「確認の記録」へ発展させる。
E. **図上の「追う光」表現**: 演者駒を選んで「この人を追う」→動線に沿ってプールが追随して描画。正面図には淡いビームだけ。3Dの物理的ビーム表現は作らない。
F. **用語の橋渡し辞書**: 表示は素人語(追う/走る/見える光線)、書き出しには照明語(フォロー/パン/ヘイズ＋ビーム)を併記。既存i18n用語集(上手=cour等)と同じ仕組み。

## あなたへの依頼（順番にすべて答える）
1. **照明さんの側から見た批評**: 演出家からの照明要望を受ける照明プランナー／オペレーターが、実際に困る・助かる要望の形は何か。日本の現場慣行で実在する受け渡し文書（きっかけ表、照明要望書、Qシート、ラフ図など）と、そこでよく起きる齟齬を挙げる。事実として述べるものは根拠の種類(一般知識/推測)を明記。
2. **Claude案A〜Fの批評**: 各案について「照明さんとの意思疎通に効くか」「作りすぎではないか」「既存の意図カード/駒/前日結論と矛盾しないか」を判定。捨てるべき案を最低1つ指名。
3. **別角度の案を3〜5個**: 例として、ムービングを一切モデル化しない案、意図カードだけを強化する案、写真/動画参照中心の案、シーン間の「変化」だけを主役にする案、照明さん側が使う入力面の案など。それぞれ「誰が・いつ・何を入れて・誰が受け取るか」を1行で。
4. **逆張り**: 「照明UIを増やすほど演出家が照明さんの領分に踏み込み、関係が悪くなる」という立場から、最小限にすべきものと、あえて作らないべきものを述べる。
5. **MVPの提案**: 上記を踏まえ、最初の1〜2週間で作るべき最小セット（画面・入力項目・出力）を、優先順位付きで。iPad側パネル幅に収まる情報設計の指針も。
6. **本人に確認すべき未決事項**を最大5問（回答で成果の方向が大きく変わるものだけ）。
