0.5 収束した設計（推奨）

「照明を作れるアプリ」の定義（Codex案・LP文言に使える）

舞台の絵の上で、見せたい光の形や動き、変わるタイミングを作り、再生できます。動きの動画と図、短い説明を照明担当者へ渡して、実現方法を相談できます。作るのは演出意図のスケッチです。灯体・回路・DMXの設計、実際の明るさや照射可否の検証、照明機器の操作は行いません。

見出しは「照明を作れる」単独にせず「光の見え方と動きを作って伝える」まで具体化する。

プリミティブ3つ（機材なし）

  • 光の形: 太さ・色・空中の光線として見せるか。
  • 動かし方: 「光の先を動かす」（出どころ固定で向きを振る＝サーチライト）と「光全体を動かす」を区別。始め・終わりを置いて往復／円／横切るを選ぶのが基本、自由になぞるのは曲線用の追加手段。
  • 時間: 動く速さ・繰り返すか・始めと終わり。音楽の錨への接続は必要な場面だけ（拍モデルを必須にしない）。

未指定の出どころは「図の仮位置」と表示し、会場の設置候補には変換しない。

出力3点セット（同じ再生データから一括生成）

  1. 短い動画（MP4候補。iPadで生成→LINEで受けたスマホで再生できるか先に確認）。「光の動きの案／相談したい点／変更できる点」のラベルを動画自体に残す。
  2. 1枚図（始め・折り返し等を再生データから切り出し。凡例「案・灯体位置ではない」）。
  3. 一文＋相談3欄（守りたい条件／変えてよいこと／相談したいこと）→既存の打合せ用出力へ接続。

一度きりの演出を説明用に繰り返すことと、演出自体の反復を区別。書き出しで勝手に終点→始点へ戻さない。

捨てた案・作らないもの

  • 手描き風・粗い再生で「案」を担保する案（動きの滑らかさが主題なのに壊す）。担保は画質でなく明示ラベル。
  • 灯体名・回路・DMX・パン/チルト数値、照度・照射可否の表示、機材台数の推定。
  • 素人語→照明語の自動置換。全種類の動作型ボタン。3D編集。GIF併設と独立アプリ公開（初回試作から外す）。
  • 既存tempo（変化の体感速度）を「動く速さ」に流用すること。

統合の形

最初から舞台スケッチ本体の独立モジュール（描画・再生・編集・出力を分けて独立検証）＋開発用の小さな試験画面。シーン・演者・セット・音源は既存正本を参照し、光の動きはシーンの意図カードに属する案として保存。返答記録で案を自動変更しない。注意: 前日ブレストの「シーン内キーフレーム／音楽の錨」は構想段階で、共通時間軸が製品実装済みとは確認できていない（Codexがコードで確認: 再生位置は保存・Undoしない設計）。工数から差し引かない。

検証方法（「動画切り抜きより速い」は仮説）

天平さんが説明したい1場面を決め、普段の「動画を選ぶ・切る・説明を添える」と試作の両方で作り、照明プランナーに両方を見せて方向・範囲・速度・光どうしの関係・未決事項を読み取ってもらう。一箇所変更して渡し直す時間も比較。成功基準は「2分で動いた」ではなく「準備・修正が負担にならず、照明さんが重要な動きを同じ意味で読めたか」。

逆張り（両方残す）

既存映像の説明を速くする道具（切り抜き動画＋舞台図の範囲注記＋「参照する点／変更したい点」の一文）は、本人が適切な映像を持ち動きの質感が重要な場合に勝つ。前例のない動きや「この光だけ逆へ」の変更には弱い。新しい動きを作る道具と比較しつつ両方残せる。

1-1. 第1ラウンド時点の要約

両者が一致した点

  • ムービングライトを機材としてモデル化しない。灯体名・回路・DMX・パン/チルトは持たない。
  • 起点は既存の「光の意図カード」。新しい帳簿を作らず、図と意図を「照明さんが解釈して返せる状態」にする。
  • 出力は「照明打合せ用」として既存の印刷経路（キューシート）を拡張。技術図面・卓のQ番号の代替にはしない。
  • 「守りたい条件」「変えてよいこと」「相談したいこと」の3欄を足す。全欄必須にしない（「お任せ」「まだ分からない」も回答）。
  • 照明さんの返答は残すが、質問／返答・条件／演出側の採否を分け、safetyStatus（安全未評価）とは混ぜない。

対立した点と、私の再判断

  • A/E「追う光」を駒として置くか。 Claude=入口として必要／Codex=「人を見せ続けたい」と「動く光を見せたい」を混ぜるので保留。→ Codexに同意。ただし発端が「ムービング」要望なので、Q2の回答で後者なら再開。
  • F 用語の自動併記。 Claude=素人語→照明語を併記／Codex=「走る→パン」「見える光線→ヘイズ」は実施方法の選定で越権。→ Codexに同意。同義語の説明表示と、照明さんが書いた用語の保持だけ残す。
  • C NGの扱い。 Claude=図上のNG領域／Codex=ジャンル規則に見えるテンプレは危険、「条件＋理由＋確認したい場」を文で。→ 折衷: 文が主、図上の対象指定は補助。
  • Bの規模。 1枚に全部は読めない→ シーン順の複数ページ。「口頭説明の代わり」ではなく「打合せの土台」。
