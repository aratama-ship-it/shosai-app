**Gは「新しい灯体駒」ではなく、意図カードに属する「光の動き（案）」として採用するのがよいです。** 今回の要望なら動く光の表現を再開する理由があります。ただし、**型のラベル＋扇一枚では、動き方より別の意味を伝えてしまう**可能性があります。

推奨は、**短い動作説明＋舞台上の範囲＋合図＋任意の参照動画**。必要な動きだけ、始めと終わりの図を補います。

以下、［資料確認］は一次資料による確認、［一般知識］は技術・慣行の整理、［提案・推測］は今回の判断です。照明プランナーへの実地確認は行っていません。

## 1. G〜Kの批評

### G：「見せる光（動く）」を足す

［提案］**照明の中に入口を置くことには賛成。ただし既存の四種と並ぶ灯体種別にはしない。**

既存駒は「灯体位置＋当たる先」を持ちます。新しい対象は「見せたい光の動き」です。一つの動きを複数の灯体で実現する場合もあり、灯体と同じ単位で数えると意味が崩れます。

UI名は **「光の動き（案）」**。意図カードの図上表現として扱い、照明台数や既存の点灯・消灯表へ自動算入しません。

#### 「型」の語彙

［一般知識］候補語は会話の入口にはなりますが、統一された動作仕様としては読めません。「現場で通じる」と「同じ動きを想像する」は別です。

| 元の語 | 解釈が分かれる点 | 推奨する文言［提案］ |
|---|---|---|
| 振る | 左右・上下・斜め、一方向・往復が不明 | **左右に往復／上下に往復／斜めに往復** |
| 回る | 光の先端が円を描くのか、模様が回転するのか不明 | **光の先が円を描く**。何の周囲かは補足 |
| 交差する | 静止した交差配置か、交差して通り過ぎる動きか不明 | **互いに横切る** |
| 走査する | 意味は推測できるが、演出家向けには説明が必要 | **端から端へ繰り返す** |
| 順に点く | 光線の移動ではなく、点灯順で動きを感じさせる表現 | **順番に点く**として別項目へ |
| ばらばら | 向き、速度、開始時刻のどれが違うか不明 | **それぞれ別の向きに動く**＋補足 |

全部を最初からボタン化する必要はありません。**「往復する／円を描く／互いに横切る／自由に書く」程度を文章入力の補助にする**方が、分類を選ぶための作業を減らせます。

#### 足りない項目

［提案］追加価値が高いのは次の四点です。

- **方向と繰り返し方**：往復か、一方向に進んで戻るか。一度だけか、合図まで続けるか。
- **複数の光の関係**：一緒に動く、順に動く、それぞれ動く。
- **終わり方**：その位置で止まって点灯を続ける、消える、別の動きへ移る。
- **客席から見せたい形**：細い線、太い帯など。厳密なビーム角ではなく、見え方の補足。

逆に、常設項目にするには余計なのは、**角度の数値、運動周期、全動作に共通する大量の型、本数から機材台数を推定する機能**です。

#### 既存tempoの共用には反対

［資料確認］既存仕様のtempoは「変化の体感速度」です。照明卓の資料でも、効果が動く速度と、効果へ入る・抜ける時間は分けられています。[ETC Effects Editor](https://www.etcconnect.com/WebDocs/Controls/EosFamilyOnlineHelp/en/Content/14_Effects/01_Effects_Editor/About_the_Effects_Editor.htm)

［提案］次は別々に保持します。

> 光は速く往復する。登場するときはゆっくり明るくなる。

「ゆっくり／速い」という表示語を再利用するのはよいですが、同じ値にはしません。「呼吸」は既存項目には残し、新しい動作速度の代表語には使わない方が明確です。

### H：静止した扇で表す

［提案］**往復の範囲を伝える補助図には使えるが、共通表現としては不足。**

扇だけでは、次を区別できません。

- 一本が動く範囲
- 複数の光が同時に開いた状態
- 面として明るくしたい範囲
- 灯体を中心とする実際の照射可能範囲

特に「淡い光線を複数描く」は、本数の誤読を起こしやすいです。具体策は次節に示します。

### I：参照動画を必須級にする

［提案］**強く勧めるが、保存・出力の必須条件にはしない。**

参照動画の方が説明しやすいという仮説は妥当です。ただし、動画を探す時間が入力の負担になり、既存作品に似た表現しか相談できなくなる可能性もあります。

入力は「時刻」一つより、**参照する区間＋着目点**が有効です。

> 00:18〜00:24。光が交差する順番を参照。色と本数は合わせなくてよい。

動画で見える光の太さ・明るさが、そのまま客席での見え方を保証するものではありません。**参照する要素を明記することが、動画の有無より大切**です。

### J：打合せシートの専用欄

［提案］採用。ただし、列を増やしたチェック表にはしません。

主役は **「何がどこをどう動き、いつ終わるか」**の一文と図です。型・本数・速度はその補足にします。

「本数」は **「同時に見せたい光の本数」**へ改称します。「たくさん」は構想段階なら有効ですが、数量指定として出してはいけません。「本数は相談」も用意します。

実現方法を照明さんの言葉で返答欄に残す方針は整合しています。本人の記録なので、表示は「照明担当者からの返答を記録」とします。

### K：ヘイズの相談質問を提案する

［資料確認］ヘイズは光線を見せるために使われます。メーカー資料には、その用途と、空気の流れの影響について説明があります。[Rosco Fog FAQ](https://emea.rosco.com/en/rosco-fog-faqs)

［提案］質問候補を出すことには賛成ですが、元の文は修正します。

> **この会場で、空中の光線を見せるにはどんな方法が使えますか。ヘイズ等を使う場合の条件も相談したいです。**

「要ると聞くが」という本人が発言していない前提を入れず、ヘイズだけに解決手段を限定しません。提案する条件も「動く光を置いたら」ではなく、**「空中の光線を見せたい」と指定したとき**です。

## 2. 図の表現：既存駒を流用するか

### 見た目は分け、操作はそろえる

［提案］既存の灯体位置＋プールは、そのまま流用しません。**光の動きには灯体の丸印を付けず、意図カードに対応する範囲・矢印・注記を置く。** 選択、移動、Undoなどの操作感は既存駒にそろえます。

扇の頂点も灯体位置に読まれるため、光が出てくる場所自体が演出の希望でない限り、固定の頂点を要求しません。

| 図の要素 | 表すもの |
|---|---|
| 実線の光線 | ある一瞬の見え方の例 |
| 破線の輪郭 | 動いてほしいおおよその範囲 |
| 矢印 | 動く方向 |
| 「光の動き・案」ラベル | 演出の希望であること |
| 「同じ1本：始め／折り返し」などの小図 | 異なる時点を区別する |

**同時に見える本数と、説明のために重ねた線の本数を混ぜない**ことが最優先です。破線だけで意味を伝えず、短い凡例を付けます。薄すぎる描画はiPadでも印刷でも読めないため避けます。

### 平面図＋正面図で足りる条件

［提案・推測］単純な往復と範囲なら足ります。しかし、円運動、前後をまたぐ交差、演者を取り囲む動きは、二枚の投影図だけでは解釈が分かれます。

その場合は、無理に扇へ押し込まず、**始め・途中・終わりの小図、または参照動画**へ渡します。客席上方の高さなど、正面図で伝わらない前後方向の条件は文章で補います。

### 3D・アニメーションを作らない判断への反論

**前回の私の指摘を、アニメーション禁止の根拠にするのは強すぎます。**

［推測］静止図でも完成済みの計画には見えます。一方、概略であることを示したアニメーションなら、一本が往復するのか複数本が交差するのかを静止図より明確にできます。

今回は実装範囲と参照動画で補えることを理由に見送るのが妥当です。将来、時間関係の誤読が繰り返し起きたなら、簡単な動作再生には再検討の価値があります。物理的な光の再現を作る必要はありません。

## 3. 照明側が動く光の相談で確認しそうなこと

［一般知識］「必ず聞く」共通リストがあるとは断定できません。以下は実現案を組む際に確認対象になりやすい情報です。

| 論点 | アプリが提案してよい質問［提案］ | 演出家に算出・判定させないもの |
|---|---|---|
| 光線の見え方・ヘイズ | 「この会場で空中の光線を見せる方法を相談したい」 | 必要な煙の量、液剤選定、許可の要否・可否 |
| 本数 | 「この見え方には、どの程度の構成が必要か相談したい」 | 必要灯体数の確定 |
| 客席との関係 | 「客席上方に光を見せたい。使える範囲を相談したい」 | 客席へ向けてよい角度・光量の判定 |
| 演者の視界 | 「この区間で、演者が道具を見る条件を確認したい」 | 一般化した安全角度や安全判定 |
| 天井高・吊物・空間 | 「この高さと範囲の動きが可能か相談したい」 | 未計測の寸法、干渉・設置可否の推定 |
| 仕込み・プログラム時間 | 「予定している作業時間内で、どこまで実現できるか相談したい」 | 必要な作業時間や要員数の算定 |
| 電源・機材・制御 | 「会場の設備で可能か、追加手配が必要か相談したい」 | 電力計算、回路、DMX、卓への割当 |
| 音楽・動作との関係 | 「どの瞬間を合わせたいか」を本人が記入 | 同期方式や制御方法の選定 |

［資料確認］例えば岡山芸術創造劇場の利用案内では、スモーク使用に関係する申請書類と技術担当との打合せが示されています。これは**会場ごとの確認事項がある根拠**であり、他会場へ同じ条件を適用する根拠ではありません。[劇場利用案内](https://okayama-pat.jp/web/wp-content/uploads/2026/01/【岡山芸術創造劇場】ご利用のしおり.pdf)

［提案］この一覧を全部自動追加してはいけません。入力に対応する候補だけを示します。既知の予算・利用時間・会場図面は参照できるようにし、本人が分からない技術条件は空欄のまま照明さんへ渡します。

## 4. P0との統合

**利用者に渡すP0には、今回の「動く光」の相談を含めます。図上編集の追加をP0.5に分けます。**

確定した発端を通常の照明相談だけで後回しにすると、今回の課題を解いたか評価できないためです。

| 順序 | 範囲 | 理由 |
|---|---|---|
| **P0-1** | 意図カード、相談3欄、複数の「変わる合図」を整理 | 情報の正本を一つにする |
| **P0-2** | 「光の動き（案）」の短文・範囲・参照区間を追加。既存図に注記して出力 | 実際のサーチライト要望を渡せる最小形 |
| **P0-3** | 質問・返答・採否の記録 | 本人が打合せ結果を戻せるようにする |
| **P0.5** | 図上で範囲・矢印・必要な小図を編集 | 文章と参照だけでは足りなかった空間関係を補う |

### 「複数の合図」は、合図名のリストだけでは足りない

［提案］一枚の意図カードを維持しつつ、各行を **「合図＋何が変わるか」**の組にします。

> 音楽の入り → 往復を始める  
> Aが中央で止まる → 光も止める。点灯は続ける  
> 次の音 → 光を消す

開始・停止・消灯を別々の欄と別々の合図一覧に二重保存しません。既存tempoは各変化の速さ、新しい「動く速さ」は継続中の運動に使います。

また、本人の返答記録から意図や配置を自動更新せず、採用した内容を本人が反映できるようにします。

## 5. iPad側パネルと出力の具体案

### 側パネル：項目順とUI文言

［提案］「光の動き」を追加すると既存カード内の該当部分が開きます。最初から全項目を縦に並べず、主入力と三つの折りたたみにします。

```text
光の動き（案）

どう動かしたい？
［細い光が左右に往復する                ］
例から入力
［往復］［円を描く］［互いに横切る］

どこに見せたい？
［図で範囲を示す］
［舞台奥の空中                          ］

変わる合図
音楽の入り → 往復を始める
［合図と変化を追加］

▸ 動き・見え方
▸ 参照
▸ 照明の相談

［前のシーン］             ［次のシーン］
```

**「動き・見え方」を開いたとき**

| UI文言 | 入力 |
|---|---|
| 繰り返し | 「1回／繰り返す／未定」 |
| 動く速さ | 「ゆっくり／速い／未定」＋補足 |
| 同時に見せる本数 | 「1本／2本／複数／相談」＋任意の具体数 |
| 複数の光の動き | 「一緒に／順に／それぞれ／未定」。複数本の場合だけ表示 |
| 見せたいもの | 「空中の光線／床・壁の明かり／両方／相談」 |
| 光の太さ・色 | 短文。必要なら既存の色入力を利用 |

「見せたいもの」は、この入口では空中の光線を主な用途としつつ、床・壁の動きと混同していた場合に修正できる項目です。全項目を必須にはしません。

**「参照」を開いたとき**

```text
動画・画像の参照先
参照する区間
どの部分を参考にする？
```

**「照明の相談」を開いたとき**

```text
守りたい条件
変えてよいこと
相談したいこと

質問候補
空中の光線を見せる方法を相談しますか？
［質問に追加］［閉じる］
```

既に入力した質問を自動提案で上書きしません。「光の動き」側に別の相談3欄を増やさず、同じカードの該当欄へつなげます。

パネルの幅は既存値を基準とし、選択肢は折り返して表示します。**一項目ずつ編集しながら図が見えること**を優先し、キーボード表示中もシーン移動と入力中の項目が埋もれないようにします。実寸・操作性は未検証です。

## 6. 逆張り：参照動画1本＋一文で十分な条件

［提案・推測］次の条件なら、Gの図上オブジェクトは不要です。

- 主に伝えたいのがリズムや動作の質で、自分の舞台上の正確な範囲は任せられる。
- 参照動画のどの区間・どの光を見るかを一意に示せる。
- 演者・セット・客席との位置関係に、個別の指定がない。
- 一文で開始・終了と変更可能な部分を伝えられる。
- 照明プランナーが別の構成を提案しても、演出意図が保たれる。

例えば、

> 動画00:18〜00:24のように、空中の光線が左右に往復する動きを見せたい。音楽の入りからAの登場まで。位置・色・本数は相談したい。

これで打合せが進むなら、図を描かせる方が余計です。

**Gが必要になるのは、「この舞台の、この範囲で、この対象とどう関係するか」を参照動画だけでは説明できないとき。** 動く光を希望した全員に駒を置かせる必要はありません。

## 7. 本人に確認すべき未決事項

1. **今回見せたいのは、一本の光が探るように動く絵ですか。それとも、複数の光が交差・連動する絵ですか。** 複数の光の関係を最初から扱う必要が変わります。
2. **光を見せたい場所は、舞台上の空間、床・奥壁、客席上方のどこですか。** 主に使う図と、範囲を示す方法が変わります。
3. **動きは開始から終了まで同じ繰り返しでよいですか。それとも音楽や演者の動作に合わせ、途中の折り返し・交差まで合わせたいですか。** 後者なら「型＋体感速度」だけでは不足します。

検討は完了し、ファイルは変更していません。次の一手は、この三点を反映した**実際の一場面の打合せ用サンプル**を文章と図の構成で固めることです。おすすめモデルはSolです。
