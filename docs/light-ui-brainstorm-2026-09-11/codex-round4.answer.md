第3ラウンドの判断を、天平さんの証言と今回の追加条件に合わせて更新します。

**初回の中心は、プリセットを選んで複数の光を動かし、再生し、動画・図・一文を出すことです。** 自由なぞり、正確な音声同期、複雑なストロボ、安全判定は後段に回します。

## 1. プリセット語彙

［一般知識］照明卓のエフェクトには、波形、周期、振幅、位相差、方向、反復回数などの概念があります。ETCの資料でも、`sine`、`step`、`ramp`、`random`、`circle`、`fly in`、`rate`、`size`、`offset`、`bounce`、`sync` などが別の役割で扱われています。[ETCのエフェクト資料](https://www.etcconnect.com/webdocs/Controls/HOG/HTML/en/sect-table_effects.htm)

ただし、これらは卓での設定語です。演者向けプリセット名としてそのまま使うと、何が動くのか分かりにくくなります。「fan」や「wave」もメーカーや現場で意味の幅があるため、表示名だけで実現方法を確定させない方がよいです。

| 演者向けの表示 | 照明語の候補 | 扱い |
|---|---|---|
| 左右に往復 | sweep / bounce | `bounce` は本来、効果の方向を反転する属性。補助語として使う |
| 扇に開く・閉じる | fan / fanning | 複数灯の間隔や位相を広げる意味が強い |
| 2本が交差する | cross / crossing | 通じやすいが、静止配置か動作かを説明文で補う |
| 円を描く | circle / circular motion | 比較的通じやすい。卓ではpan・tiltの組合せ |
| 端から端へ移る | ramp / fly in・fly out | `fly` は卓や現場によって意味が変わるため、日本語を主にする |
| 順に動く | chase / sequential | `chase` は順番に変化する意味で使いやすい |
| 波のようにずれる | wave / phase offset | `wave` は定義が揃わない。説明文を必須にする |
| 一緒に動く | sync / in phase | 技術語では同期、演者向けには「同時に動く」 |
| ばらばらに動く | random / staggered | randomは意図した不規則さか、単なる時間差かを分ける |
| 点滅する | strobe / mark on・off | 動線ではなく明るさの属性。別扱いが適切 |

［推測・提案］初回試作に入れるのは次の6個です。

1. 左右に往復
2. 扇に開く・閉じる
3. 2本が交差する
4. 円を描く
5. 順に動く
6. 点滅する

「一緒に動く」は複数本プリセットの設定、「速さ」「範囲」「位相差」は調整項目にし、独立したプリセットにはしません。

### 「サーチライト」の扱い

「サーチライト」はプリセット名に入れてよいですが、機材名にはしません。

> サーチライトのように左右に探す（左右に往復）

こうすれば、照明さんには意図が伝わり、特定の灯体を要求しません。

## 2. BPM同期の落とし穴

BPM同期は、厳密な音楽同期よりも、今回の「振幅をBPMに合わせる」目的に絞るべきです。

### 「1往復」の意味

「1往復」は曖昧です。UIでは次のように固定します。

> **1周期：左端 → 右端 → 左端**

片道を指定したい場合は「片道」と書きます。

初期値は、

> 合図で左端から開始し、1周期で元の位置へ戻る

に固定します。

### 位相

最初から「拍頭で折り返すか、通過するか」を自由に選ばせると難しくなります。

初回の既定値は、

- 合図で端から開始
- 半周期で反対端
- 1周期で元の端
- 以後繰り返す

です。

「中央から開始」「拍頭で折り返す」は、2回目以降の詳細設定に回します。

### 複数本の時間差

初回は自由なミリ秒指定を作らず、プリセットで固定します。

- 2本対称：半周期ずらす
- 順に動く：一定の順番でずらす
- 一緒に動く：位相差なし

HOG系の資料でも、複数灯の効果は`offset`や`sync`でずらし・同期を扱いますが、これは卓側の概念です。[ETCのエフェクト属性](https://www.etcconnect.com/webdocs/Controls/HOG/HTML/en/sect-table_effects.htm)

UIでは、

> 光の関係：一緒に／向かい合わせ／順に

程度に留めます。

### 曲のテンポ変化

曲の途中でBPMが変わる場合、固定BPMでは動きがずれます。初回は、

- BPMを数値入力、またはタップで決める
- 途中のテンポ変化は扱わない
- 「曲全体で一定のBPMとして再生」と表示する

で十分です。

最小の表示は次です。

```text
拍に合わせる　オフ／オン
1周期　　　　 1拍／2拍／4拍／8拍
開始位置　　　端から
```

「速さ」と「拍に合わせる」は分けます。BPMを使わない場合は、従来どおり「ゆっくり／普通／速い」を使います。

## 3. ストロボの扱い

**データ上は属性、UI上はプリセットを用意する**のがよいです。

- データ：各光に `flash` 属性を持つ
- UI：すぐ使える「点滅する」プリセットを置く
- 出力：点滅の指定を独立した項目として表示

こうすれば、通常の動きに点滅を追加でき、ストロボ専用の動作体系も増えません。

### 演出上の入力項目

初回に残すのは以下です。

- 点滅の速さ：遅い／普通／速い、または1拍・2拍・8分・16分
- 範囲：全体／一部／選んだ光だけ
- 長さ：1拍／2拍／合図まで
- きっかけ：場面頭／音楽／動作／手動
- 点滅後：止まる／通常点灯に戻る／消える

照度、周波数の細かな数値、機材ごとの発光方式は入力させません。

### 光過敏発作への表示

［一般知識］点滅の影響は、頻度、明るさ、背景とのコントラスト、距離など複数条件で変わり、個人差があります。アプリが安全可否を判定する領域ではありません。[Epilepsy Foundation](https://go.epilepsy.com/what-is-epilepsy/seizure-triggers/photosensitivity)

［提案］点滅を指定したときだけ、次の短い質問を出します。

> 点滅を含む案です。光過敏発作などへの影響は、条件や人によって異なります。会場・照明担当者と、実施条件・事前告知・代替表現を相談しますか。  
> Stage Sketchは安全性を判定しません。  
> ［質問に追加］［今回は追加しない］

プレビューは自動再生せず、再生ボタンを明示します。これは安全判定ではなく、突然の点滅を避ける操作上の配慮です。

## 4. 舞台登録なし入口

### 推奨データモデル

別製品用のデータ形式は作らず、Stage Sketchの最小プロジェクトとして保存します。

```json
{
  "kind": "shosai-stage-sketch",
  "version": 4,
  "project": {
    "title": "光の動き案",
    "scenes": [
      {
        "id": "scene_motion_01",
        "title": "動く光の試作",
        "lightingIntent": {
          "objective": "",
          "lightMotion": {
            "version": 1,
            "coordinateSpace": "front",
            "beams": [],
            "timing": {},
            "references": []
          }
        }
      }
    ]
  }
}
```

`lightMotion`は意図カードの子要素です。舞台登録がない場合は、会場や演者配置が未指定のまま保存します。仮の空ステージは描画上の背景であり、会場設備の候補ではありません。

### 既存ショーへ取り込むとき

既存シーンへ自動上書きしません。

- 「新しいシーンとして追加」
- 「選択したシーンの光の案へコピー」
- 「既存の光の案を残して別案として追加」

のいずれかを本人が選びます。

同じシーンに既存の`lightMotion`がある場合は、置換ではなく「別案」として保存します。シーン番号や配列位置をIDの正本にはしません。

### 単独利用との境界

単独入口は「Stage Sketchの最小シーンをすぐ開く入口」です。次は別製品化しません。

- 独自アカウント
- 独自共有基盤
- 独自の機材データベース
- 独自の会場データ形式
- 単独アプリ専用の保存形式

これで「舞台を登録しなくても作れる」と「舞台スケッチ本体の一機能」を両立できます。

### サムネイルのループ再生

［推測］6〜10個のサムネイルを同時にループ再生すると、iPadでは処理負荷、電池、視線の散乱が増えます。初回は次の方式を推します。

- 一覧は静止サムネイル
- 選択中だけループ再生
- 各サムネイルには再生アイコンを表示
- 再生中のものをタップすると停止
- 動きを減らす設定では静止表示

「一覧で全部動く」は、選択の速さより見づらさが勝つ可能性があります。

## 6. MVPの最終リスト

### 2週間の必須範囲

#### 順0：書き出し成立の確認

最初に、短い動きを再生し、iPad上で保存し、別端末で開けることを確認します。

- 動画
- 一枚図
- 一文
- 「案・灯体位置ではない」の表示

動画形式は、iPadとスマホ、LINE相当の受け渡しで実際に確認して決めます。ブラウザが形式を受け付けても、録画・保存・再生まで成功するとは限りません。

#### 順1：舞台登録なしの最小入口

- 空ステージを1タップで開く
- 正面図を表示
- 光を1本置く
- 最小の意図カードを持つ
- 既存ショーのシーンからも同じ編集画面を開ける

#### 順2：プリセット主入口

初回は次の5種です。

- 左右に往復
- 扇に開く・閉じる
- 2本が交差する
- 円を描く
- 順に動く

各プリセットの調整は、

- 本数
- 範囲
- 速さ

に限定します。太さ・色は初期値を持たせ、必要性が確認できてから開きます。

#### 順3：再生と出力

- 再生・停止・最初から
- 2本までの同時再生
- 対称・順番の関係をプリセットで固定
- 動画・図・一文の一括出力
- 相談3欄、参照区間、質問・返答・採否への接続

ここで天平さんが「動画を切り抜くより早い」と感じるかを測ります。

#### 順4：BPMの薄い実装

2週間に入れるのは、必要な場面なら次だけです。

- 固定BPMの入力
- タップでBPMを決める
- 1周期＝1・2・4・8拍
- 開始位置は端から固定

音源の読み込み、途中のテンポ変化、曲の自動解析、音声付き動画は2回目に回します。

#### 順5：ストロボの薄い実装

2週間に入れるのは、

- 「点滅する」プリセット
- 速さ
- 範囲
- 長さ
- きっかけ
- 相談文の提案

までです。複雑なランダム点滅、複数ストロボの位相制御、明るさの安全分析は2回目に回します。

### 2回目に回すもの

- 自由なぞりによる任意曲線
- 3D上の光の編集
- 個別光線ごとの任意位相・遅延
- 音源からのテンポマップ
- 音声付き動画
- GIFや複数形式の同時出力
- 光線の太さ・色の細かな調整
- 複雑なストロボパターン
- 照明さん側の直接入力
- 会場条件との照合
- 機材候補やDMXへの変換

## 7. 実装計画へ渡す仕様項目

### データ構造

- `lightingIntent.lightMotion.version`
- `coordinateSpace`: `front`を初期値。`plan`は後から追加
- `beams[]`
  - `id`
  - `width`
  - `color`
  - `visible`
  - `path`
  - `presetId`
  - `relation`
- `path`
  - `kind`: `line`、`circle`、`polyline`
  - 始点・終点・必要な通過点
  - `loop`: `once`、`ping-pong`、`untilCue`
- `timing`
  - `mode`: `free`、`fixed-bpm`、`tap`
  - `bpm`
  - `cycleBeats`
  - `startPhase`
  - `repeat`
- `flash`
  - `enabled`
  - `beatDivision`
  - `scope`
  - `durationBeats`
- `cues[]`
  - `triggerType`
  - `triggerRef`
  - `action`: `start`、`stop`、`hold`、`flash`
- `references[]`
  - URLまたはローカル参照
  - 区間
  - 着目点
- `notes`
  - 守りたい条件
  - 変えてよいこと
  - 相談したいこと
- `origin`
  - `standalone`または`scene`
  - 元シーンID
  - 作成時のリビジョン

正本は意図カード内のデータです。動画、PNG、GIFは派生物にします。

### 再生の時間表現

- 動きの正本は、秒ではなく正規化された位相または拍単位
- `cycleBeats`は「1周期」を意味する
- 片道・往復を別の状態として保存
- BPMから秒へ変換する値は再生時に導出
- `durationMs`を正本にしない
- 音楽の途中テンポ変化は、テンポマップ対応まで未対応と明示
- 再生中の位置をUndo・シーン保存の正本にしない

現在の音楽処理にも、同じ音源なら再生位置を保ち、再生位置は保存・Undoしない設計があります。[stage-sketch.js](</Users/arata/Library/Mobile Documents/com~apple~CloudDocs/claude code files/show-creative-ideas/shosai-app/stage-sketch.js:4772>)。既存の音源再生と、光の編集用時間軸を同一視しないことが重要です。

### 書き出し要件

- 動画、図、一文を同じリビジョンから生成
- 動画は短いループまたは指定回数。演出自体が反復するかとは別に記録
- 動画・図の両方に「光の動きの案」を表示
- 「灯体位置・DMX・安全性は示さない」を表示
- シーン名、版、出力日を含める
- 音声なしを初期値
- iPad保存、スマホ再生、LINE相当の受け渡しを実機確認
- 動画形式は、iPad・受け手端末で確認したものだけを採用
- 失敗時は「動画だけ保存済み」など、成果物ごとの状態を表示
- 一文、図、動画で異なるリビジョンを混ぜない

### 既存コードとの接続点

- `newScene()`：空の`lightMotion`を必要に応じて初期化
- `normalizeScene()`：未知項目を落とさず、既存version 3／4との往復を保つ
- 保存・読込・Undo／Redo：意図カードと同じ経路へ接続
- 正面図レンダラー：初回の光線表示と再生
- 既存の動線再生：描画曲線の補間処理を再利用できるか確認
- 音楽パネル・音源ストア：BPM参照の入口だけ接続し、再生位置を正本化しない
- 打合せ出力：動画・図・一文・相談欄・返答記録を同じ案IDへ接続
- `stage-i18n.js`：演者向け語を主表示にし、照明語は補助表示
- エクスポート処理：動画、図、文章を同一スナップショットから生成
- Service Workerと版番号：製品へ組み込む場合のみ更新
- テスト：
  - 新旧データ往復
  - 複数光線の順序と位相
  - 1周期の端点定義
  - BPM導出の再現性
  - ストロボ設定の保存
  - 動画・図・一文の同一リビジョン
  - スタンドアロンから既存シーンへの明示的取り込み
  - 既存シーンの意図・照明駒・音楽を勝手に上書きしないこと

今回の最終推奨は、**「照明を作る」ではなく、「舞台上で見せたい光の動きの案を作って再生する」モジュール**です。これなら天平さんの実体験に応えながら、機材シミュレータや卓操作ソフトへ戻らずに済みます。
