## 完了したこと

### データモデル
- `scene.lightingIntent.lightMotion` を新設。正規化・定数・幾何/時間計算・描画・書き出しは
  新規独立モジュール `stage-light-motion.js`（`window.SHOSAI_STAGE_LIGHT_MOTION`）に分離
  （`stage-machinery.js` と同じ設計パターン）。機材（灯体名・回路・DMX・パン/チルト・照度）は一切持たない。
- `emptyLightingIntent()` / `normalizeLightingIntent()`（stage-sketch.js）を拡張し、
  `lightMotion` 単独でも中身ありと判定して保存する。既存の意図カードの原則（中身のない案は保存しない・
  安全認定を与えない）は変更していない。

### プリセット（順2・仕様どおり5種）
左右に往復／扇に開く・閉じる／2本が交差する／円を描く／順に動く。調整は本数・範囲・速さの3つだけ
（fan/cross/chaseは本数を2に固定）。複数本のときだけ「光の関係（一緒に／向かい合わせ／順に）」を出す。
1周期＝端→端→端（circleのみ連続回転）。

### UI配置（仕様からの意図的な変更点）
spec.html のワイヤーフレームは左268pxの**照明パネル**（灯体登録欄）への配置を想定していたが、
実装前にDOM構造を確認した結果、既存の「光の意図カード」は**中央作業域の図の上**（details要素、
シーンに紐づく）にあり、照明パネルは灯体の登録・管理という別の関心事だった。
Codex第2ラウンドの回答も「意図カードに対応する範囲・矢印・注記を置く」としていたため、
**既存の光の意図カードの直後に、同じ視覚語彙（details/summary・真鍮キッカー・左の細罫線）で
並べる**方針に変更した（照明パネルには置いていない）。既存デザインシステムを優先する方針
（dev-preferences）に沿う判断。

### 舞台登録なし入口（項目8）
新規ルーティングは作らず、**既存の「新しいショー」ボタン**（`baseState(false)` で
演者・セット・音楽なしの最小プロジェクトを作る）で要件を満たすことを確認した
（ブラウザで実機確認済み・下記）。新しい入口を重複して作らない判断。

### 再生・書き出し
- ライブプレビューは `requestAnimationFrame`（既存の動線再生と同じ方式）。
- 書き出しは順0で検証済みの方式（`captureStream(0)` + 固定ステップ + `track.requestFrame()`、
  isTypeSupported順に試す）。動画・1枚図（始め・折り返し・戻りの3コマ）・一文＋相談3欄を
  同じ再生データから生成し、3ファイルをダウンロードする。

### 機能フラグ
`FEATURES` 配列に `lightMotion`（`def: false`）を追加。既存の設定パネルが自動でトグル行を生成する
（このアプリの新機能ロールアウトの標準パターン）。**既定OFF**。

### i18n
新規の日本語文言すべてに英語訳を追加（`stage-i18n.js` TEXT辞書・SAY配列）。中国語繁体/簡体は
英語へフォールバックする既存の仕組みでカバーされる（テストで確認済み）。

### ガード（worker.js）
`GUEST_STAGE_ASSETS` に `/stage-light-motion.js` を追加。ゲストアカウント（公開先の限定共有）が
新しいスクリプトを403で弾かれないようにした。**この修正がなければ公開後にゲストの画面が壊れていた**
（`tests/worker-guest-scope.test.mjs` が検出）。

## 発見して直したバグ（実装中の手動検証で発覚）

**要約文の本数二重表記**: 「2本が交差する」というボタン表示名をそのまま要約文の動詞句に使ったため、
「光2本が2本が交差する。」と重複していた。ボタン表示名（stage-i18n.js）と要約文の動詞句
（stage-sketch.js内の別辞書）を分離し、要約文専用は「交差する」（英語は動名詞で数の一致を回避）に修正。
5プリセット全部をブラウザで実行して確認済み。

## 追記 2026-09-11: 光の意図カードを非表示にし、光の動きをモーダル化

本人指示（音声入力、「光の糸」＝「光の意図」の誤変換と本人確認済み）により、実装直後に以下を変更した。

### 1. 光の意図カードを非表示に
- `featureOn("lightIntent")` を常に `false` を返すよう上書き（他の値に関わらず）。既存の端末保存値（本セッションの検証で `true` にしていたもの含む）も無視される。
- `FEATURES` 設定配列から `lightIntent` のトグル行を削除（設定パネルに出さない）。
- カード本体・「配置案を試す」比較欄・図への作図の重ね（`lightIntentOverlayOn()`）は同じ1箇所の変更から連鎖して非表示になる（多重管理にしない）。
- **データ・正規化関数（`emptyLightingIntent`/`normalizeLightingIntent`）は削除していない**。既存の保存データを破壊しない「非表示」であり「削除」ではない。

### 2. 光の動き（案）を独立させ、モーダル化
- データを `scene.lightingIntent.lightMotion` から **`scene.lightMotion`**（`beat`/`rehearsal`と同じ、シーン直下の独立項目）へ移動。`normalizeScene()`/`newScene()` を更新。
- UIを、光の意図カード直後の `<details>` インラインカードから、**既存の「プリセットから組む」（照明の駒プリセット）と同じモーダルパターン**へ変更。
  - トリガー: 照明パネルの「プリセットから組む」の直下に「**光の動きを組む**」ボタンを追加（現在の案を2行目に小さく表示）。
  - モーダル: `.stage-modal`（既存の共通スタイル）＋ヘッダー（タイトル・✕）＋本体（プリセット・調整・再生・書き出し・消す）。Escape・背景クリック・✕クリックで閉じる（`stage-light-preset-modal`と同じ挙動）。
- 内部の状態遷移・書き出しロジック（`stage-light-motion.js`）は無変更。sync/mutateの土台だけを「光の意図カードの子」から「シーン直下＋モーダル」に付け替えた。
