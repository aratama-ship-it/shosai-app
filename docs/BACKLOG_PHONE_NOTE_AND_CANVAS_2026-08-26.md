## ★着手前に確認すること（本人の前提と、実装の事実が食い違っている）

**指示2の「PC版に反映されない」は、現状の作りとは違う。**

図の上の付箋は `sc().notes` に入る（`stage-sketch.js:18399` の `sc().notes.push(note)`）。
これは**シーンのデータそのもの**なので、

- 書き出したJSONに含まれ、**PCで開けばそのまま出る**
- 共有セッション中なら**ホストへも渡る**
- `sc().note`（情報パネルの「このシーンのメモ」）も同じくシーンのデータ

つまり「スマホのメモはスマホの中だけのもの」ではない。

**確認したいのは、新しいメモ欄に書いた内容をどこへ入れるか。** 候補:

| 案 | 中身 | 向き不向き |
|---|---|---|
| A. 既存の `sc().note`（シーンのメモ）を、図の下へ常時出す | いま情報パネルにあるものと同じ。**PCにも反映される** | 一番自然。「情報」を開かずに書ける。ただし情報パネルとの重複をどうするか決める |

という趣旨に読める。Aなら位置を持たないシーン単位のメモなので、PCでも素直に読める。

## ★図の縦幅1.2倍 — 「余白を詰める」を本人が選択したが、着手前に止めた

**あの余白は空いていない。使われている。**

`drawPlanVenue()`（`stage-sketch.js:9149` 付近）は、舞台の枠の**外側**へ
「袖」「舞台裏」の帯を描く。幅は `planBounds()` の `uMin` / `vMin` から決まる
＝**舞台の外に置かれた駒の位置**で決まる。

```
if (b.uMin < 0) { const w = -b.uMin * s.w;  … s.x - w  と  s.x + s.w  に袖を描く }
if (b.vMin < 0) { const d = -b.vMin * s.h;  … s.y - d  に舞台裏を描く }
```

→ **`pad = 104` を単純に詰めると、袖と、そこに置かれた演者・道具が画面外へ切れる。**

### 安全にやるなら: 余白を「必要な分だけ」にする

固定の104ではなく、**`planBounds()` から実際に要る余白を計算し、足りる範囲で最小にする**。

- 袖に何も置いていないショー（`uMin >= 0` かつ `vMin >= 0`）は袖が描かれないので、
  余白をほぼゼロまで詰められる＝**図が目に見えて大きくなる**
- 袖に駒があるショーは、その分だけ余白を残す＝**切れない**

**スマホだけに適用するか、PCも含めるかは要判断。** スマホだけなら安全だが、
同じショーがPCと違う大きさで見える。

### なお、詰めても1.2倍には届かない場合がある

`layout()` は先に `sw = availW`（横いっぱい）を取り、収まらなければ高さで詰め直す。
**横で決まっているショーは、余白を詰めても横は最大1.1倍程度しか伸びない**
（1280に対して現状1072なので）。縦で決まっているショーは1.2倍以上いける。
**「1.2倍」は一律には保証できない。**

### 正面図は別問題

正面図は擬似パースで、床の厚み・幅の開き・消失点を席の位置から組み立てている。
平面図と同じ「余白」という概念が無いので、**別途調べる必要がある。**
