## 背景

共有セッションのホストがPC再起動・アプリ/ページの再読み込みをすると、部屋番号と
ホスト鍵がJSメモリからしか無いため消え、同じ部屋へ戻れない。新しいセッションを
開始して招待URLを配り直すしかない。一方、**ゲストの接続は生きたまま残る**ので、
ホストが同じ部屋へ戻れさえすれば、ゲスト側は何もせず自動で再開される
（サーバーの部屋と`hostKey`は、誰かが接続している限り保持される。
全員退出の10分後に消える）。

併せて、ホスト切断中のゲスト画面は静止画のまま残るが、参加者リストの変化でしか
分からない。目立つ「ホスト不在」表示を足す。

**前提（2026-08-26 Claudeが確認済みの事実。再調査不要）**:
- `session-room.js` の presence には各参加者の `role` が入る（`participantFrom()`）
- ホスト再接続時は既存の open ハンドラが `sendHostDocument(true)` で全文書を配り直す
- 間違った鍵での接続はサーバーが `{t:"bad-key"}` で拒否する。部屋が消えた後の
  再接続も storage に鍵が無いため同じく bad-key になる
- Macアプリのページ（shosai://app）の localStorage はアプリ再起動後も残る。
  `SessionRelay.connect` は部屋番号・鍵を引数で受けるだけなので、
  **Swift側の変更は不要**
- `stage-session.js` には localStorage 利用の先例がある（`NAME_KEY`、81行付近）

## F-1. ホスト情報の保存と「前回のセッションを再開」

対象: `stage-session.js`（と `index.html` のセッションパネル・`stage-i18n.js`・`style.css`）

1. **保存**: `startHostSession()` が roomId / hostKey を得たら、localStorage
   （キー例 `shosai-session-host-room`）へ `{roomId, hostKey, savedAt}` をJSONで保存する。
   `NAME_KEY` と同じ try/catch 作法（保存失敗でもセッションは続ける）。
2. **再開ボタン**: ページ読み込み時、保存があり `savedAt` が **24時間以内**なら、
   セッションパネルの「セッションを開始」の近くに「前回のセッションを再開」を出す。
   押したら `/session/new` を**呼ばずに** role=host・保存済み roomId/hostKey で
   `connectSocket()` する（表示名は既存の欄の値を使う）。招待URLも保存済み roomId から
   組み立てて表示する（Macアプリ時の origin は発注書D同様
   `sessionStart` を経ないため、**本番オリジンを直書きせず**、
   ブラウザ時は `location.origin`、ブリッジ時は保存時に origin も一緒に保存して使う。
   つまり保存内容は `{roomId, hostKey, origin, savedAt}` とする）。
3. **後始末**:
   - 新しいセッションを開始したら保存を上書きする
   - 再開の接続が `bad-key` / `full` で拒否されたら保存を消し、
     「前回のセッションは終了しています。新しく開始してください。」を出し、
     再開ボタンを隠す
   - 24時間を過ぎた保存は無いものとして扱う（読み込み時に消してよい）
4. ホスト鍵はローカル保存だが、**ログや画面に鍵そのものを出さない**こと。

## F-2. ゲストへの「ホスト不在」表示

対象: `stage-session.js`・`index.html`・`style.css`・`stage-i18n.js`

1. ゲスト参加中、presence の参加者に `role === "host"` が**いない**とき、
   目立つ帯を出す: 「ホストの接続が切れています。復帰を待っています…」。
   ホストが戻って presence に host が現れたら消す。welcome 受信時も同じ判定を通す。
2. 置き場所は画面上部中央。E-3のゲストバッジ（`stage-session-guest-badge`）の
   意匠・実装に倣い、`pointer-events: none`・`aria-live="polite"`。
   バッジと重ならないこと。
3. ホスト自身の画面には出さない（role=guest のときだけ）。

## F-4. ゲスト画面から不要な機能を隠す（本人指示 2026-08-26）

対象: `style.css` 中心（必要なら `stage-session.js` / `stage-sketch.js` の小さな補助）

ゲスト参加中（E-3で導入済みの `body.stage-session-guest`）は、**見る・指す・
矢印を描く以外の機能を画面から隠す**。E-3は道具ボタンを絞ったが、左列の
編集・管理系パネルはまだ見えている。

**隠すもの**（パネル・ボタン単位。CSSの `body.stage-session-guest` 配下ルールで）:
- ショーのパネル（書き出す・読み込む・ショー一覧・新しいショー・複製・
  構成テンプレート・印刷用ページ）
- 劇場サイズ（形式・規模・この部屋を作る・会場を書き出す/読み込む）
- 音楽（楽曲を読み込む等）
- 出るもの（名簿からの追加）・舞台セット（セットを組む）
- 舞台機構・セット登録・照明・背景の各パネル
- 保存パネル・Vision Pro稽古用JSON・舞台を空にする・AI指示
- シーン列の「新規シーン・+セット・+全部・セクション+・地図・削除」等の編集ボタン
  （シーン一覧の表示自体は追従用に残してよい。切替不可は既存実装のまま）

**残すもの**: 舞台の絵（正面・平面・3Dカメラ等の見るための切替）、道具（矢印のみ・
E-3のまま）、シーンの表示、セッションパネル、ゲストバッジ、設定（環境設定）と言語切替、
F-3で環境設定内に移した「どこで何ができるか」。

**戻し**: セッションから抜けた（roleが消えた）ら全部元どおり表示される。
クラスの付け外しは既存の `stage-session-guest` の仕組みに任せ、CSSだけで隠すのが基本。
JSでhiddenを付ける場合は、外し忘れが起きない一箇所で管理すること。
