Stage Writeを実際に試して分かったこと

2026-09-09 / Web版 2.10.29 / Pro体験版 / 架空の台本2頁・照明キュー1件

現在ページの差替えでは、キューは残りました。ただし、台詞が下へ動いてもキューの位置は元のままです。舞台スケッチでは、旧版を残し、確認が必要な割当から順に付け直せる設計を進めます。

実画面で確認したこと

  1. 日本語PDFの読込みとキュー作成。架空台本「扉の向こう」を読み込み、ドラッグで範囲を作り、右側へ「LX 12 · 扉を開ける」を記入・保存しました。初期状態ではLQとSQのレイヤーがありました。
  2. 「新規PDF取込み」と「現在ページの差替え」で扱いが違う。Import New PDFは既存のキュー・文章・配置との関連を削除する警告を表示。空の検証作品への初回取込みだけ実行しました。Replace Current Pageは、選択PDFの先頭頁で現在頁を替え、注釈と配置リンクは維持すると案内します。
  3. ページ差替え後のキューを確認。改訂版の先頭頁へ替えると、LX 12の内容と枠は保持されました。対象の台詞は下へ移りましたが、枠とキュー文字は元の高さに残りました。各ハンドルをドラッグして付け直し、保存できました。
  4. 台本PDFを取得し、舞台スケッチへ読み込み。Create PDF → Production - PDF → PRINT PDFで生成した2頁をDownloadsから取得し、試作へ読み込めました。日本語本文とLX 12の位置は表示されますが、Qの日本語は出力PDFですでに□表示でした。本文は画像で、編集可能なQや台詞との対応は自動で引き継がれません。実ファイルと画面の比較を見る

設計への反映案

改訂版を追加する入口を分かりやすくし、旧台本・Q・割当を保持します。「残っている」と「正しい台詞に付いている」を区別して要確認を表示し、旧位置を見ながら新位置へドラッグできる流れを重視します。既存試作の「要付替え」警告をこの判断に使います。

ページをまたぐ移動、複数頁の一括改訂、配置・経路との関連、実iPad、CSV・独自形式の出力、他の文字・レイヤー・出力設定での再現性は未確認です。今回の1件をStage Write全体の仕様や全利用者の挙動へ一般化しません。

移行の流れ

  1. 台本をPDFで書き出す。今使っているアプリでPDFを保存し、左メニューの「PDF読込み」で選びます。先頭ページと頁数を確認してから反映します。
  2. 用意できたQ一覧をCSVで持ち込む。「Qシート」→「CSVを読み込む」から選びます。列名が違う表では「Cue → Q番号」「Description → 内容」のように対応を選び、全行の候補を確認します。移行元でCSVを出せない場合は、Q一覧の表を別途用意します。
  3. Qやシーンを台本へ置く。文字入りPDFでは本文へ、スキャンPDFではページ内の位置へ割り当てます。ドラッグのほか、項目を選んで台本を押す操作や、本文の選択欄も使えます。
  4. 改訂後の未確認箇所を直す。改訂PDFは別の版として追加します。前のQ・割当は消えず「要付替え」に残るので、新しい位置へ付け直します。

元の作業を残すための扱い

汎用CSVのQは新規追加として扱います。番号が同じだけでは既存Qを上書きしません。対応しない列や元の種別は備考に残し、頁番号や元アプリのIDを勝手に割当に変換しません。

PDFに見える線や注釈と、舞台スケッチで編集できるQは別に扱います。PDF上の既存注釈は描画可能なものを参照表示しますが、読み込んだだけで全てのキューが編集可能になるわけではありません。

今は操作確認用の試作です。ファイルはブラウザ内で処理し、送信しません。読み込んだPDF、Q、割当は再読込みで初期化します。QシートCSVは保存できますが、台本・割当全体のバックアップにはなりません。

製品に組み込む前に

提供可能な競合アプリの出力サンプルで、注釈・頁数・日本語の文字位置・配置の参照を照合します。元の件数と変換結果、要確認の項目が分かる取込み結果を作り、保存・復元と改訂履歴を製品側につなぎます。

自動で台詞を探して付け直す処理や独自プロジェクト形式の変換は、その確認を経て追加する計画です。
