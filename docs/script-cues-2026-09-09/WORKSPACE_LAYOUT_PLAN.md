# 台本あり／なしのワークスペース構成

2026-09-09 / Astra提案 / 製品未適用。人間向け入口はworkspace-layout.html。

## 本人の方向性

一画面で舞台と台本を管理するため、台本・キュー情報を右へ、メニューを左へ集める。台本あり／なしを分け、台本ありではiPadのような押出式も検討したい、という希望。左右配置はこの方向で計画を更新する。本人が比較見本に賛成したため、次の局所試作は押出式で進める。

## 既存の参照と今回の判断

現在のiPad PWAはstage-sketch.js:11554以降で同じパネルDOMを左ドロワーへ移し、入力・保存を一系統に保つ。style.css:10433付近は58pxレール＋0/280〜360pxドロワー＋残りの舞台というgrid。150msで幅を変更する。今回の押出式も「上に重ねて隠す」ではなく、パネルの幅を確保して舞台領域を縮める方式として検討する。現物のiPad操作感を今回測定したという意味ではない。

設計メモ: 演出・舞台監督が舞台を見ながら台詞と合図を対応させる。一度覚えた道具の場所が変わらず、表示を閉じても作業を失わない体験を優先。既存の舞台図、シーン、左レール、紙色を継承。台本表示に合わせてメニューを左右へ移動させない。役割別の画面が増えても同じ人物・シーン・キューを参照する。

| 構成 | 台本あり | 台本なし | 評価 |
|---|---|---|---|
| A 左メニューを常設 | 左に操作、中央舞台、右に台本 | 左操作＋広い舞台 | 大きな画面で一覧性が良い。舞台とPDFの両方を広く取る余地が少ない |
| B 左レール＋押出式（推奨案） | 左の道具を必要時に開く。右の台本は表示／折畳 | 左レール＋広い舞台 | 舞台の幅を確保しやすく、既存iPad構成へ接続しやすい |

「台本あり／なし」は同じプロジェクトの表示モード。切替でPDF・注釈・キューを消去/複製しない。台本未登録のプロジェクトも通常の舞台編集が使える。PDF未登録で台本ありを選んだ場合は登録入口を出し、登録を舞台編集の必須条件にしない。

## 操作の場所

- 左: ショー、舞台/人物、シーン/転換、台本/キュー、保存/設定のメニュー。作成・一覧・選択対象の編集入口も左へまとめる。今回の見本はシーン/キューの一覧と説明の限定表示。
- 中央: 現在の舞台。シーン名と舞台図を表示。シーン一覧を選ぶだけで切り替えず「舞台で見る」で明示的に表示する。
- 右: 台本の本文、注釈、選択した注釈の要点。ページ送り・ズーム等は本文に隣接する直接操作として右に置く。全体メニューを右へ複製しない。
- 下: シーン順と必要時の短い状況表示。人別予定表や転換詳細は同時に常設せず、必要時に選ぶ。『全部管理』を『全項目を常時表示』としない。

## 押出式の契約

1. パネルの開閉は表示だけ。舞台座標・選択・台本頁・注釈・キューを変えない。現在の舞台図は中央位置と縦横比を保って表示領域へ再フィットする。実製品のカメラとズームを保持する契約は統合時に検証する。
2. 右を閉じて戻しても頁・ズーム・選択・スクロール位置を復元。台本なしへ切替して戻る場合も同じ。
3. 十分な幅では左右同時表示可。幅が足りなければ新しく開く側を優先して反対側を畳み、その状態と再表示の入口を残す。狭いスマホ幅では一面を表示し、舞台へ戻る操作を常設する。小さな舞台を無理に残さない。
4. シーン/キューを左から台本へドラッグするときは、右のドロップ先を先に確保する。ドラッグ開始後にパネルを自動開閉して対象を逃がさない。狭い幅では「この項目を台本へ」から対象を持ったまま右へ移る代替操作を備える。
5. ドラッグ中のレイアウト/モード切替は未確定操作を取消し、元データを保持。ビューの開閉がGOやシーン再生を発火しない。
6. 台本のアンカー/注釈の表示座標とPDF内部座標を分離し、右パネル幅の変更を実データの移動と解釈しない。

1. **今: 画面構成を確認。** 台本あり／なし、左常設／押出、左右開閉をPC・iPad相当幅で比較。舞台と台本を読める面積、道具の場所、戻り方を見る。見本は固定HTML/SVGで実アプリ未接続。
2. **次: 1シーンと1キューを結ぶ一巡。** 新規のシーン/キューを左の一覧から右の台詞へ置く → そのシーンを中央で見る → 台本なしへ切替 → 戻して保持を確認。狭幅ではタップでも同じ結果。ここまでを実PDFの旧新版各1本で試す。
3. **その後: 改訂と保存。** PDF交換後の付替え/Undo、復元、転換・人物への参照を共同保存契約とつなぐ。製品への統合はここまでの仕様と実PDF検証を経て行う。
