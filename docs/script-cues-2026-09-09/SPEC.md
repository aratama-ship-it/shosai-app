## 1. 達成したい体験

「台本の箇所を選ぶ → キューを付ける → 舞台や転換の対象を選ぶ → 変更したところを確かめる」。
登録の速さだけでなく、稽古で台詞・順番・呼び出し位置が変わった後に、何が変わり何を確認すべきか読めることを完成条件にする。

### 設計前の5点

- 利用者: 演出・舞台監督が作り、関係する担当が読む想定。実際の担当者・規模は未確認。
- 場面: PCで仕込み、稽古中にタブレットで位置/内容を直す仮説。スマホは読む/少数の修正中心。実機検証で見直す。
- 使用感: 台本を読む位置を失わず、その場で付け直せる。後から取り消せる。
- 固有性: 台詞・動作・合図の前後、部門別の呼び名、場面と転換の区別、担当へ渡す紙にある。
- 継承/条件: 既存の紙色・舞台図・場面一覧を継承。読みやすい文字、44px操作、日英、IME、オフライン、保存失敗の回復、軽い停止状態を守る。

## 2. 3案のブレスト

| 案 | 強み | 変更時の弱点 | 採否案 |
|---|---|---|---|
| A 原資料へ注釈 | PDFや写真の台本をそのまま読める。組版・書込み位置を保持 | 差替えでページと位置が変わる。画像PDFから台詞の意味は自動取得できない | 添付がPDF中心なら初回入力の第一候補。元PDFを再構築しない |
| B 段落ごとに編集できる台本 | 台詞の途中と前後を細かく指定でき、編集の対応を追いやすい | 専用エディタへ移す負担。縦書き/ルビ/ト書きの入力を粗くすると逆効果 | アプリ内改稿が主目的なら第一候補。添付前には確定しない |
| C キュー表から割当 | 台本なしでも始められ、番号・部門・場面を一覧で整理しやすい | 台詞の前後を読むため往復が増える | 補助ビューとして採用候補。単独の主画面にはしない |

推奨は「台本に並ぶキュー＋選択中の詳細」。台本の表現層A/Bは差し替え可能にし、キューの意味と転換への参照は共通にする。3つの別アプリは作らない。全公演タイムラインは初版に広げない。

## 3. 『割当』を3操作に分ける

1. **呼ぶ箇所を付ける**: 台本の単語/台詞の終わり/ト書きの動作/段落前後へ付ける。
2. **起きることを付ける**: 明かり、音、転換などの内容と、場面/転換手順の参照を選ぶ。
3. **担当を付ける**: 転換の各作業の担当を転換画面で選ぶ。キューへ同じ担当名簿を複製しない。

現行の明かり表は場面間差分から印刷する派生表。そこから『候補として追加』は将来可能だが、差分を自動的に呼び出しキューへ確定しない。
台本位置を付けるだけでは舞台は動かない。音響・照明制御の送信、本番の呼び出し装置、共同同時編集はこの計画の初版対象外。

## 4. 主画面と端末

- 上: 公演/台本の版、保存状態、Undo/Redo。読む/編集のモードは見える位置へ。
- 左の主領域: 台本。各位置の脇にキュー番号・種別・短い内容。1箇所複数キューは縦に並べる。密度が高い箇所は「ほかN件」を展開、未確認を隠さない。
- 右: 選んだキューだけの詳細。呼ぶ位置、内容、接続先、準備/開始の区別、影響対象。舞台プレビューと手順の詳細はここから開く。
- 場面一覧/全キュー表/変更一覧は切替。常時4〜5列を表示して台本を狭めない。
- 台本とキュー詳細の選択を連動。本文のスクロールだけでは場面や再生を切り替えない。往復後は本文位置・拡大率・選択・フォーカスを復元する。
- 1024px以上: 台本minmax(0,1fr)、詳細320px、主領域が560pxを確保できなければ詳細を別面へ。
- 768〜1023px: 台本を広く、詳細は明示的に開く別面。閉じると元の位置へ。キーボード表示中も確定/取消を画面内に保つ。
- 767px以下: 台本/詳細を1面ずつ。主要操作44px。単純な縮小版にせず、番号と内容を省略しすぎない。
- 台本本文は18px/1.9、操作14〜16px/1.5以上。日本語の意味ある短い句だけを折返し制御し、長文全体をnowrapにしない。

## 5. 割当・変更・修復

### 初回と空状態

台本を開く、または台本なしでキューを作る。空のキュー表は『先にキューを作り、台本が届いたら位置を付ける』ことも案内する。
添付受領後に入力MVPを1つ選ぶ。PDFはテキスト層があれば選択、画像だけならページ位置をタップ。OCRで得た台詞は確認前の候補。Wordの往復編集/完全組版再現は独立した要件として判断する。

### 追加

箇所を選択→「キューを付ける」→種類/内容を入力。番号は任意、前回の種類は使える。必須入力は短い内容に絞る。選択前後のどこか（前/途中/後）を表示する。
既存キューを選ぶ導線と新規を分け、同名だから既存に自動統合しない。未確定の入力を下書きへ保存可能。

### 付替え

「位置を変える」→新しい箇所→「ここに移す」。旧位置と新位置の短い抜粋を同時表示する。Esc/取消で元の選択位置へ。ドラッグは任意の近道で、ドラッグだけにしない。
番号/内容/転換参照は維持し、Undo1回で位置だけ戻る。タブレットの長押しを必須にしない。

### 改稿

| 変更 | 自動で行うこと | 利用者に見せること |
|---|---|---|
| 該当箇所より前に文章を挿入 | 編集差分が確実なら同じ語を指す位置へ追従 | 対象語/内容が不変なら不要な確認を増やさない |
| 合図にした台詞を変更 | キューを保持、確実に対応するなら位置は追従 | 『台詞が変更』と旧新抜粋。意味を確認するまで既確認に戻さない |
| 該当語/段落を削除 | キューと参照を保持 | 『位置を選び直す』。旧抜粋、新位置選択、位置だけ解除、Undo |
| 同じ台詞が複数ある | 候補を並べる | 話者・前後文・場面で本人が選ぶ。最初の一致へ自動移動しない |
| 台本を新版へ差替え | 原本と既存対応を保持し、旧新の対応案を作る | そのまま/台詞が変更/位置不明。影響のある件数と個別修正へ |
| キュー番号を変更 | 同じcueIdを維持 | 転換の参照先表示と派生印刷を更新。ほかの番号は自動詰めしない |
| 場面を並替え/削除 | 台本位置は維持 | 場面参照と転換A→Bの接続が外れたことを別表示 |
| 保存失敗 | 編集中データと未保存差分を維持 | 『未保存』と再試行/ファイル保存。保存済みと表示しない |

改訂確認は行ごとに同じモーダルを出さず、変更一覧を1つ開いて連続処理する。未確認の全件を一括確認する操作は初版に置かない。確認する範囲を明示する。
版差替えの適用は台本/アンカー/確認状態を1トランザクションで更新する。台本をキャンセルしたのにキュー位置だけ変わる中間状態を作らない。
キューの削除/廃止と、台本位置だけの解除は文言も操作も別。参照中のcueを廃止するときは影響する転換の手順/待機を一覧化し、解決または明示的保留とUndoを用意する。

## 6. データの責任と転換への接続

詳細は INTEGRATION_DRAFT.md。転換側から回答を受領し、project.cues[] の共通正本と台本/待機条件の分離は双方賛成。最終schemaと主GO位置数は共同確定前。
転換側の HANDOFF_NEXT_2026-09-09.md を最新の担当交代・準備条件として優先する。担当交代は本人回答により通常要件となり、区間の担当が正本、作業全体の担当は派生。
合図の内容/位置変更は、合図に依存する担当競合・所要の確認へ影響し得る。幾何の確認は保持し、依存する確認だけを戻す。同じ合図を共有する転換複製はcueIdを維持し、独立コピー時だけ再発行する。
準備前の合図で作業は開始しない。準備後も勝手に動かさず『条件が揃ったとして試しを再開』を行う提案。現場のGO再発行とは別で、台本のスクロールやアンカー移動による自動GOはない。実際の受信/本番履歴は対象外。

| データ | 責任 |
|---|---|
| 台本/版/アンカー | 台本側。原資料ハッシュ、表示ページ、対応ブロック、選択位置、旧新抜粋 |
| cueId/番号/内容 | プロジェクト共通。番号は任意文字列、並び順やIDに代用しない |
| cueIdを参照するgroup/segment | 転換側。前作業完了AND合図、待機到達、対象、担当、所要時間 |
| 『この合図で進む作業』 | 参照から派生。独立した編集配列にしない |
| 試し進行中の合図通過 | 転換プレビューの揮発状態。台本JSONへ保存しない |
| 確認状態 | 位置・合図内容・転換内容・保存を分ける。人の確認を意味しない条件には『確認済み』を使わない |

初版案: cue1件に主GO位置0〜1、準備（standby）位置はGOとは別の注記として扱う。繰返し上演の同じ効果を別の箇所で呼ぶなら別cueId。複数GO位置の実例があればoccurrenceを導入するか判断する。転換内の同cue再待機ではwait-instanceを新しくする既存案を維持。
台本を読む位置とタイミングの正本は別。scene.cueSeconds/sceneAnimMsは表示用、rehearsalは既存の稽古予定。台詞の長さを秒へ自動変換しない。

### アンカー案

エディタ型: scriptId/revisionId/blockId、範囲、前/後の境界向き、短い一致文と前後文、確認した版。
文字インデックスはUTF-16等の規約を明記し、DOM表示行を保存しない。改行正規化、絵文字、結合文字、ルビ、IMEの変換中と確定時を別途テストする。W3Cの位置/引用セレクタは考え方の参照であり、現時点で準拠実装とは主張しない。
PDF型: assetId、revisionId、pageId、正規化矩形、ページの回転/CropBoxに対する規約、任意の確認済み抜粋。ページ番号の変更をページ同一性と混同しない。画像の差替えで位置を黙って継承しない。
原PDF/画像のバイナリをstateのUndoスナップショットに丸ごと重複保存しない。内容ハッシュの資産参照を用い、保存容量・ポータブル書出し・欠落時回復を先に測る。保存方式は容量調査後に決める。

## 7. 印刷・版・引継ぎ

初版に含む: 台本＋キュー、部門別キュー一覧、転換表への参照。公演/台本版/キュー編集版/出力日時/未確認件数を付ける。
同じ番号の別cueや未定の位置は紙でも残す。番号を詰め直す場合は旧→新対応と差分を別紙に出せる設計。
絞込み印刷でも準備/開始、必要な前提、台本の該当箇所が消えない。番号だけの表にしない。
変更の反映をアプリ内で確認できても、配布済み紙や他人の端末が更新されたとは表示しない。変更分の印刷は用意できるが、自動送信は対象外。

### 必要な検証

- ID: 同名別cue、欠落、重複、複製の内部/外部参照、番号変更、番号未入力。
- 割当: 台詞前/途中/後、ト書き、1箇所複数cue、同じ台詞反復、台本なし、準備と開始。
- 改稿: 前方挿入、対象内変更、範囲削除、block分割/結合/移動、新旧版差替え、対応の曖昧さ、取消。
- 回復: 付替えと廃止のUndo/Redo、改稿取消、保存失敗、再読込、元資料欠落、破損/未知版。
- 連携: 合図番号変更で参照保持、内容/位置変更が担当競合へ及ぼす影響、前作業完了AND合図、準備前GOと明示的な試し再開、同cue再待機、共通/独立の転換複製、表示用秒数非転記。
- UI: 1440×900/1024×768/768×1024/390×844/低い画面、日英、IME、44px、フォーカス復帰、reduced-motion、長い台詞、多数cue、印刷改頁。
- 性能: 実台本のページ/文字/cue件数と端末を記録して測る。固定例の成功を大きなPDFの速度/保存保証へ拡大しない。
