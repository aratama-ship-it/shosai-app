## 設計メモ
- 稽古中の演出・舞台監督が、手元の台本と既存Q表を持ち込む。
- 既存の作業が残っていることが分かり、試して戻せる操作にする。
- 核はPDF原稿・Q本体・台本位置の独立。改訂時もIDと旧版を保持する。
- 確認済みの左メニュー／舞台／割当道具／右台本の構成を継承する。
- 読込み失敗・取消で現状を変えない。新しい版を確認してから反映し、戻せる。
- 常設の大型移行パネル、専用別画面、モーダルを比較し、作業面を保てるモーダルを採用。

## 追加トークン

モーダル最大幅760px、外余白16px（狭幅8px）、最大高calc(100dvh - 32px)。
見出し22px/1.5、本文16px/1.75、補足14px/1.75。内部余白16px、操作間隔8px、区切り1px、角丸4px。
PDFプレビュー高220px、本文表示最大200万画素、読込み中は本文の割当対象を隠す。
外部PDF上は透明な全面操作面と位置ハイライト。文字範囲に置けば本文断片、それ以外はページ位置を保存。
PDF中のラベルは本文を覆わないよう下の一覧へ置く。選択した割当の位置を枠で表示。
CSV列対応は2列（狭幅1列）、候補一覧は最大高220pxでスクロール。見出しを固定し、取込前の全行を確認可能にする。
PDF本文の候補は、制御文字（NULを含む）と単独の頁番号を除外した後、2行かつ12文字以上ある頁だけに出す。条件を満たさない頁は候補を一切出さず「位置指定」で扱う。これは画像化・埋込みフォントなど原因を断定せず、読めない文字を台詞候補に見せないための保守的な判定である。
位置指定時は、本文候補に使わない理由と除外件数を取込プレビューに出す。反映後は紙面を直接押す操作と、キーボード利用者向けの「このページの中央へ置く」44px操作を出す。
保存の縦切りはIndexedDBの単一ワークスペース記録（schema v1）を使う。記録にはPDF File/Blob、PDF版ID・表示名、Q、typed subject、正規化したページ/矩形アンカーを入れ、同一トランザクションで置換する。保存中・保存済み・保存失敗を常時短く表示し、失敗時は画面上の作業を変更しない。
ページ画像・PDF.jsの描画キャッシュ・Undoの途中履歴・選択中の道具は保存しない。再読込み後はPDFをBlobから描き直し、Qと注釈ID/アンカーを戻す。端末内保存はバックアップや他端末移行を意味しない。書出し/読込み一式と本体project schemaへの統合は別工程にする。

## 実装範囲
- 任意のローカルPDFをPDF.jsで表示。ファイルを送信せず、同梱ライブラリ・workerで処理。
- 本文候補が判定基準を満たすPDFは文字範囲に近い位置、満たさないPDFはページ内位置へ割当。OCR・意味解析は行わない。
- 50MiB/ファイル、合計100MiB、300頁/版、外部版8件まで。ページは必要時に読み、画像キャッシュ3頁。
- 初頁プレビュー成功後に新しい版として反映。旧PDFと既存Q/配置参照を保持。以前の位置は要付替え。
- 既存PDF注釈は描画できるものを参照表示。独自レイヤー・注釈を編集可能なQへ自動変換するとは約束しない。
- 汎用CSVの列対応を確認してQ表の候補へ追加。番号だけで既存Qを上書きしない。
- 対応しない列や元種別は備考へ残す。ページ数や元IDを自動で割当・GOへ変換しない。
- 自社CSVは従来の安定IDによる更新を維持。全処理はブラウザ内の仮データで、試作ワークスペースは同じ端末・同じブラウザで再読込み後も復元する。
- 試作のPDF・Q・割当はこの端末のIndexedDBへ自動保存し、同じ端末・同じブラウザで復元する。保存不能時は保存済みと表示しない。外部バックアップ、他端末同期、製品projectへの保存統合は行わない。
