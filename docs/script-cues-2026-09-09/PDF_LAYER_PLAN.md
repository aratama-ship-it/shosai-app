## 1. 今回はここを核にする

PDF台本をそのまま開き、ページ・行・単語に照明/音響キュー、配置図、動線、転換への参照を付ける。改訂版への差替えでは、作った情報を残し、必要な位置だけ直して舞台監督用のコーリング台本を更新する。

第一案の判断:
- 誰/いつ: 演出・振付担当が配置/動線を結び、舞台監督がキューを整理する。稽古の改稿後も作業を継続する。
- 使用感: 以前の作業が残っていること、直す範囲が限られていることを把握し、迷ったら元へ戻れる。
- 固有の核: 台本の言葉と配置/動線/舞台転換の対応、準備と開始の区別、部門ごとの読む/渡す体験。
- 継承: 舞台スケッチの色/場面/舞台図を継承。PDFビューアのズーム/ページ送り、注釈の非破壊編集を使う。
- 条件: PDF本文の組版を変えない。ドラッグ＆ドロップを主導線とし、クリック/タップ/キーボードの代替操作も備える。小画面では拡大と内部パンを使い、主要操作を44px以上に保つ。

### 3方式の比較と採否

| 案 | 良い点 | 破綻する例 | 採否 |
|---|---|---|---|
| 固定座標だけのレイヤー | PDF画像でも使え、背景交換で注釈が残る | 台詞が改頁/折返しすると別の言葉を指す | 最低限の保持方法として必要だが単独では不十分 |
| 抽出テキストだけに紐付け | 同じ単語が動いても追いやすい | 画像PDF、文字抽出順序、同語反復、ルビ、台詞の削除 | 補助的な候補提示に使う。必須入口にしない |
| **PDF＋独立注釈＋位置の対応情報** | 保存を保証しつつ、確かめて調整できる | 自動対応不能な箇所には手作業が残る | **推奨。自動候補と人の調整を両立する** |

アプリ内の台本執筆・Word原稿の往復編集は後段。今回の入口を汎用文書エディタへ広げない。

## 2. UIは『レイヤーを作る』から始めない

画面全体の配置と台本あり／なしの使い分けはWORKSPACE_LAYOUT_PLAN.mdを最新案とする。左に操作、中央に舞台、右に台本・キュー。常設/押出式はworkspace-layout.htmlで比較する。表示モードを切り替えても共通データを消去しない。

本人の2026-09-09の希望により、通常の主導線は「PDFを開く → キューや配置図をつかむ → 台詞へ置く」。選択中の舞台場面/動線から「台本に結び付ける」という逆の入口も用意する。
表示を切り替えるときにだけ『照明・音響・配置/動線・転換・メモ』を選ぶ。内部は独立レイヤーでも、最初にレイヤー名・重なり順・グループ管理を入力させない。

- PDF上のアンカー（何を指すか）と、余白のラベル/吹き出し（文字をどこへ置くか）を別に編集する。ラベルを避けるだけで合図の位置が動かない。
- テキストPDF: 単語/行を選択し『この語の前/後』『この行の終わり』等を指定。範囲に付ける一般メモと、瞬間を指すGOを区別。
- 画像PDF: タップ/矩形で位置を指定し、必要なら合図となる言葉を本人が短く入力。読めない文字をアプリが補わない。OCRは任意の補助候補。
- ページ全体の注釈: ページ内の特定語を意味しない。ページに付いたものと単語に付いたものを凡例/詳細で区別。
- 同じ箇所に複数注釈: 部門名と番号を並べる。見た目だけの重なり調整でアンカーを変えない。注釈の未確認件数は折り畳んでも見える。
- 位置変更: 注釈をつかみ、行/単語の候補を見ながら移動し、離して付け直す。指す箇所の変更はその場で1操作として反映し、意味の確認は別に残す。毎回モーダルや確認ボタンを挟まない。クリック/タップの「注釈を選ぶ→指す箇所を変える→新箇所」とキーボードも同じ結果になる。
- 読むモード: ページ送り/ズーム/注釈参照が中心。編集モードを明示し、Pencilで本文を触っただけで合図を動かさない。タッチ仕様は実機確認が必要。
- 戻るとPDFのページ・拡大率・スクロール位置・選択を復元。通常は舞台ビューを自動切替しない。『この配置を見る』『動線を見る』で明示的に開く。


### 直接つかんで操作する設計（本人の希望を優先）

- 新規の割当はキュー/配置図/動線の一覧から台本へドロップ。元の場面や経路を移動・複製するのではなく参照を付ける。既に付けた注釈のドラッグは付替えで、無断で注釈を増やさない。
- ドラッグ中は元の場所を残し、持っている注釈と対象件数、行/語の候補を表示。候補は位置だけでなく話者/前後の短文を見分けられる表示とし、離すまでデータを変えない。
- 単語/行/ページのドロップ領域を区別。同じ語が複数でも、実際に指した候補を採る。原PDFの文字層がない場合は位置へのドロップと短い合図文で扱う。
- 複数選択して1件をつかむと全選択が動く。元の間隔を保持した一括移動のプレビューを見せ、範囲外の対象があれば全体を取消。部分的に適用しない。段落ごとのずれは別々に選び直す。
- 見た目だけの調整は別の「ラベル位置」操作/ハンドルで行う。台詞を指す位置と接続線は固定し、合図の意味を変えない。つかむ場所で何が動くかを区別する。今回の見本は注釈の付替えと一括移動のみを実装し、自由なラベル配置は未実装。
- 正常なドロップで確定、1回Undoで対象全件を戻す。候補外・Escape・pointercancel・画面切替で取消。ドラッグを離した後のclickを別の操作として誤実行しない。
- 読むモードと改訂比較の旧版は編集不可。タッチでは注釈をつかむ動作と背景のスクロール/ピンチを分ける。長押し待ちは既定にせず、専用ハンドル等の判別を実機で確認する。
- ページをまたぐ移動は端スクロール/ページ送り候補から行先をプレビュー。これと新規割当パレット、矩形選択、ラベル位置の独立ドラッグは製品試作で検証する項目。現時点の固定見本は表示中の3語へのドロップに限る。

## 3. 初版に含む注釈

| kind | 対象/意味 | 動作 |
|---|---|---|
| cueRef | 照明/音響などの共通cueIdと呼ぶ箇所 | 詳細を表示。選択で発火しない |
| sceneRef | 配置図を持つsceneId | その配置を表示。GOを作らない |
| pathRef | 場面/転換の特定の経路 | 参照先を強調して表示。別の経路データを複製しない |
| transitionRef | 転換全体/特定の手順や区間 | 転換の段取りを表示。呼ぶ合図が必要なら別途cueRef |
| note | 短文/指示メモ | 台本上の注釈。実行条件式にはしない |

レイヤー表示をOFFにすることは、キューを無効化/削除することではない。差替えと参照整合性チェックは非表示/ロック中を含む全注釈が対象。一括調整では対象集合を件数と部門で示し、ロック中は除外するか本人が明示解除してから操作する。
部門別番号は任意の文字列。LX12、S3、Q13等を固定規則で統一しない。表示番号をIDや台本順に使わない。同じGOを複数部門に分けるかは現場運用で選ぶ。

## 4. 改訂PDFへの差替えは4段階

### ① 新版を開く

元PDFと注釈はそのまま。新版は別資産・別revisionとして読込。ファイル名が同じでも上書きしない。全体差替えと1ページ差替えは同じ仕組みで範囲を指定する。
読み込み失敗/破損/パスワード保護/容量不足なら現行版で作業を継続できる。解析失敗の段階で注釈を消さない。

### ② ページを対応させる

旧12頁→新13頁等を見せる。PDFの物理index、紙に印刷されたページ番号、論理pageIdを分ける。
同じ描画/本文でも複数あるページや白紙は、一意な対応とは断定しない。ページ内図版/回転/CropBox/寸法の差も確認する。
ページの分割・結合では一対多/多対一の対応を許容し、個々の注釈の行先を選べる。UIとデータを1対1写像だけで作らない。

### ③ 注釈を保ったまま確認する

旧/新を同じ倍率で切替または比較。『元の注釈位置を表示』は比較用の輪郭で、新版の確定位置と混同しない。比較の位置連動は任意とし、手で見ている場所を勝手に戻さない。

| 結果 | 次の操作 |
|---|---|
| ページと内容/位置が同じ | 対応の根拠を表示。変更のない範囲は個別の再登録不要 |
| ページ番号だけ変わる | 旧→新のページ対応を確認。注釈の内容/ID/意味は保持 |
| 内容は同じで位置がずれる | 候補に合わせる、または選択した注釈をまとめて平行移動。対象と移動量のプレビュー→適用→Undo |
| 同じ言葉が複数ある | 前後の台詞/話者と候補を並べ、指す箇所を選ぶ。最初の一致へ自動で決めない |
| 台詞が改変された | 元の言葉と新しい言葉、影響する合図/接続を示し、意味を確認 |
| ページ/台詞が削除された | 注釈は『行先を選ぶ』に残す。旧抜粋/元ページ/元座標/参照先を保持して再配置可能 |

配置をまとめて動かす対象は本人が選ぶ。本文が均等にずれた場合だけ平行移動を候補にし、拡大/回転/非線形変形を自動で注釈全体へ適用しない。文字サイズや線幅まで変形しない。
アンカーとラベル位置をどちらも動かすか、アンカーだけかを明示。ラベルのみの調整は合図の意味を変えない。
確認状態は単純な緑/赤1つに潰さない。『位置が一致するか』『合図の意味/順序が同じか』『参照先が存在するか』を独立に持つ。意味が変わったか判定できない場合も影響する担当/所要は要確認。

### ④ 新版に切り替える

『注釈 N件を保持／位置確認 K件／意味確認 M件／行先なし U件』を表示。保持件数は重複しない総数、確認種別の件数は重複し得ると表示。
未解決を残して新版を下書き採用することは可。ただし『未解決K件を残して切り替える』を明示し、確認済みにはしない。紙にも未解決を残す。
版の切替とアンカー候補採用を1つの原子的操作にする。途中失敗なら現行版は無変更。採用前の取消は旧版へ戻る。
採用後は通常のUndo/Redoで差替え操作を戻せる。後続の編集があるときの『旧PDFへ戻す』は、その編集を黙って消さず、現在の注釈を保った別の差替えとして扱う。

## 5. 保存の責任分担

概念モデル（まだ製品へimportできるJSONではない）:

```
Project
  ScriptRevision -> immutable PDF asset hash, ordered revision pages
  Annotation     -> id, layer, typed subject, anchor history, label placement
  Cue            -> id, display label, content
  Scene / Transition / Work segment -> existing stage data

Annotation.subject: cueRef | sceneRef | pathRef | transitionRef | note
Annotation.anchor: revisionId + pageId + region + optional quote/context
Annotation.label:  revisionId + pageId + separate label placement
```

PDFを削除/交換しても注釈をcascade deleteしない。行先が無くても履歴を持つ独立annotationとして残す。PDF内に焼き込んだ注釈だけを編集正本にしない。
元PDFは資産単位で保持し、Undoのたびにバイナリをstate JSONへ複製しない。版の採用は資産/ページ対応/注釈をトランザクションで保存。容量不足/途中終了/保存競合をテストする。
ページ座標は回転/CropBoxを解決した正規座標とし、表示ズーム/スクロールと分離。PDF本文の抽出文字位置は補助で、文字抽出の順序・正規化・ルビ・縦書きを確定しないまま唯一のキーにしない。
pathRefは既存routeに安定IDがあると仮定しない。現在のstage-sketch.js:3451はpiece.routeとして格納、同一対象の対応はcastId/setId/originId等。実装前に場面/対象/経路・転換/作業/区間の参照を解決できる契約を確定する。削除/分割/複製後の対応が不明なら『対象の経路を選び直す』へ残す。名前や距離で付替えない。

### 転換側との整合

- 共通cueIdと転換作業/区間の参照をPDF差替えで変更しない。
- 呼ぶ内容/順序が変わる、または同じと判定できない場合は依存する担当/所要の確認を引き継がない。無関係な幾何は保持。
- 同じ内容/順序のまま別の紙面位置へ動いたと確認できる場合は、担当/所要の不要な再確認を増やさない。
- 担当交代・準備工程・合図先着は転換側HANDOFF_NEXT_2026-09-09.md。本文の頁送り/注釈選択はGOではない。
- 同じ合図を使う転換の複製はcueId維持、独立した合図だけ新ID。
- 旧v3/v4、normalizeState/Undo、共有/MCP/棚/ファイルの保存契約は両機能で共同監査。注釈を理解しない旧書込みで消える経路を残さない。

## 6. 印刷と渡すもの

初版: コーリング台本PDF（原PDF＋注釈）、部門別一覧、配置図/動線/転換表の参照または付録。印刷用余白を足す場合も原PDF資産は無変更、派生レイアウトとする。本文上に重なる注釈は印刷前に調整できる。
公演・PDF版・注釈版・出力日時・未解決件数を残す。非表示レイヤーを何としたか印刷前に選び、除外を明示。
『読む用PDF』と『編集を続けるバックアップ』を分ける。後者は必要PDF資産、注釈、cue、参照先の必要データ、マニフェストを含み、新しい環境で復元できることを実測する。localStorageだけの保存をバックアップと呼ばない。
編集用一式のファイル構造は保存基盤調査後に決定。共有後に相手の紙/端末が新版へ変わったとは表示しない。

### 試験の最小セット

1. 同じレイアウトのPDF差替えで全注釈ID/内容/参照不変。
2. 途中に1ページ追加、削除、並替え。物理番号と論理参照を混同しない。
3. 段落が次のページへ移る。1→2頁/2→1頁も個別注釈の行先を選べる。
4. 同じ語の反復、台詞変更/削除、白紙/重複ページ、画像PDF。
5. ラベルだけの移動はanchor/合図の意味を変えない。
6. 選んだ注釈だけの一括移動。隠した/ロックしたレイヤーを黙って変えない。
7. 合図内容不明のまま、担当/所要を確認済みにしない。cueIdと幾何は保持。
8. PDF読込失敗、途中終了、保存失敗、容量不足、旧版読込、参照欠落で原版を失わない。
9. 取消/Undo/Redoと、差替え後に編集して旧PDFへ戻す場合の保全。
10. コーリング台本印刷の未解決/版情報と、編集用バックアップの新環境復元。

計測: 旧新PDFのSHA-256、ページ数/サイズ、注釈数、手動調整時間、誤対応件数、端末/ブラウザ/画面寸法を記録。固定HTML見本の成功をPDF解析・大量頁性能・保存の証明にしない。
