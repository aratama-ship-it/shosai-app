# 台本・キューと舞台転換：接続案

転換側の SPEC.md と OPERATIONS_2026-09-09.md を読み、既存設計へ以下を提案する。転換側の資料は上書きしない。

1. 合図の定義は project.cues[] の一か所を正本にする案。転換のみでも使え、台本の登録は必須にしない。番号/名前からの自動統合は禁止。cueId は同一プロジェクト内の安定ID。
2. 台本は scriptId/revisionId とアンカーを所有する。台本位置は cueId に結び付けるが、転換の groups/actions/segments は現行案どおり cueId を参照する。転換→合図の参照から逆引き一覧を生成し、同じ接続をcue側へ二重保存しない。
3. 合図は『いつ呼ぶか』、転換は『前の作業が終わったか・待機へ到達したか・どの対象が動くか』を所有する。台本をスクロール/選択/編集しても合図を発火しない。standby は GO と別の注記役割で、待機を解放しない。
4. 初版は1 cue に1つの主GO位置（未割当可）を提案。同じ台詞に複数cue可。別の時点で同じ効果を繰り返す場合は新cueId。転換内で同cueを再度待つ場合は既存案の新wait-instanceと再確認を維持し、過去に通った台本アンカーを流用して自動解放しない。複数GO位置が必要なら実例を受けて occurrenceId を検討する。
5. 台詞編集は変更内容を見せる。番号変更では作業参照を維持。合図の内容/主GO位置変更では受け手一覧に変更を示し、影響する担当競合・所要時間を再確認する。幾何が不変ならその確認は保持する。位置の未解決、合図の意味、転換の幾何/担当、保存成功を別の状態として扱う。
6. 台本削除/改稿で位置が失われてもcueと作業を消さない。『位置を選び直す』へ残す。使用中cueの廃止は影響する待機/手順を列挙し、参照解決/Undoを一括で行う。台本位置の付替えだけでキュー番号や転換時間を変えない。
7. 既存 cueSeconds/sceneAnimMs/rehearsal の時間は継承。台本順から経過秒数は生成しない。担当交代を含む場合、合図を試したことと作業を開始できることを分ける。準備前の合図では進めず、準備後も自動再開せず『条件が揃ったとして試しを再開』する提案。現場で同じGOを再発行する意味ではない。揮発的な試し履歴であり、次の待機を解放する予約/実受信記録ではない。転換側 HANDOFF_NEXT_2026-09-09.md を優先する。
8. 新形式の保存契約は台本と転換の共同作業1件にする。v3/v4の入口差、normalizeState/restore、棚・共有・MCP・ファイル・旧クライアントを一緒に監査。旧書込みで新キーが消える経路を残したまま製品保存を有効にしない。
9. 転換の複製で同じ合図を使うならcueIdを維持。独立した合図として複製する場合だけcueを新IDへ複製し、該当参照を付替える。プロジェクト全体の複製はプロジェクト内IDの参照閉包を保つ。名前からの自動統合は禁止。
