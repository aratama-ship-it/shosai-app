# 設計研究 HTML：設計メモとトークン（2026-09-11）

対象 `index.html`（判断用の静的資料）。既存の set-transitions／project-contract 資料の紙色と工程表を継承。製品 UI ではない。

## 設計メモ（5つの問い）

1. 誰が・どの場面で: 本人（演出・舞台監督）が、改訂の届け直し方式を採用するかを決める場面。稽古の合間にスマホで読む可能性がある。
2. どんな気分に: 「何を決めればよいか」が冒頭で分かり、規則と反例を辿れば根拠に届く。読み終えて未確認事項が残っていることも分かる。
3. 固有の核: 4層の所有境界、4つの記録の分離、変更の種類ごとの規則、架空公演での反証。装飾ではなく表と規則で固有性を出す。
4. 踏襲・外すもの: 既存資料の紙色・見出し・工程表・44px を踏襲。カード反復・グラデーション・大きな抽象コピーは使わない。ケースは折畳＋絞り込みで一覧性を保つ。
5. 守る条件: PC／スマホ、印刷、reduced-motion、キーボード操作、外部依存なし、file:// で開ける。

比較した構造: (a) 長文＋表、(b) 判断3件→要約→根拠の階層、(c) ケース中心。(b) を採り、ケースは §7 に折畳で置いた。
