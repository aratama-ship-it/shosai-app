M1の結論: 窓口は作れる

本体を読んで確かめた根拠。

  1. 本体は論理座標で描いて、あとから倍率をかけている。 drawStage の冒頭は const S = target.canvas.width / W; target.setTransform(S,0,0,S,0,0)。つまり W×H（W＝メインキャンバスの幅、H＝720）という固定の座標系で描き、描画先の大きさに依存しない。任意のキャンバスへそのまま出せる。
  2. 会場と駒の描画は画面固有の状態を見ていない。 ズーム（zoomOf）は drawStage 側で別に掛けている。drawFrontVenue(target, L) と drawStagePiece(target, piece, L, leanAt) は L（レイアウト）だけを見る。
  3. 投影も同じ座標系。 stagePoint(u,v,h,L) が論理座標を返すので、光を重ねるときは同じ S を掛ければ必ず一致する。

本体側に要る手当て（M4でやる）: ①drawStage の中にインラインで書かれている駒の描画（並べ替え・保持物・名前）を drawPiecesInto(target, L, leanAt) として切り出す（振る舞いは変えない小さなリファクタ） ②window.SHOSAI_STAGE_VIEW を足す。

気をつける点: refreshBases(L.size) と buildPaintLayer(L) を描く前に呼ぶ／ズームは掛けない／首振り（state.frontPan）と表示トグル（state.showLightsFront など）は state を見るので、モーダル側から指定できるよう layout(view, override) の形にする（照明駒は出さない——別物なので）。

1. 何を作るか

試作で固まった「照明を組む」画面を、舞台スケッチ本体の中に作る。正面図（3D）は本体の描画をそのまま使う——袖幕・ホリゾント幕・舞台の立ち上がり・客席の暗がり・姿勢つきの演者・会場の種類が最初から全部出る。試作のように描き直さない（二重管理を作らない）。

本体の描画を使う、の中身

本体の正面図は drawFrontVenue（546行）＋drawStagePiece（121行）＋姿勢49種＋写真・塗り層・実在会場の輪郭で出来ている。これを写すのではなく、本体に「描いてもらう」。 必要なのは本体側の小さな窓口1つだけ。

// stage-sketch.js に足す（これだけ）
window.SHOSAI_STAGE_VIEW = Object.freeze({
  // 指定のキャンバスへ、正面図の会場と駒を描く。戻り値はその絵の投影関数。
  // 光はこの投影関数を使って上に重ねる＝同じ遠近・同じ席で必ず一致する。
  renderFront(ctx, { width, height, sceneId, seat }) {
    const L = layout("front");            // 既存
    drawFrontVenue(ctx, L);               // 既存（幕・ホリゾント・apron・客席・会場）
    drawPieces(ctx, L);                   // 既存（姿勢つきの演者・セット）
    return {
      point: (u, v, hM) => stagePoint(u, v, hM, L),   // 既存
      pxPerM: L.pxPerM, seat: L.seat, size: L.size,
    };
  },
  seats: () => FRONT_SEATS.map(s => ({ id: s.id, label: s.label })),
});

※ 実際の引数と内部関数名は実装時に本体へ合わせる。上の形で足りるかは未検証——layout() が画面固有の状態（ズーム・首振り・選択）を見ているので、切り出せるかを最初に確かめる（下の M1）。
