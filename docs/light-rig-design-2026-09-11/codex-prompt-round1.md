# 設計のやり直し依頼: 舞台スケッチ「照明を組む」画面（灯体を舞台に組み、一灯ずつ動きを付ける）

あなたはClaude（私）と本人（元サーカスアーティストのショー制作者）の壁打ち相手です。目的は「別の角度からの案」と「Claude案への厳しい批評」。同意の羅列は不要。

## 前提の訂正（重要）
同じフォルダの親 `docs/light-ui-brainstorm-2026-09-11/`（spec.html、codex-round1〜4.answer.md）に前回の4ラウンドがある。結論は「機材（灯体）をモデル化せず、プリセットから動く光を1つ作って渡す」だったが、**本人の意図を読み違えていた**。本人の訂正（2026-09-11、原文の要旨）:
> まず「照明を組む」というボタンを追加し、そこで照明をステージに組んでいく作業をできるようにしたい。劇場にはトラスがあり、床や横にムービングライトが設置されていることがほとんどなので、それらの位置を設定する。その後、それら一つ一つの動きを設定していく。そこまでをやる総合的なアプリが必要。プリセットだけでボタンで選ぶということではない。

前回の資料は「状況把握」のためだけに読んでよい。結論（機材を持たない・プリセット主入口・光の意図カード）は**採用しない**。

## 本人の確定回答（2026-09-11）
- Q1 既存の照明パネル（吊り／SS／前明かり／転がしの4種＋プリセット）との関係 → **「照明を組む」という別の画面を新しく作る**。既存パネルはそのまま残す。
- Q2 灯体の位置の精度 → **概略でよい**（トラス＝奥から何段目とおおよその高さ、床＝舞台上の位置、横＝上手/下手とおおよその高さ）。実在会場の寸法・バトン番号との対応は後。
- Q3 一灯ずつの動き → **型（往復・扇・交差・円・順に等）を灯ごとに割り当て、範囲・速さ・向き・開始位置を調整**。複数灯の関係（一緒に／向かい合わせ／順に）は組で指定。
- Q4 用途の軸 → **照明さんへ渡す「案」のまま**。灯体の位置と動きは持つが、機材の型番・回路・DMX・照度は持たない。書き出しは動画・図・一文。

## 既存資産（コードを読んで確認してよい。すべて shosai-app/ 配下）
- 照明パネル（stage-sketch.js `LIGHT_KINDS`、`LIGHT_PRESETS`、`renderLights`、`drawLight`）: 灯体を `project.sets`（kind:"light"）に登録し、各シーンの `scene.pieces`（type:"light"）に灯体位置(u,v)＋当たる先(beam)＋強さ(glow)を持つ。平面図・正面図・3D簡易ビューに描く。光の動線（シーン間で当たる先が移動）もある。**今回は触らない**。
- 動きモジュール `stage-light-motion.js`（今回作成済み）: 5つの動きの型（sweep/fan/cross/circle/chase）、位相計算（1周期＝端→端→端、circleは1周）、正規化、`drawFrame(ctx,w,h,motion,tMs,opts)`、動画書き出し（captureStream(0)+固定ステップ+MediaRecorder、実機検証済み）、3コマPNG。ただし出どころは固定の仮位置で、灯体の実位置とは無関係。**再利用できる部分と作り直す部分を切り分けてほしい**。
- 「光の動きを組む」モーダル（今回作成済み、`scene.lightMotion`、シーンに1つの動き）: 本人は「これはこれでいい」と言ったが、新しい「照明を組む」に吸収・置換されるべきかは論点。
- 会場モデル: `venueSize()` が幅・奥行き・高さ(m)を返す。venue-v2 は実在会場の輪郭・客席・バトン帯（ceiling.gridM、描画のみ）を持つ。
- 別画面の先例: `stage-venue-editor.js`（会場を組む専用モーダル、自前のキャンバス、保存してから本体へ反映）、`stage-set-builder.js`（セットを組む）。「照明を組む」もこの型に倣うのが自然。
- 制約: iCloud共有ワークスペース、Nodeテスト（tests/*.test.mjs、i18nカバレッジが厳格＝新しい日本語文言は英訳必須）、index.html→build_stage.py→stage.html、Service Worker・?v=は公開時まで触らない、既存の未コミット変更を保護。

## Claude(私)の案（たたき台。遠慮なく壊してよい）
**A. データ（2層）**
- `project.lightRig`（ショー共通・シーンをまたいで同じ）: `trusses[]`（id, 奥から何段目 row 0..n, 高さm 概略, ラベル）、`fixtures[]`（id, 名前, 種類: moving／spot／wash の3つ程度, 取り付け: {mount:"truss", trussId, u} | {mount:"floor", u, v} | {mount:"side", side:"L"|"R", v, h}, 色）。
- `scene.lightRigCues`（シーンごと）: `[{fixtureId, on:true, motion:{type, range, speed, direction:"lr"|"ud"|"cw", start:"left"|"center"..., phase}, groupId}]`＋`groups[]`（id, relation: together|opposite|sequential）。動きなし＝静止して当てるだけ（当たる先 aim を持つ）。
**B. 画面「照明を組む」**（照明パネルにボタン、既存の「プリセットから組む」の並び）: 会場エディタ型の広いモーダル。上部に2つの段階タブ「①組む（灯体を置く）」「②動かす（一灯ずつ）」。
- ①: 左に平面図（上から）、右に正面図（客席から）を並べる。パレット「トラスを足す」「ムービングを置く（トラスに／床に／横に）」「スポットを置く」。置いた灯体はドラッグで位置調整、右の一覧で名前・色・削除。
- ②: 一覧から灯体を選ぶ（複数選択で組）→ 型・範囲・速さ・向き・開始位置。正面図で再生（灯体の実位置から光線が出る）。組の関係を指定。
**C. 描画**: 自前の概略キャンバス（既存の舞台描画は流用しない）。トラス＝横線、灯体＝小さな印＋名前、光線＝出どころ→当たる先のグラデーション線、当たる先の輪。現在シーンの演者は平面位置から読み取ってシルエットで表示（編集不可、位置関係の参考）。
**D. 書き出し**: シーンごとに動画・3コマ図・一文（既存の書き出し経路を灯体複数対応に拡張）＋灯体一覧（名前・置き場所の概略）。「案。機材・DMX・安全性は示さない」を焼き込む。
**E. 既存との関係**: 既存の照明パネル（4種＋プリセット）は触らない。`scene.lightMotion`モーダルは「照明を組む」の②の一部に吸収し、旧モーダルは非表示（データは残す）。
**F. MVP順**: ①トラス1本＋灯体を置ける→②1灯に型を割り当て再生→③複数灯と組→④書き出し→⑤床・横の設置→⑥灯体一覧の書き出し。

## 依頼（順番にすべて答える）
1. **Claude案A〜Fの批評**: 特に(a)データの2層構造（ショー共通のrig／シーンごとのcue）は妥当か、既存の `project.sets`/`scene.pieces` の設計と整合するか、(b)「概略の位置」の持ち方（トラス段数・床u,v・横side+h）は照明さんが読める最小か、(c)向き(direction)の設計: 横に置いた灯体の「左右に往復」は何を意味するか、パン/チルトを持たずに向きを表す最小の語彙は何か。
