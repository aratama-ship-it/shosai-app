## Claude（Fable）の第1案 — 壊してよい

### A. 「フルリグ」＝劇場サイズ別の最強機材セット（3種）
既存8種と同じ `RIG_PRESETS` の仲間として、劇場プリセットの小/中/大に1対1で対応する3つを足す。
| | 小劇場 8×7×6 | 中劇場 12×9×8 | 大劇場 18×12×12 |
|---|---|---|---|
| 前明かり（固定） | 8 | 12（シーリング8＋フロントサイド2+2） | 16（10＋3+3） |
| バトン1/2/3（全ムービング） | 6/6/6 | 8/8/8 | 10/10/10 |
| SS 下手/上手 | 固定3/3 | 固定3/3＋ムービング1/1 | 固定4/4＋ムービング2/2 |
| 床置きムービング | 4 | 6 | 8 |
| ホリゾント | 床＋上 | 床＋上 | 床＋上 |
| 合計 | 42 | 58 | 76 |
バトン高さは劇場高さの 0.85〜0.9 倍。前明かりは既存 `putFront` の ahead/h を劇場サイズで比例。
選んだ会場プリセットに応じて自動で該当フルリグが入る（「ビジュアルから作る」ボタン1つ）。

### B. プリセットは灯体IDではなく「役割（ロール）」で書く
`preset.layers[].role` = `front` / `b1` / `b2` / `b3` / `ss_l` / `ss_r` / `floor` / `cyc_floor` / `cyc_top`。
狙い先は名前付きゾーン: `stage`（全面）/ `center` / `ds` `us` `ds_l` `ds_r` `us_l` `us_r` / `aerial{hM}` / `performer{n}`（シーンの演者）/ `house`。
**適用時にリゾルバ**が今のrigの中で該当ロールの灯体を探し、ゾーンに均等に散らす（`spreadU` と同じ考え）。
→ フルリグでなくても既存8種のrigに**縮退適用**できる（該当ロールが無ければその層は静かに空振り、結果に「この明かりは○○が無いので一部しか再現できていません」と出す）。

### C. プリセットは「層」。全部入りではなく重ねる
層の種類: 地明かり(base) / 顔(face・前明かり) / 抜き・逆光(back) / 横(side) / ホリゾント(cyc) / スペシャル(special・1〜数灯) / 動き(motion) / 効果(fx・ストロボ等)。
1つのプリセットは1〜数層を持ち、**触れるロールだけ上書き**する。「ルック」＝層の束（例: 「夕暮れの独白」＝ cyc:オレンジ→紫グラデ ＋ back:琥珀6灯 ＋ face:弱め暖色 ＋ special:中央ピン）。
右パネルに「いまの明かりの層」チップを常時出し、どの層が何のプリセット由来か分かる。

### D. 「大量」の作り方
- 手で書く**基本ルック 30〜40**（サーカス・演劇・ダンス・トークの定番。名前は照明用語でなく場面の言葉）。
- **バリエーション軸**で機械的に増やす: 色（12色相＋白3種）× 強さ（3段）× 広がり（絞り/普通/開き）× 動き（なし/ゆっくり往復/扇/円）。手書き30 × 軸で数百〜千になるが、一覧に千枚並べるのではなく**「基本ルックを選ぶ→軸を3つのつまみで振る」**。
- サムネイルは静止画を用意せず、**その会場・そのrigで正面図（3D）を小さく描く**（既存 `drawFront3D` を流用、120×68程度、遅延描画＋キャッシュ）。

### E. データ形式
プリセットは**JSONデータ**（関数でない）。`{id, version, name, words[], layers:[{role, zone, level, color, beamDeg, path?, gobo?, strobe?}], tags{genre, mood, colorFamily, motion}}`。
適用は純関数 `applyPreset(preset, rig, dims, scene, cue) → {cue', coverage}`。`coverage` に空振りした層を残す。

### F. UI（PC・照明デザインモード内）
- 入口: 灯体パネル上部の「よくある仕込みから選ぶ」の隣に**「ビジュアルから作る」**。押すと会場サイズに合うフルリグ＋ギャラリーが開く。
- ギャラリーはモーダルでなく**右パネルの1タブ**（「明かりの見本」）。上に絞り込みチップ（層／気分／色／動き）、下にサムネイル格子。クリックで**即適用**（元に戻すで取り消せる）。
- 適用後は既存の灯体パネルでそのまま微調整。3つのつまみ（色相／強さ／広がり）はギャラリー側で全層一括。
- 「似た明かり」: 同じ基本ルックの別バリエーションを横並び。

### G. 照明さんへの渡し方
フルリグは「願望の仕込み」であり実現可能性は担保しない。書き出しでは LX cue ごとに「使っている役割と灯数」（例: 前8・バトン1に6ムービング・cyc）を一文で出し、実機への割り当ては照明さんに委ねる。

## 依頼（順番にすべて。各項目に「案・根拠・捨てた案・本人に決めてもらう点」）
1. **フルリグ構成の批評**: 表Aは日本の劇場の実態として無理がないか（数・高さ・SS/床置きの扱い）。「最強」を「実在しそうな上限」に留めるべきか、あえて非現実でも「表現の自由度が最大」を優先すべきか。
2. **ロール方式 vs 灯体明示**: B案の縮退適用は本当に有効か。リゾルバの散らし方（ゾーンへ均等）で破綻するケース。ロールの粒度（b1/b2/b3を分けるべきか、`battens` 1つでよいか）。
3. **層の合成規則**: 2つのプリセットが同じロールを触ったときの解決（後勝ち／混ぜる／聞く）。層の粒度は8種で足りるか。「ルック」と「層プリセット」を同じ一覧に混ぜてよいか。
4. **「大量」を雑音にしない方法**: 手書き30＋軸で振る方式は妥当か。初回に何個あるべきか。非専門家（サーカスの人）に効く名前・タグの言葉は何か（照明用語を避ける）。実在の参考（照明卓のパレット、Capture/Vectorworks Visionのプリセット、Lightroomのプリセット、Figmaのスタイル）から取り入れるべき仕組み。
5. **サムネイル**: 実描画（3D正面図の縮小）で60灯×数十枚を描く負荷。事前計算・キャッシュ・遅延の設計。静止画を持たない判断は正しいか。
6. **LX cue モデルとの整合**: 「画面＝編集中キューの中身」モデルにプリセット適用を載せると何が起きるか（下書きに当てる／編集中キューに当てる／新規キューを切って当てる）。既存「光の動き」6プリセットとの関係（統合すべきか、別物か）。
7. **演者を参照するプリセット**: `performer{n}` や `aerial` を持たせるとき、シーンの演者データ（u,v,姿勢,高さ）への参照をどう持つか。シーンが変わって演者が消えた時の振る舞い。
8. **MVP**: 実装は後日だが、最初の2週間で何を作り何を削るか。フルリグ3種＋プリセット何個＋ギャラリーUIの最小形。
9. **本人に確認すべきこと**を最大3問（回答で設計が大きく変わるものだけ）。
