- **公開は必ず一時インデックス経由**（作業ツリーを一切触らない）:

```bash
cd "<repo>"
git fetch origin main -q
D=docs/light-rig-design-2026-09-11/prototype
export GIT_INDEX_FILE=$(mktemp /tmp/rigidx.XXXXXX) && rm -f "$GIT_INDEX_FILE"
git read-tree origin/main
for f in app.js index.html rig-engine.js; do
  H=$(git hash-object -w "$D/$f"); git update-index --cacheinfo 100644,"$H","$D/$f"
done
TREE=$(git write-tree); PARENT=$(git rev-parse origin/main)
SHA=$(git commit-tree "$TREE" -p "$PARENT" -m "メッセージ")
REF="refs/heads/main"; git push origin "${SHA}:${REF}"
```

- **複数ファイルを渡すときは zsh の配列で書く**（`FILES=("a" "b"); for f in "${FILES[@]}"`）。`FILES="a b"; for f in $FILES` は
  zsh が単語分割しないので1回しか回らず、`update-index` が全部失敗して**中身が空のコミット**を push してしまう
  （2026-09-14 ccfe400 で実際に起きた。`git write-tree` の結果が `origin/main^{tree}` と同じなら push しない、を必ず挟む）。
- **`"${SHA}:${REF}"` と必ず波括弧で書く。** Bashツールはzshなので `"$SHA:refs/..."` と書くと
  `:r` がzshの修飾子として食われ、`...efs/heads/main` になって push が失敗する（実際に踏んだ）。
- 変更したファイルだけ `update-index` する。差分確認は
  `git hash-object <file>` と `git rev-parse origin/main:<path>` の比較で行う。
- Pages は手動で起こしてポーリング:
  `gh api -X POST repos/aratama-ship-it/shosai-app/pages/builds` →
  `gh api repos/aratama-ship-it/shosai-app/pages/builds/latest --jq .status` が `built` になるまで。
- **JS/CSSを変えたら必ず `?v=` を上げる**（`index.html` の3本まとめて）:
  `V=$(date +%s); sed -i '' "s/\.js?v=[0-9]*\"/.js?v=$V\"/g" index.html`

## 4. いまの実装状態（すべて公開済み）

### ビュー
平面図（真上から）／下手を見る・上手を見る（タブ切替の側面図1枚）／正面図（平面・3D切替）。
照明デザインパネルは右列で上下に貫通（`.panel.insp{grid-column:3;grid-row:1/-1}`）。
**起動時の既定タブは「照明デザイン」。**

### 灯体
`mount.type` = `truss` / `front` / `side` / `floor` / `cyc`。
キューの持ち物: `on, level, levelTo, color, surface(floor|air|back), path,
beamDeg, beamDegTo, gobo, goboSpin, goboAngle, goboSoft, strobe`。

### ホリゾントライト（cyc）— 2026-09-13 に簡素化
- **配置パネルの `#cyc-tools` にある「床から（地明かり）」「上から」の2つのオンオフだけ**で置く／外す。
  クリック配置・ゴーストプレビューは廃止（`PLACE_TOOLS` から `cyc` を削除済み）。
- **位置は中央固定**（`mount.u` は読まない）。`dup`/`del` は cyc のみの選択時は無効。
- 長さ `mount.len`（幅の5〜100%）、届く高さ `mount.reachM`（0.5〜`E.CYC_REACH_MAX`=**10m**）。
- 描画は `drawCycWashes(ctx, P, dims, sink)` の**プリパス**で、
  `drawPiecesPlan` / `drawPiecesUp` より**先に**呼ぶ（演者の後ろに回すため）。
  通常の灯ループは `f.mount.type === "cyc"` で早期 return する。
- プリセット4種（小劇場21 / 中ホール37 / 演劇・素舞台27 / ダンス29）に床cycが1本ずつ入っている。

### 光の当たり方
- `spotEllipse(S,T,deg,surface)`: 円錐と面の交線を厳密に解いた楕円
  （`a = H cosθ sinθ / K`, `b = H sinθ / √K`, 中心ずれ `H tanφ sin²θ / K`, `K = cos²θ − sin²φ`）。
  真下以外は必ず歪む。2e-15 rad まで一致を確認済み。
- `spotFalloff`: 長軸に沿った `cosι / r²` を正規化（最も明るい点が1）。
- ゴボの筋: マスク中央帯の横走査 `goboProfile`（48段）を帯のグラデーションの段にする。
- **筋は `createConicGradient`（扇形）で灯体の位置から放射させる**。
  `createLinearGradient` だと等値線が平行になり筋が根元へ収束しない（2026-09-13 修正）。
  `createConicGradient` が無い環境と帯が線に潰れているときは平行版へ自動フォールバック。
- 暗転の穴は `drawBeam` の戻り値（`{r,toX,toY,landX,landY,halfW,ry,lying,asLine,noPool,pool}`）から
  同じ形を組み直す（点光源＋面光源に見えた不具合の対策）。

### LX cueは独立パネル・左列の上へ（2026-09-13 本人指定）
**パネルは3つ**になった: 左列の上＝**LX cue**、左列の下＝灯体、右＝照明デザイン。
LX cueは照明デザインの中ではなく別のパネル。

- 構造: `.figgrid` の1列目1行目に `.leftcol` を置き、中へ **灯体（左）と LX cue（右）を横並び**で入れた
  （縦積みだと両方が半分の高さになり一覧が2行しか見えなかった）。`.leftcol{flex-direction:row}`＋子は `flex:1 1 0`。
  **枠は広げない**（2026-09-13 本人指定「横幅をそれぞれ半分にしてコンパクトに収める」）。
  `syncFigureSizes` が `.leftcol` へ入れる幅は真下の側面図と同じ `sideW` のままで、
  `s` の式（`W + D*2`）も `--band` も元どおり。一度 `sideW*2` へ広げた版（`5e8c5eb`）は本人指摘で戻した。
  実測（1440×900）: 左枠323px＝側面図と一致・灯体158px・LX cue158px・高さ350pxで同じ・登録9本中**7本見える**・
  はみ出し0・平面図452px（広げた版より大きい）。
- 半分幅に合わせた詰め: LX cueの行は `[番号][名前][▶][✕]`（呼び出すは▶＋title）。番号の頭2つは `番号 [1]-[1]`。
  トグルの言葉は「シーンと連動」。`btn()` に第4引数 `title` を足した。
- 灯体一覧（2026-09-13 本人指定）: **常に縦1列**（`cols2` は付けない）。**見出しは縦積み**
  （`.grp{flex-direction:column}`——半分幅で「取り付け場所」と「6灯 まとめて選ぶ」を横に並べると
  どちらも細かく折り返して読めなかった）。**絞り込みの4つは1行に横並び**（`flex:1 1 0`・10.5px・nowrap）。
  実測（1440×900・パネル163px）: 一覧22行が1列・絞り込みは1行で文字の切れなし・はみ出し0。
- **「現在のシーンと連動」トグル**（`#lxlink` / `state.lxLink`、既定オン）。オンならいま編集しているシーンのLX cueを出し、
  シーンを2へ送れば勝手に2のLX cueへ切り替わる。オフにすると**その時点のシーンに固定**され（`state.lxScene`）、
  見るシーンを選ぶプルダウンが出る。
- 連動を切ってあるときにパネルから登録・呼び出しをすると、**そのシーンへ画面も移動する**（`lxGoto`）——
  何をしたのか見えないまま値だけ変わるのを避けるため。
- 縦の作り: 上（番号・登録ボタン）は固定、`.lxlist` だけ巻く。セクション／シーンは横1行（`.lxnums`）。
  連動中のシーン名は図の上の帯が出しているので繰り返さない。
  **落とし穴（縦積みだった頃の実害）**: `.panel` は `min-height:0` なので、縦に積んで `flex-shrink` を残すと
  見出しだけに潰れる。横並びにした今は `flex:1 1 0`（横方向）なので起きない。

### キュー編集モード（2026-09-13 本人要望で「登録」から作り替え）
**画面に出ている明かりは、つねにどれか1本のキューの中身**という考え方にした。

- `sc.lxEditing` に編集中のキューのidが入る。null＝どのキューにも入っていない下書き。
- **保存の操作はない。** `commit()` の先頭で `lxSyncEditing()` を呼び、編集中のキューへ
  `sc.cue` を書き戻す。つまみを動かし終えた時点（commit）で中身に入る。
- **一覧の行をクリック＝そのキューの編集に入る**（名前欄と✕の上は行の操作にしない）。
  入るときに `sc.cue` をそのキューの中身で置き換える。編集中の行は枠＋錆色で出す（`.lxrow.editing`）。
- **〈＋ 新規キュー LX cue n-n-n〉** はいまの明かりをそのまま次の番号のキューにして、そのまま編集を続ける。
  白紙ではなく**いまの明かりから**始める（前のキューからの続きを作ることが多いため）。
- **画面の表記は「LX cue」で統一**（2026-09-13 本人指定。旧「LX cue」「LX cue」は0件）。
  内部の名前（`#panel-lxq` / `#lxqbox` / データの `lxq`・`lxEditing`）は保存済みファイルとの互換のため**変えていない**。
- **図の上の中央に `#qnow`** を大きく出す（20px・真鍮色。2026-09-13 本人要望「もっと大きく」）。
  左右に **`#q-prev` / `#q-next`**（前後の LX cue へ移る矢印）。行き先が無ければ押せない。
  下書きのときは前が無効・次が1本目。`lxEnterCue(si, id)` を一覧の行クリックと共用し、
  `lxNeighbors()` が番号順の前後を返す。実測: 3本作って前へ2回で 1-1-1（強さ90）まで戻り、
  1本目では前が無効、次で 1-1-2（強さ50）へ。配置タブでは矢印ごと隠れる。
  編集中なら `LX cue 1-1-1` ＋名前（名前は14pxの明朝）、下書きなら「未登録の下書き」（15px・控えめ）。
  照明デザインの見出しに付けていた小さい `#qbadge` は**この表示に一本化してやめた**。
- **シーン送りは図の上の帯から LX cue パネルの上へ移設**した（同要望）。幅が狭いので名前は
  `1. オープニング` と短く出し、正式名は title に入れる。
- **場面はセクション／シーンの2層**（2026-09-13 本人要望）。LX cue パネルの上に同じ形の行を2本置く
  （`#sec-prev` `#sec-name` `#sec-next` ／ `#scene-prev` `#scene-name` `#scene-next`）。
  セクション番号は**シーンが持っている** `sc.lx.section` から数え上げる（`lxSections()`）ので、
  実在するセクション＝どれかのシーンが指している番号。セクションを送る＝そのセクションの**最初のシーン**へ移る。
  **シーン送りはいまのセクションの中だけを回る**（`lxStepScene`。以前は全シーンを回っていたので配線も差し替えた）。
  セクションが1つしかないときは送りボタンを無効にする。
- **セクション名・シーン名はここで変えない**（2026-09-13 本人指示）。場面は舞台スケッチ側のものを使う前提で、
  この試作は参照するだけ。番号（`sc.lx.section` / `no`）だけを持つ。
- **モーダルは外側を押すと閉じる**（`dialog()` に `pointerdown`/`pointerup` を付けた。Escでも閉じる）。
  中で押して外で離した場合は閉じない（文字を選んだ流れで消えないように）。
  確認ダイアログを外側で閉じても、ボタンの処理（削除など）は動かない＝「やめる」と同じ扱い（実測で確認）。
- **一覧の1行は高さ36px・字12.5px**（2026-09-13 本人要望「縦幅をちょっと大きくして見やすく」）。
  行の列は `auto minmax(0,1fr) auto` の**3列**——呼び出しを行クリックへ一本化したあとも4列のままで、
  空の列に幅を取られて名前欄が41pxまで痩せていた（実測して気付いた）。
  上の固定部分も詰めた（新規ボタンは `＋ 新規 1-1-7` と番号だけにして1行に収めた）。
  実測（1440×900・パネル158px）: 行36px・一覧の枠119px・同時に3本見える・はみ出し0。
  **縦は左列の高さで頭打ち**なので、行を高くするほど見える本数は減る。本数を優先するなら行を戻す。
- **LX cue はつまんで並び替えられる**（`lxReorder`）。掴めるのは**番号だけ**（行ごと掴めるようにすると
  名前欄の文字が選べなくなる）。落とすとその位置へ入り、**連番を1から振り直す**——番号は進行順そのものなので。
  実測: A,B,C,D の4本でDを先頭へ落とすと D,A,B,C になり番号は 1-1-1〜1-1-4 に付け直され、
  編集中だったDの編集はそのまま続く（中央の表示も `LX cue 1-1-1 D` へ追従）。
- **配置モードでは LX cue パネルを隠す**（`#panel-lxq.hidden`）。灯体パネルが左の枠いっぱい（1440で338px）に
  広がり、一覧も横2列へ戻る（`cols2` は `clientWidth >= 230` で切り替え）。照明デザインへ戻すと半分幅・1列に戻る。

  断面の形に意味がなく、三角が出ると別方向へ走っているように見える（本人「三角形が見えて違和感」）。
  光源のまぶしさと、舞台の手前端を通るあたりの滲み（75%の明るさ）だけで表す。
  帯は**平面図と側面図**が受け持つ（それぞれ横の開き・前後の進みが読める図）。
- **狙い点の赤い丸は「光の終わり（手前端の通過点）」に出す**（`houseHandleProj`）。
  以前は生の狙い点＝帯の倍くらい先にあって掴みにくかった。`hitHandle` に第4引数 `projFor(fid)` を足して
  **描く位置と掴む位置を同じ変換**にした（`secHandleProj`）。
  さらにドラッグ中は `houseAimFromCut()` で「通過点 → 狙い点」へ引き伸ばしてから渡す。これが無いと
  丸が指より鈍く動く。実測: 指を(30,-14)(-25,18)(0,25)動かすと丸も**同じだけ**動く
  （上限に当たる高さまで振ると、舞台高さ`H`のクランプで止まるのは仕様）。

### 客席向けの光は図ごとに描き分ける（2026-09-14 本人指摘で作り直し）
**図の性質がちがうので、同じ伸ばし方をしてはいけなかった。**
- **正面図（2D・3D）は奥行きを畳んだ図**。客席へ向かう光をそのまま先まで描くと、投影上は
  ただ下へ降りるので「舞台を斜めに降りて演者に当たっている」ように見えてしまう
  （真横から見た図では当たっていないのに、という本人指摘の矛盾）。
  → **舞台の手前端 `y = D` で切る**（`houseCutAtFront`）。先端にも滲みを置くので板のようには切れない。
  実測: 灯体 z=7.0m から客席6m先の 4.2m を狙うと、手前端での高さは **5.65m**（演者1.7mの遥か上）。
  正面図の演者の頭(1.8m)・胸(1.1m)・床の行はいずれも**光の画素0**、切った高さの行だけ131px光る。
- **側面図は奥行きが横軸**なので、そのまま客席側へ伸ばして枠の外へ抜けさせる（今までどおり正しい）。
- **平面図は真上から見る図**なので、客席へ向かう光は<b>横に開く帯</b>として見えるはず。
  `asLine` のままだと点線しか出ず「光のラインが見えない」と指摘された。→ **帯（三角）で描く**ようにして、
  客席帯の位置を通り越して枠の外まで伸ばす。実測: 舞台中ほど24px・手前85px・客席帯170px が光る。
- 逆光の影絵はそのまま。6灯の逆光＋床当て2灯では、体33／まわり83〜108 で写真と同じ見え方になる。

### 客席へ向けた光が途中で切れる（2026-09-13 修正）
`beamEnd` が客席向け（`surface:"house"`）のとき**狙い点をそのまま終点に返していた**ため、
正面図・側面図で光が宙で切れて見えていた（本人指摘・スクリーンショットあり）。
最初は世界座標で一定倍（`houseRay`）にしたが**まだ切れる**と指摘され、**画面の枠から必要な倍率を解く**
`houseFarPoint(S, T, P, cv)` に作り直した。平面の投影は一次なので
`P(S + m(T−S)) = P(S) + m(P(T)−P(S))` から枠を越える最小の m が出る（60pxの余白＋15%増し）。
遠近の3D図は一次でないので、その m から始めて外へ出るまで1.6倍ずつ試す（上限80倍）。
**必要な最小限だけ伸ばす**——伸ばすほど光の輪も太くなるため。3Dは `houseCapY` で先に `D*1.45` へ寄せてから。
実測: 正面図(2D)の枠の下端262px・3Dは下端91/右端119・側面図は下端167/左端136 の画素が光る。

### まぶしさ（丸い滲み）の大きさを選べる（2026-09-13 本人要望）
客席へ向けた光は「帯」と「光源から丸く広がる滲み」の2層でできている。後者の大きさを
**灯ごとの倍率 `light.glare`（0.2〜3.0・既定1）**で持つ（`glareMul()`）。4か所の `drawGlare` 呼び出しに掛ける。
つまみは〈当てる場所〉が「客席」のときだけ出る（「まぶしさ」）。
実測: 0.3→29,326px／1.0→35,960px／2.6→75,846px と明るい画素が単調に増える。

### 側面図だけ光が暗く見える理由（2026-09-14 調査・未修正）
`drawBeam` は `dim` のとき濃さを **0.32倍**にする。側面図の `dim` は
`!(mine || (air && isSel)) || (選択中で自分が非選択)` で、`mine` は
**「その灯がこの側（下手／上手）のSSであること」**。つまり**バトン吊りの灯は常に `dim=true`** になり、
正面図（`dim = 選択中で自分が非選択`）より薄く出る。側面図がSSを置くための図だった頃の名残。
実測（1灯・未選択）: バトン吊りは側面図で `dim:true`、SSの灯は `mine:true` で `dim:false`。
**直すなら**側面図の `dim` を他の図と同じ「選択中で自分が非選択」だけにする（本人判断待ち）。

### 逆光のとき演者を影絵で出す（2026-09-13 本人要望）
**作業灯を消したときだけ**、演者より<b>奥</b>にある灯が点いていれば、その演者を黒い影絵で描き直す
（`backlitPieces()` が対象を集め、`drawPiecesUp(..., {silhouette:Set})` で**作業灯の暗幕より後に**重ねる）。
光の上へあとから黒を置くので、体で光が遮られたように見える。影絵の回は影と名前を描かない。
- 判定は「点いている灯の光源 y ＜ 演者の y」だけの**近似**。どの灯が実際に当たっているかまでは見ない
  （本人了解「アイディア出しができる表現でOK」）。
- 実測: 奥のバトン（y=2.4）から客席へ向けた灯で演者（y=4.6〜5.8）は全員 33（真っ黒）、
  周りは43〜112。前明かり（y=14）だけにすると同じ演者が 255〜419 で**影絵にならない**。

### ゴボの回転角（2026-09-13 修正）
- `E.goboAngleAt` は**常に 0〜360 に畳んだ角**を返す。反時計回り（`goboSpin` が負）でも負の角は出ない。
- 帯の筋（`goboProfile`）は角を5°刻みに丸め、`{goboAngle: 丸めた角, goboSpin: 0}` で `goboMask` を作り直す。
  以前は負の角がこの再投入で `clamp(…, 0, 360)` に潰されて 0° 固定になり、
  **光だまりの模様は回るのに帯の筋だけ止まる**（時計回りは正常）という不具合が出ていた。
- 実測（正面図の帯領域・しきい値0）: 修正前は反時計回りで t=0/1.5s/3s の帯差分 **0画素**、
  修正後は 23,469画素が動き、同じ角になる時計回り（−27°＝333°）と**画素完全一致**。

## 5. 実際に踏んだ落とし穴（同じ穴を掘らないこと）

- **Safari は canvas の `ctx.filter` が既定で無効**。代入しても例外が出ず黙って無視される＝
  「Chromeでは効くが本人の環境だけ無反応」になる。ぼかしは `shadowBlur` で作ってある。
  描画系APIを足すときは着手前に Safari を名指しで互換確認する。
- **`RIG_ENGINE` は `Object.freeze` 済み**。監視のための monkey-patch は黙って失敗する
  （呼び出し回数0と誤報告した）。`app.js` 側に一時フックを置いて、公開前に消す。
- **変更直後の最初のフレームは古い絵を掴む**。実測前にフレームを1〜2回空読みして温める。
- **明るさ重心と幾何中心は別物**。減衰の検証は必ずアプリが使っている楕円中心で行う。
- **`evenodd` だと重なった開口が打ち消し合う**。マスクは `nonzero` で塗る。
- **`.pbox` は `display:grid`** なので、中身が広いとパネルごと広がる。`min-width:0` を当てる。
- **スクロールする親で `display:grid` の自動行を大量に積むと行高が0に潰れる**ことがある。
- **JS の `%` は符号を残す**。回す向きを負の速さで表す設計では、角度・位相を返す関数の側で
  `((a % 360) + 360) % 360` に畳む。下流の丸め・範囲制限に負値を渡すと、片方の向きだけ黙って壊れる。
  **正方向で動いた確認を両方向の確認と見なさない。** 検証は「同じ角になる時計回りと反時計回りの
  画素一致」のような対照条件で行う（今回はこれで修正前0画素／修正後一致を確認）。
- **公開処理の rebase で作業ツリーが一時的にベースへ戻り、同時編集中の変更が「消えた」ように見える**（2026-09-14 01:34 実害）。
  `git reflog` に 01:32 commit → 01:34 `rebase (start): checkout origin/main` → 01:35 finish → amend×3（5fc1473）が残っている。
  作者ホストはこのマシン自身（AratanoMac-mini.local）。**公開では rebase を使わず commit と push だけにする。**
  どの道具がその一括 publish を実行したかは未特定。対策: 変更は**アンカー方式の
  再適用スクリプト**として `patches/` に残し、公開直前に `git hash-object` で中身を再確認する。
  `git diff origin/main -- <path>` は**この試作には効かない**（ローカルで未追跡のため空になる）。
  `git show origin/main:<path> | diff - <file>` で見る。
- **平行か放射かの判定法**（今回使った決め手）: 光線の両縁から最小二乗で頂点を求め、
  **同じ角度範囲を2つの深さで走査して相関**を取る。放射なら深さによらず一致、
  平行なら深さ比で縮めたときだけ一致する。
  実測: 修正後 放射0.991/平行0.563、修正前 放射0.612/平行0.996。
  対照実験として `CanvasRenderingContext2D.prototype.createConicGradient` を実行時に
  消して旧挙動を再現し、両方を測って比べた。**片方の環境で動いたことは動作確認ではない。**
