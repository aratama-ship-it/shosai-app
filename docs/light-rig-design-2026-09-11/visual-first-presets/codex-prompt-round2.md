## 反論1: 「縮退適用を初版から外す」— 半分同意、半分反対
同意: 初版の適用対象はフルリグ3種だけでよい。任意rigへの割当アルゴリズムは後段。
反対: **プリセットの記述形式には初日から `requires`（必須／補助の配置グループと灯数）を持たせる**べき。理由は2つ。①既存8種の仕込みで作業中の人が「見本を試す」入口に来たとき、「このrigでは主題が成立しない」と3状態で言えるのは `requires` があるときだけ。②書き出しで照明さんに「この見本に最低限必要なもの」を渡せる（灯数でなく配置グループ単位）。実装は「フルリグ以外では見本タブに『この仕込みでは試せません（必要: 前明かり左右・バトン2本）』と出すだけ」で足りる。
→ これに反論があれば。無ければ `requires` の最小の書き方を決めてください。

## 反論2: 「層＝部分変更」— 同意。ただし呼び名と単位
同意: 初版は「全体の見本（置換・未使用灯は消灯）」＋「部分変更（明示した配置グループ×属性だけ後勝ち）」。取り外せる層は作らない。由来チップは表示のみ。
確認したい点: 部分変更の単位は**配置グループ**（例「背景だけ夕焼け」＝上下ホリゾントだけ）で固定してよいか。それとも「使い道」（顔／輪郭／床／背景／空間）で切るべきか。本人は非専門家なので「背景」「顔」「輪郭」の言葉のほうが伝わる、と私は考える。**内部は配置グループ、表示は使い道**の二重にするなら、その対応表を決めてほしい。

## 反論3: 「試し表示と採用を分ける」— 反対寄り。テンポと既存原則との衝突
本人の既存決定: 「取り消せる操作に確認を挟まない」（2026-09-11、プリセット適用は確認なしで一撃・toastの元に戻すで取消）。この原則に従うと、**カードのクリック＝即commit（Undo可）**が自然で、試し表示という中間状態は増やしたくない。
あなたが挙げたリスク（`lxSyncEditing` が commit で編集中キューへ書き戻す）は、即commitなら「編集中キューが変わる」のが本人の意図そのものなので問題にならない。問題になるのは「隣のカードも見比べたい」ときで、それは **Undo→別カード** で足りるのではないか。
ただし「新規キューにする」は別ボタンとして残す（既存の〈＋新規キュー〉がいまの明かりから始まるので、「見本を当てる→＋新規」の順でも成立する）。
→ 反論があれば。特に「一覧で連続クリックして見比べる」体験が Undo で本当に足りるか、あなたの見立てを。
