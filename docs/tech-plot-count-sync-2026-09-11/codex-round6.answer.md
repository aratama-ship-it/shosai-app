## 1. v0.1の優先順位

主語を「振付を作る」から、**完成済み振付を速く記録し、演者が自分の動きを予習する**へ変える。

- 動画を見ながら：音源を再生し、カウントをタップして現在配置を一括記録。短い区間をループし、次のカウントは前配置を複製して動いた人だけ直す。
- 紙メモから：`第3エイト・1／中央へ`のような行を先に作り、全員の配置を置く。未入力の演者を警告し、精密な経路は後回し。
- 既存配置から：配置を複製、複数選択、左右入替・名前交換・全体移動を一操作で行う。記録者の修正速度を最優先する。

予習画面は、対象演者の経路を太線・強色、他の演者を薄く表示し、「前／次のカウント」「自分の位置から舞台を見る視点」「カウント別メモ」「個人付箋」を中心にする。共有ライブ再生はv0.1から落としてよい。同じ部屋での事前学習なら、公開済みリビジョンを各自が再生・停止・反復できれば足りる。オンライン会議とリアルタイム同期は舞台スケッチへ委ねる。

## 2. Choreographic網羅の境界

「機能の成果」を網羅し、画面構成は舞台スケッチ流に変える。

- **置換**：3D・任意角度は客席ビュー／FPV、クラウド・フォルダ権限は既存の共有・招待リンク、会場の側面・裏は既存会場モデル、色選択はcast色。
- **単体で持つ**：音源アップロード・トリミング・波形、0.01秒遷移、直線／曲線／円弧／多点経路、動く大道具、セクション、メモ、検索・ライブラリ、オフライン編集と再接続、グループ編集、多言語。
- **持たない**：別の会議機能、DMX・I/O・安全計算、独自の認証・権限体系。衝突防止は自動移動ではなく、身体フットプリントと経路の重なりを警告し、意図的な交差は理由付きで解除する。奥行き未入力の衝突は「要確認」とする。

## 3. UI/UXの進め方

参照は、稽古で間隔を直す導線が明確な[Stage Write](https://www.stagewritesoftware.com/)、音源と形成変更を結び notation を増やさない[Stancz](https://stancz.com/en/about)、波形・クリップ・連続時間の扱いを見る[Ableton Live](https://www.ableton.com/en/manual/session-view/)がよい。

最初に実物で試す操作は、①動画の一部分から全員配置を記録、②複製配置の入替・差分修正、③演者ビューで自分だけを追い、次カウントとメモを使う、の三つ。iPadは小さい点、指の遮蔽、横画面の密度を避け、スマホは縦画面・片手のカウント送りを優先する。音源はオフライン保存とiOSの再生開始制約を先に検証する。

## 4. 最小入力形

```text
formation: {
 stage:{widthM,depthM},
 track:{assetId,trimStartSec,countBpm,firstCountSec},
 dancers:[{id,name,color}],
 frames:[{id,count,poses:{dancerId:{u,v,facing}},note}],
 heroCount
}
```

入力時は前フレームを引き継ぎ、差分だけ編集する。保存・取込時に全員の解決済み配置へ展開し、舞台スケッチの`scene.motion.keyframes`へ対応させる。
