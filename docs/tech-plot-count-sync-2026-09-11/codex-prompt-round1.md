# お題
Webアプリ「舞台スケッチ」(Stage Sketch)へ、後々「バンドの技術プロット」「照明・映像プロット」「カウント同期」を導入する計画を立てたい。

# 舞台スケッチの現状（事実）
- 核: 平面図と正面図が同一データ、客席の任意位置・3D一人称(FPV)で「同じ場面を別の会場・別の席から」見る。共有セッション（複数端末リアルタイム）、演者ビューア（スマホ閲覧）、正規化座標で会場を替えても配置が残る。PWA・オフライン・iPad対応。日英完備、仏・中ドラフト。
- 主用途は「演劇を含むサーカス」。売りは管理機能でなくビジュアル共有。安全検証（荷重・吊点）は作らない方針。
- 場面(scene)は「キュー」として扱い、転換は cueSeconds(0.2〜10秒)で補間再生（盆・せり・幕などの機構含む）。**タイムラインUIは本人が明確に不採用**（再提案しない）。
- 照明: 駒4種（吊り／SS横／前明かり／転がし）を平面図・正面図・3Dに置ける（灯体名・回路・DMXは持たない）。さらに場面ごとの「光の意図カード」（何を起こす／観客の視線／人・背景・空間の見せ分け／いつどう変わる: 契機= scene-start/action/line/music/time/manual、変化= fade/snap/crossfade/blackout、体感速度）。
- 音: 場面ごとに楽曲ファイル（最大24曲・IndexedDB）を割り当て、場面送りで再生継続／切替。カウントや小節の概念は無い。
- 映像/LED/プロジェクター: 無い。
- バックライン・マイク・楽器: 無い（小道具駒と人物駒はある）。
- 試作済み（製品未適用）: 台本PDFの行・語へキューを錨づけ（cueIdはproject共通正本・台本は任意・自動GOなし）、転換の担当交代（区間担当・準備条件・合図と準備の分離）。
- 書き出し: JSON、香盤表、小道具表、ピッチPDF。MCPサーバーあり（AI編集案を差分確認して適用）。

# 先行アプリの事実（一次情報で確認済み）
- StageBuilder Pro: ブラウザ3D/2D、250+機材（音響・照明・映像・ステージング・バックライン）、I/Oリスト自動生成、PDF/CSV、AI自動配置、リアルタイム共同編集、会場DB。Free／Pro $5／Elite $10／Lifetime $250。対象はツアーミュージシャン・音響。
- Drafty: 仕込み図ブラウザアプリ（照明・音響・映像・ラック・配線）。6レイヤー自動切替、PDF/DXF/CSV。個人 月8,800円・年88,000円、学割年27,500円。裏方屋ドットコムが日本語化。
- Vectorworks Spotlight: 照明プロットの自動採番・機材表・凡例、製造業者シンボル、GDTF/MVR、Braceworks（荷重）、Vision/Showcase プレビズ、Lightwright連携、各種レポート。プロ標準・高価。
- Choreographic: ダンスフォーメーション。3D表示、音楽同期（カウント）、ダンサー経路、0.01秒精度の遷移、リアルタイム共同編集、オフライン。月550円／年3,900円。iOS/iPadOS/macOS/visionOS。

# Claude(私)の案 — 「作らない・受け取る・薄く繋ぐ」
方針: 先行アプリを複製せず、舞台スケッチの核（見え方の共有）に沿う形だけ入れる。3層に分ける。
1. 意図層（既存の強みを横展開・小）: 「光の意図カード」と同型の「音の意図カード」「映像の意図カード」を場面単位で追加（何を聞かせる／どこに映す／観客の注意はどこへ／いつどう変わる）。
2. 演出配置層（中）: 技術仕様を持たない「見え方の駒」を追加。
   - 映像面（スクリーン／LED／プロジェクション面）: 大きさと位置だけ持つ面オブジェクト。任意席・FPVから「何が隠れるか／見切れるか」を見られる（既存の視点機能と直結）。
   - バックライン／マイク位置: ドラム・アンプ・キーボード・ボーカルマイクを「演者の立ち位置に関わる物」として置く。回路・機種・ケーブルは持たない。
3. 橋渡し層（大・将来枠）: プロットは他ツールで作る前提で、受け渡しだけ持つ。
   - 書き出し: 位置一覧CSV／簡易ステージプロットPDF（バンドが会場へ送る紙）。入力表(input list)は最小の表として書き出せる程度。
   - 読み込み: MVR（Vectorworks等が出す共通形式）から灯体位置だけを読み、既存の照明駒として表示（将来枠）。DXF読込は重いので保留。
4. カウント同期（タイムラインを作らずに）: 各場面に「音楽の錨」= 楽曲ID＋開始位置（秒 と 8カウント×拍 の併記）を持たせる。場面一覧に「3×8+1」のようなカウント表示を出し、再生中はカウントに達したら場面が自動送りされる（既存のキュー再生と楽曲再生の合流）。ダンサー個人のカウント別経路（Choreographic領域）は作らない。BPMは曲ごとに手入力（自動検出は将来）。
段階案: Phase0 方針の明文化（LP文言「プロットは作らない、受け取る／渡す」）→ Phase1 意図カード2種＋映像面駒 → Phase2 カウント錨＋自動送り → Phase3 バックライン駒＋CSV/PDF書き出し → Phase4 MVR読込（将来枠）。
