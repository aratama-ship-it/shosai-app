## 何を作るか（1行）

舞台スケッチの演者に**髪型（形＋髪色）と服装（トップス・ボトムスの色と丈）**を持たせ、
2D（正面図）・3D（一人称/自由カメラ）・印刷の描画で同じ見た目にする。

## 設計の前提（第一案の前の考察）

- **誰が何のために使うか**: 本人が場面スケッチ中に、役柄の見た目（衣装の初期イメージ）を
  試し、複数の演者を色以外でも見分けるため。ピッチ資料（Contours等）の説得力も上がる。
- **この機能の固有の核**: 舞台スケッチの演者は「実寸が読める抽象シルエット」という
  描画言語で統一されている（姿勢も用意したものから選ぶだけ・形は編集させない。
  stage-sketch.js 1182行のコメントが正本）。髪と服はこの言語を壊さずに拡張する。
  すなわち **服装＝体の色面の割り付け、髪型＝頭の輪郭への追加**として設計し、
  着せ替えアプリ風の写実プレビューや顔パーツ編集（目・口の形）はやらない。目は点2つのまま。
- **意図的に外すもの**: 質感（布のシワ・柄）、性別の作り分けを目的とした体型変更、
  アクセサリー、靴。体型は既存の heightCm と size のまま。

## 現状の仕組み（コードを読んで確認した事実）

- 2D描画は `drawPerformer`（5337行）→ `paintBody`（5149行）。体は駒の単色 `piece.color` 一色。
  手足＝`taperedChain`、胴＝`torsoOutline`、頭＝楕円、目＝点2つ。
  奥側の手足は `mixToward(color, 0.26)` で沈める。
- 3D描画は `stage-first-person.js` の `paintBody3d`（1341行）。2Dの透視投影版で、
  形の定数・関数は `window.SHOSAI_STAGE_BODY`（5328行）から借りる＝**形を二重に書かない**。
- **`taperedChain`（1773行）は全部を一本の path に入れて最後に一度だけ塗る**。
  関数のコメントに過去の実バグが2件記録されている:
  ①節ごとに塗ると半透明のとき重なりが濃く出る
  ②台形と関節丸の巻き方向を揃えないと nonzero で打ち消し合い、
  「手足が数珠つなぎの黒い丸」に見えた。
  → **手足を途中で切って2回塗る方式は、この罠をそのまま踏む。**
- **`torsoOutline`（1751行）が受け取る rings は「首リング＋胴リング」**（5020行で
  `NECK_RINGS` を作り、`TORSO_RINGS` と連結して渡す）。`NECK_RINGS` は肩の上端から
  頭の中まで8枚（1914行）。返り値は右側の点列＋左側の逆順＝**一本の閉じたポリゴン**。
  → **「胴＝トップス色」と素朴に書くと、首まで服の色で塗られる。**
- **`poseExtent`（1686行）は関節座標だけから外接を測る**（`wheel` だけ例外加算）。
  これは選択枠だけでなく **「演者の上端＝物が乗る高さ」**（4717行）にも使われ、
  支え判定と、許可リスト運用中の `tools/check-object-on-performer.mjs` の基準に効く。
  → **髪を poseExtent に入れると、確認済み27件の許可リスト運用が壊れうる。**
- `duplicateSelected`（16531行）は `{ ...piece }` の**浅いコピー**。
  オブジェクトのフィールドは複製元と共有される。
- 演者の身元は `project.cast[]`（3337行）が持つ: `{id, name, color, heightCm, note, locked}`。
  駒は `castId` で指し、名簿の色編集は全場面の駒へ写す（10470行）。登録なしの駒もある。
- `STASH_KEYS`（3189行）＝控えに残すキーの一覧。登録から引き直せない値だけを持つ方針。

## 設計判断（決定事項と理由）

### 1. 塗りは「肌で全身 → 服の範囲を上塗り」のレイヤー方式（★初版から変更）

初版の「手足の線を割合 t で切って2色で塗り分ける（slicedChain）」は採用しない。
`taperedChain` が単一パス＋nonzero で継ぎ目を消している構造と噛み合わず、
コメントに残る過去の実バグ（数珠つなぎの丸・重なりの濃さ）を踏み直すため。

代わりに、**同じジオメトリを2回通す**:

1. **下地**: 現行とまったく同じ手順で、体全体を `skin` 色で描く（`paintBody` の既存経路）。
2. **上塗り**: 服の範囲だけを、同じ関節・同じ半径列で作った図形として `top/bottom` 色で塗る。
   - 腕 → 肩から袖口までの**部分チェーン**を `taperedChain` で塗る
     （節の列を袖口で打ち切り、打ち切り点の半径は線形補間で作る）。
   - 脚 → 腰から裾までの部分チェーンを同様に塗る。
   - 胴 → `torsoOutline` を**リング範囲で切った部分外周**（`right[a..b] + left[a..b].reverse()`）
     を閉じたポリゴンとして塗る。首元の開き（襟）は開始リングの index で表す。

- **利点**: 下地は既存経路そのままなので `look: null` の互換が自明。上塗りは既存の
  `taperedChain` / `smoothClosedPath` をそのまま使え、新しい低レイヤー幾何関数を作らずに済む。
  境界に隙間が出ても下から肌色が出るだけで、黒い穴にはならない。
- **袖口・裾が丸くなる**のは `taperedChain` の関節丸に由来するが、腕・脚は円柱なので
  袖口が丸く見えるのは正しい近似。意図した仕様として明記する。
- 奥側の手足を沈める `mixToward(…, 0.26)` は下地・上塗りの両方へ同じように掛ける。
- **色はすべて不透明**（`piece.color` と同じ hex）。半透明を許すと重なりが濃く出るため、
  `look` の色は不透明限定にする。

### 2. 首は服で塗らない（★初版の穴）

胴の上塗りは `NECK_RINGS` の途中から始める。既定の開始位置は
**「首の付け根」（`NECK_RINGS` の s:0.28 のリング）**とし、それより上（実際に目に見える首）は
下地の肌色のまま残す。襟の種類（開き）を後から足すときは、この開始 index を種類ごとに持たせる。

### 3. 見た目データは「登録（cast）」が正本。駒側は3状態で上書き（★初版から変更）

- 名簿 `cast[]` に `look` を持たせる（下記のデータモデル）。髪や服は「その人の見た目」で、
  場面をまたいで同じであるべきなので、色と同じく登録側が正本。
- 駒側は **`lookMode`**（文字列）＋ `look`（任意）の2フィールドで持つ。
  初版の「`piece.look: null` なら単色」だと、**名簿に look がある人を
  この場面だけ単色に戻す**が表現できなかった（JSONに `undefined` が書けないため）。

| `piece.lookMode` | 意味 |
|---|---|
| `"cast"`（既定） | 名簿の `look` に従う。名簿に無ければ単色 |
| `"plain"` | この駒だけ単色（現行描画）に強制 |
| `"custom"` | `piece.look` を使う（場面ごとの衣装替え。今回はUIを作らず器だけ） |

- 描画時の解決 `resolveLook(piece, cast)` は上表のとおり。戻り値が null なら現行の単色経路。

### 4. `look` 未設定は「今の見た目」のまま＝互換の芯

- 名簿にも駒にも look が無ければ**現行の単色シルエット描画と完全に同じ経路**を通す。
  既存32ショー・テスト・許可リスト運用に影響を出さないため。
  新しい見た目は「登録で設定した人だけ」に付く。

### 5. 種類は POSES / PROP_SHAPES と同じ「登録制の一覧」で持つ

- `HAIR_STYLES`・`TOP_KINDS`・`BOTTOM_KINDS` をコード内の一覧（id＋日英ラベル＋形の定義）
  として持ち、保存JSONには **id文字列だけ**を入れる。
- **未知のidは「描画時だけ既定へ落とす」。保存値は壊さない**（★初版から変更）。
  複数マシン・複数エージェントが同じJSONを触る環境なので、新しい版で付けた種類を
  古い版で開いて保存したときに潰れると復元できない。
  正規化では `hair.style` の文字列をそのまま保持し、`hairStyleById(id)` が
  未知なら既定を返す形にする。

### 6. 髪は「頭ローカル座標の部品集合、前後2層」。ただし制約を明記（★初版に追記）

- 髪型1種は頭ローカル座標系（原点=頭の中心、軸=首→頭の向き、スケール=頭の描画スケール、
  左右=顔の向きの符号）で定義した楕円・パスの集合。各部品は `layer: "back" | "front"` を持つ。
  - back … 頭の楕円を塗る**直前**（後ろ髪・ポニーテール）
  - front … 頭の楕円と目を塗った**直後**（前髪・頭頂）
- **`layer` は描画順であり、顔の前後ではない**。顔の向き（`pose.face` と `facing`）から
  `faceSign` を作り、部品は `faceSign` を掛けた座標で描く。背中を向けたら前髪は
  頭の裏側へ回り、輪郭からはみ出す分だけが見える。**この近似の限界を仕様として明記する**:
  - ロング・ポニーテールは「頭に固定された記号」であり、**重力で垂れる表現はしない**。
    逆さ姿勢（トラピーズのぶら下がり）でも髪は頭に付いたまま上下逆になる。
  - 抽象シルエットの描画言語（姿勢を選ぶだけ・形は編集させない）と一貫させるための
    意図的な割り切り。物理的な揺れが必要になったら別途起票する。
- 共通の描き手 `paintHair(ctx, head, angle, scale, faceSign, styleId, color)` を
  stage-sketch.js に置き、`SHOSAI_STAGE_BODY` 経由で3Dへ貸す。
  2Dは `ux` 由来、3Dは `P.head.s` 由来のスケールを渡すだけ（頭が既にビルボード楕円なので
  髪も同じ近似でよい）。

### 7. 髪は poseExtent（当たり判定・上端）に入れない（★Claudeが追加で発見）

`poseExtent` の `top` は「演者の上に物が乗る高さ」の基準で、支え判定と
`tools/check-object-on-performer.mjs`（許可リスト27件で運用中）に効く。
髪を含めると全演者の上端が上がり、既存の判定結果が動く。
**髪は見た目だけの層とし、当たり判定・支え判定・上端の計算には一切入れない。**
姿勢タイルのプレビューだけは髪が切れないよう、**タイル側で余白を持つ**（extentは変えない）。

### 8. 小さく描かれるときは自動で省く

袖・裾の境界と髪は、小さく描かれるとノイズになる（ミニマップ、遠景、姿勢タイル）。
描画スケール（2D=`rig.ux`、3D=`P.head.s`）が閾値未満なら**単色シルエットへ落とす**。
閾値は既存の目の描画が使っている判定（`0.05 * ux > 3`、5224行）と同じ考え方で決める。

### 9. 名簿の色は「見分けの色」として残す

- `member.color` の役割（一覧のスウォッチ・選択・ミニマップ・FPVの人物チップ・
  単色描画時の体色）は変えない。
- `look` を新規作成するとき、**`top.color` の初期値を `member.color`** にする。
- 以後、名簿の色を変えても `top.color` は追従しない（服は服として選んだものだから）。
  ただしUI上で「名簿の色に合わせる」ボタンを1つ置き、手動で揃えられるようにする。
- **ミニマップ・FPVの人物チップ・香盤表・ピッチ用プロンプトには look を反映しない**
  （記号としての色分けが役割のため）。これを仕様として明記する。

### 10. 複製は深いコピーにする

`duplicateSelected`（16531行）は浅いコピーなので、`look` を持つ駒を複製すると
複製元と同じオブジェクトを共有する。`look`（と `hair`/`top`/`bottom`）は複製時に
新しいオブジェクトへ写す。

> **別件として報告**: 現行でも `route` と `beam` はオブジェクトで、同じく浅くコピーされている。
> 動線を引いた駒を複製して片方の動線を編集すると、もう片方も動く可能性がある。
> 本設計とは独立の既存の穴なので、別途検証・起票する。

### 11. 輪郭が変わる服は「衣の殻」＝リングを積んだ面として持つ（★第3版で新設）

スカート・ドレス・ロングコート・マントは、体の色を塗り分けるだけでは作れない。
サーカス・舞台の衣装ではこれらが中心的なので、**最初の器に含める**（本人判断）。

**設計の芯: 胴の作り方をそのまま流用する。** 胴は既に
「断面リング（`{halfX, rz}`）を軸に沿って積み、`ringAt` で画面へ落とし、
`torsoOutline` で外周をなぞる」という作り方をしている（buildRig 4996〜5037行）。
`ringAt` は 2D（5011行）と3D（stage-first-person.js 1274行）に同じ形で存在し、
どちらも `{o, wx, wy, dx, dy}` を返す。
**衣の殻は、このリング機構をもう一組使うだけで作れる**＝新しい幾何の仕組みを増やさない。

衣の殻1つの定義:

```jsonc
{
  "id": "skirt_a",
  "from": "hip",          // 起点 "hip"（腰の中点）| "shoulder"（肩の中点）
  "axis": "ankle",        // 軸の向き "ankle"（起点→両足首の中点）| "down"（常に真下）
  "rings": [              // 軸に沿った位置 t と、その断面の 幅 halfX ・厚み rz
    { "t": 0.00, "halfX": 0.085, "rz": 0.062 },   // 腰（TORSO_RINGS の腰と同値）
    { "t": 0.18, "halfX": 0.105, "rz": 0.072 },
    { "t": 0.50, "halfX": 0.150, "rz": 0.105 }    // 裾（膝の高さ）
  ],
  "layer": "over"         // "over"＝体の後に塗る（スカート）| "under"＝体の前（マントの後ろ身頃）
}
```

- **軸の取り方**（判断の芯）: `axis: "ankle"` は **起点→両足首の中点**。
  重力方向ではなく体に沿わせる。髪を頭に固定したのと同じ割り切りで一貫させる。
  この軸なら姿勢ごとに素直な絵になる:
  - 立つ・しゃがむ・ぶら下がる → 軸は下向き＝スカートは下へ
  - 座る・長座 → 軸は前方斜め下＝スカートが腿の上に乗って前へ流れる（実物に近い）
  - ポール旗（体が水平）→ 軸は横＝スカートも横へ。物理的には垂れるが、
    **体に固定された記号**として一貫させる（髪と同じ割り切り。仕様として明記）。
- **`t` の基準**: 起点から軸の先端までを 1 とした割合。腰→足首は身長の 0.48
  （hipMid y=0.52、ankleMid y=0.04）なので、膝が t=0.5、床が t≈1.08。
  丈を身長比の絶対値ではなく軸の割合で持つことで、座り姿勢でも丈が破綻しない。
- **wide / deep の作り直し**: 胴の `wide`/`deep` は胴の軸（肩→腰）に直交させて作られている
  （5002〜5007行）。衣の殻は軸が違うので、**同じ7行の手順を衣の軸に対してもう一度行う**。
  `pose.wide` を衣の軸へ投影し直し、外積で `deep` を得る。
- **外周は `torsoOutline` をそのまま使う**（リングの配列を渡すだけ）。
- **描画順**: `layer` で決める。`"over"`（スカート・前身頃）は体を全部塗ったあとに重ね、
  `"under"`（マントの後ろ身頃）は体より先に塗る。
  ただし `"over"` は腕まで隠してしまうので、**手前にある腕（z が衣の中心より手前）は
  衣のあとにもう一度塗る**。この再描画は `paintBody` の parts ソートの結果を使い回す。
- 1つの服が殻を複数持ってよい（例: ロングコート＝後ろ身頃 `under` ＋ 前身頃 `over`）。
  `TOP_KINDS` / `BOTTOM_KINDS` の各種類が `shells: []` を持ち、空なら色面だけの服。
- **殻も当たり判定・`poseExtent` には入れない**（判断7と同じ理由）。

これにより、スカート／ドレス／ロングコート／マント／チュチュ／ケープ／羽織りものが
**同じ1つの部品**で表せる。種類が増えてもリングの数値が変わるだけで、コードは増えない。

## データモデル（保存JSONに増える形）

```jsonc
// project.cast[] の各メンバー（piece.look も同形）
"look": {
  "skin":   "#d9b38c",                                  // 肌の色（不透明のみ）
  "hair":   { "style": "short",  "color": "#2a2320" },
  "top":    { "kind": "tshirt",  "color": "#a84b26", "sleeve": "short" },
  "bottom": { "kind": "skirt_a", "color": "#3a3f4a", "length": "knee" }
}

// scene.pieces[] の各駒
"lookMode": "cast",   // "cast" | "plain" | "custom"。既定 "cast"
"look": null          // lookMode === "custom" のときだけ意味を持つ
```

- `normalizeLook(raw)` を新設。色は `validColor`（不透明のみ）。
  **種類idと丈の文字列はそのまま保持**（描画時に一覧照合して既定へ落とす）。
  raw が無ければ null。
- **`length`（丈）は種類をまたぐ共通の段階値**で、腰→両足首の軸に対する割合を指す:
  `"mini"`=0.30 / `"knee"`=0.50 / `"midi"`=0.72 / `"ankle"`=1.00 / `"floor"`=1.08。
  ズボンでは色面の塗り終わり、スカートでは殻の裾。**同じ語彙で両方を表せる。**
  `sleeve`（袖丈）も同じ考え方で肩→手首の軸に対する割合
  （`"none"` / `"short"` / `"threequarter"` / `"long"`）。
- 種類の一覧側が持つもの（保存JSONには入らない）:
  `shells`（衣の殻の定義。空なら色面だけの服）、`collar`（胴の上塗り開始位置＝
  `NECK_RINGS` の s 値。既定 0.28）、丈の既定値。
  **殻の `rings` の `t` は「その服の中での割合」**（0=起点、1=裾）で持ち、
  実際にどこまで伸ばすかは `length` が決める。これによりミニもロングも同じ形の定義で表せる。
- 正規化は `normalizePiece`（2801行）と名簿正規化（3337行）の両方へ足す。
- `STASH_KEYS`（3189行）へ **`lookMode` と `look` を追加**する。
  登録駒は名簿から引き直せるが、`"plain"` / `"custom"` は登録から引き直せない値のため。

## 段階分け（それぞれ別の発注書にする）

| 段階 | 内容 | 出口 |
|---|---|---|
| **段階0 器** | `normalizeLook` / `resolveLook` / `lookMode` / STASH / 深いコピー／`paintBody`・`paintBody3d` の引数拡張（look を受け取るが**まだ何も描き分けない**）／`look` 未設定が現行と完全同一であることのテスト | 見た目は1ピクセルも変わらない。回帰0を確定させる |
| **段階1a 色面の服** | 肌の下地＋上塗り（腕・脚の部分チェーン、胴の部分外周、首を残す）＋2D/3D＋プロフィールUI＋小サイズ省略＋コントラスト警告 | Tシャツ・長袖・ズボン程度の最小セットで塗りの骨格を検証 |

- **段階0を独立させる理由**（第2版で追加・本人承認済み）: 服の実装は塗りの骨格に触るので、
  データ層の回帰と描画の回帰が同じ発注書に混ざると、不具合が出たとき切り分けられない。
  段階0は「見た目が変わらないこと」だけを出口にできるので、検証が明快になる。
- **1a と 1b を分ける理由**（第3版）: 本人の判断で衣の殻は「最初から」入れるが、
  色面の塗り替えと殻の追加は触る場所が違う（前者は既存の塗りの改造、後者は新しい部品の追加）。
  1本の発注書にすると、実機で絵が崩れたときに原因の切り分けができない。
  **順序として髪より前に置くので「最初から含める」の要求は満たす。**
