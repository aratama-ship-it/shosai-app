台本 / Q / 転換を統合する前の確認

workflow v1 を、
いまの保存経路へ入れてよいか。

本体のproject、台本キュー試作、MCP、Mac、共有セッションの読み書き経路を、未知のworkflow情報を失わないかという観点で読んだ監査です。製品コードと保存データは変更していません。

判定: 現時点では入れない。

browserの状態正規化が既知のproject fieldを再構成するため、未知の project.workflow を失います。全経路が同じfeature gateとround-trip試験を持つまで、workflowは companion file として扱います。

ここからの実装順

先にできること

fixtureからQ、台本位置、転換activityを読むだけの画面を作る。保存も既存projectへの書込みも行わない。

統合前に止めること

未対応のbrowser / MCP / Mac / sessionへworkflowを含むprojectを書き込ませない。たまたま未知keyが残る経路を互換性とは呼ばない。

  1. 全経路に同じfeature gateとround-trip testを用意する。
  2. project内へ統合するか、companion workflowを第一級保存単位にするかを一つに決める。
  3. PDF Blobをmetadataから分け、欠損してもQ・anchor・activity・reviewを残す。
  4. 古いprojectを自動変更せず、互換性のない入力は明示して新しい版として保存する。

確認した根拠と限界

確認したソース

  • stage-sketch.js: export v4、import、state normalizer、session bridge。
  • stage-session.js: bridgeのexport / apply。
  • mcp-server/src/stage-model.js: v3 validator。
  • mac-app/Sources/StageSketchProjectStore.swift: v3 project store。
  • stage-audio-store.js: binary assetの分離。
  • docs/script-cues-2026-09-09/script-cue-storage.js: 試作の端末内PDF保存。

まだ行っていないこと

  • workflowを混ぜて現行projectへ書込む試験。既存保存を危険にさらさないため行わない。
  • iPad、共同編集、外部公開済み環境、未作成のPDF asset store。
  • PDF package、端末間同期、GO送信、所要時間の自動推定。

Mac / MCPで未知keyが現状通過し得ても、意味・version・参照整合を検証しないため、workflowを安全に保存できる証拠にはなりません。
