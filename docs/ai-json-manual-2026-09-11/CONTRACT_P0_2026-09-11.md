## 1. 外枠（D1・D5）

```json
{ "kind": "shosai-stage-sketch", "version": 4, "venues": [], "project": { ... } }
```
- `version` は**数値**の 4（文字列 "4" は不可。会場同梱処理は `document.version === 4` の厳密比較。L701）
- `venues` は常に空配列。AIに会場データを書かせない（同梱会場はプレビュー前にライブラリへ保存され取り消せない。L18183）
- `mcpMeta` / `editSummary` / `appliedRevision` / `sectionsNested` は書かせない
- 新規ショーの下書き専用（D7）。既存ショーの修正・再生成は対象外

## 3. cast / sets

- cast要素: `id`（必須・ASCII `^[a-zA-Z0-9][a-zA-Z0-9._-]{0,95}$`・一意）、`name`（必須・1〜24字）、`color`（必須・`#rrggbb`）、`heightCm`（任意・120〜210）、`note`（任意）
- sets要素: `id`・`kind`・`name`・`color` 必須、`note` 任意。`kind:"light"` のときだけ `lightKind:"hang"` 必須（D5）
- **ブラウザは cast の色を駒へコピーしない**（normalizePiece L3681）。piece 側にも color を書く
- 同じ実体は場面をまたいで同じ登録ID。同一場面の別個体は別登録ID（同一場面で同じ castId を2回使わない）
- 未解決の castId/setId は読み込みを止めず文字列のまま残る（名前からの再接続なし）。検査器で必ず検出する

## 4. 生成をサポートする種類（D6）

| 区分 | piece.type = set.kind | 扱い |
|---|---|---|
| 演者 | performer（castId） | 常時可 |
| 什器・小物 | block, table, chair, bench, stool, wall, sphere, suitcase | 常時可 |
| 照明 | light（set.lightKind="hang" 固定） | beam は書かない＝真上・高さ6m・床へ照射に固定（normalizeBeam L3641） |
| 高リスク装置（注意付き） | trapeze, tissue, cyrwheel, pole | 各場面の note に「安全未確認」を明記。flown/wires は書かない（trapeze/tissue は自動で吊物扱い。FLOWN_ONLY L1771） |
| 対象外 | model, prop, diabolo, teeter, wire, trampoline, cane, car, seri, revolve, deck, curtain, pool | 種類を書かず、必要なら note で提案 |

- Codex は実装時に、上の各 kind が **PIECE_TYPES（L1366）と SET_KINDS（L1759）の両方に存在する**ことを確認し、無いものは表から外して報告する
- piece.type と参照先 set.kind は一致させる（ブラウザは一致検査をしない）
- 不明な type は performer に、不明な set.kind は block に化ける。AIに「不明な種類を既知へ黙って読み替える」指示をしない

## 5. scenes（平坦な配列・上限 60）

- section: `{ "kind":"section", "depth":0, "id", "title" }`。駒・beat・note を書かない
- scene: `{ "kind":"scene", "depth":1（sectionを使わない場合は0）, "id", "title", "note", "background"?, "beat"?, "lightingIntent"?, "pieces":[...] }`
- `note` は「行為／観客に見える規則／変化」を短く（PLAYBOOK流儀）。最大2000字
- `beat`: `{ "role": 短い役割, "energy": 1〜5の整数 }`。不正な energy は clamp ではなく null になる
- `lightingIntent`（任意）: `{ "objective", "audienceFocus", "mood" }` の文章のみ。横・前・床からの明かりの意図はここに書く（駒では表現しない）
- section の入れ子は `nestLooseSections`（L4346）がブラウザ側で処理する。Codex は「depth0 section → depth1 scene」の平坦配列が往復（読み込み→書き出し→再読み込み）で階層を保つことを確認し、保たない場合は保つ書き方へ変えて報告する

## 6. pieces（1場面 上限 80）

| キー | 必須 | 値 |
|---|---|---|
| id | 必須・一意 | ASCII |
| type | 必須 | 第4節の種類 |
| castId / setId | performer は castId、それ以外は setId | 登録に存在すること |
| u, v | 必須 | 0〜1（客席から見て u: 左0→右1、v: 奥0→前1）。null 禁止（Number(null)=0 で 0 に化ける。finite L3314） |
| color | 必須 | `#rrggbb` |
| facing | 任意 | 0〜359（0=客席、90=画像右、180=奥） |
| pose | 任意（performer のみ） | ブラウザの POSES 配列（L1757〜、実測46種。makePose は48回呼ばれるが trapeze_sit/trapeze_hang は配列外）から。MCP列挙の lie_back/lie_front/lie_side は存在しない（正: lie / supine / sidelie） |
| size | 任意 | 55〜180、既定100 |

- 書かせない: route, strokes, arrows, notes, photo, screenTexts, heldBy, holdSide, base, supportId, beam, glow, locked, stashed, 舞台機構の値
- 並び順: 同一場面内は 什器→演者 の順を推奨（支え判定は前方探索。現行コードで椅子・机等は除外済みだが順序は依然効く。supportUnder L6395）

## 7. 読み込みの実際（本文に書く「ユーザーの手順」）

- 読み込みを止めるのは JSON構文エラーと `project.scenes` が配列でない場合だけ（L18152〜18175）。**「開けた」≠「意図どおり」**
- PC: 差分プレビュー → 「別のショーとして開く」（#stage-import-as-new）が既定。現在のショーは壊れない
- スマホ閲覧: プレビューなしで即保存
- `scenes:[null]` 等は正規化中の例外になり整ったエラーが出ない → AIに null 要素を作らせない

## 9. 質問票（2026-09-11 追加・本人指示「足りない要素があれば聞いてくるように」）

- JSONの前に、結果を大きく変える未確定事項だけを**質問票1回**（最大6問）で聞く。細部は既定で埋め、指定済みは再質問しない。
- 形式は本人の判断シートと同型: `Qn 見出し／問い／推奨: X — 理由／A: B: C:`。回答は「Q1 A、Q2 保留、Q3 別案: …」。
- 保留＝推奨案を仮採用し、影響を受ける scene.note の先頭に「仮定: …」。別案は契約内へ寄せる。
- 質問票と JSON を同じ返答に混ぜない。「質問不要」「推奨で進めて」なら質問票を省く。
- 将来案（未着手）: 質問票を `shosai-ai-questions v1` のJSONでも出せるようにし、アプリ側で判断シートとして描画する。
