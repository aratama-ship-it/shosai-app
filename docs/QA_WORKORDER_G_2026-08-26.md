## 手順2. 「最新を取り直す」ボタン

- ゲストのセッション欄に **「最新を取り直す」** ボタンが出ているか（参加中のみ表示）。
- 押す → 画面がホストの最新状態になる。押しても切断表示のまま戻らないなら異常。

## 手順3. ホスト再起動からのゲスト自動復帰（Gの核心）

1. ホスト＝Macアプリでセッション中。ゲストが同じ舞台を見ている状態にする。
2. **ゲストのタブ／PWAを前面に出したまま**にする（後述の偽陰性条件）。
3. Macアプリを終了 → 再起動 → **「前回のセッションを再開」** を押す。
4. ゲスト画面がホストの舞台に戻るまでの秒数を計る。**ゲストは何も操作しない。**

### 合否の基準（コードから導いた実際のタイミング。ここが判断の肝）

- ping間隔25秒／pong待ち10秒 → **死んだ接続の検知に最大35秒**、その後3秒で再接続。
- したがって **40秒待って戻れば正常**。20秒で戻ることも、38秒かかることもある。
  **30秒で戻らないことをもって失敗と判定しないこと**（keepaliveが設計どおり働いた姿）。
- **60秒待っても戻らなければ失敗。** そのとき「最新を取り直す」で戻るなら、
  再接続の経路は生きていて自動検知だけが効いていない、という切り分けになる。

### 偽陰性（実は直っているのに失敗に見える）条件

- **ゲストのタブを裏に回した／別アプリに切り替えた／iPhone・iPadで画面を消した。**
  バックグラウンドのタイマーは間引かれ、iOSではタブごと止まるため、
  25秒のpingが飛ばず検知が遅れる。**必ず前面のまま待つこと。**
- ゲスト側が手順0をやっていない（古い版のまま）。
- ホストの「前回のセッションを再開」を押す前に計り始めた。

### 失敗したときに記録すること

- 何秒待ったか／「最新を取り直す」では戻るか
- ゲストの端末とブラウザ（PWAかタブか）
- ゲスト画面に「ホスト接続切れ」の帯が出たか、出たなら何秒後か
- ホスト側Macアプリのセッション表示（再開できたと出ているか）
