# メニュー「AI指示」— AI編集パネル 仕様書

作成: 2026-08-09 / 設計: Claude / 決定: 本人
関連: [`MAC_APP_DESIGN.md`](MAC_APP_DESIGN.md)、[`AI_EDITING_HANDOFF.md`](AI_EDITING_HANDOFF.md)

## この画面の考え方

**AIと会話する場所ではない。** 舞台の現場で、演出家は自分で装置を動かさない。
言って、返ってきたものを見て、採るか捨てるかを決める。この画面はそれを写す。

したがって次を**作らない**。

- 吹き出しの積み上げ（会話が育つと盤面が見えなくなる）
- ストリーミングで文字が打たれる演出（待ち時間が長く見えるだけ）
- 会話履歴の常駐（残すべきは指示ではなくショー）

**残す固有の核**: 変えたい対象がいま盤面に描かれている。だから返事はテキストだけで返さず、
**盤面の上に下書きとして重ねる**。紙の平面図に鉛筆で修正を書き込むのと同じ見え方にする。

## 置き場所

既存の左メニューに1項目足す。新しいUIパターンを作らない。

```
ショー / 出るもの / セット登録 / 照明 / 背景 / シーン / 選んだもの / 保存 / AI指示
```

- `<section class="stage-panel" data-panel="ask" data-title="AI指示">`、**保存の後ろ**
- `window.stageSketchBridge` が無い環境（ブラウザ・iPad）では、**section をDOMから取り除く**。
  空の項目を見せない
- 見た目は既存パネルに完全に揃える。新しい配色・角丸・影を持ち込まない

## データの流れ（穴を埋めた版）

MCPが編集できるのは `.stage-sketch-mcp/projects/` の下書き。画面のショーは `localStorage` にある。
そのままではAIが「いま見ているショー」を読めないため、**依頼のたびに現在のショーを書き出す**。

```
1. 本人が「AI指示」に指示を書く
2. アプリが現在のショーをMCP形式で projects/ へ書き出す（bridge.writeProject）
3. アプリが runAgent を呼ぶ。プロンプトで projectId を明示し、
   「stage_sketch_plan_edit までで止まる」ことを指示する
4. アプリが最新の計画を読む（bridge.latestPlan）
5. plan.diff[].pieces を使って盤面に下書きを重ねる。差分の日本語行もパネルに出す
6. 「採る」→ runAgent をもう一度呼び、planId を confirmed:true で適用させる
7. 適用で生まれた読み込み用JSONを、新しいショーとして棚へ入れる
```

**6でMCPのapplyを使い、適用処理をJS側へ複製しない。** 複製すると仕様が二重管理になり、
MCP側の検証・履歴・revision競合の保護が効かなくなる。

## 未指定値は既定値で埋める（本人決定: 2026-08-09）

AI経由でも、手動で「出るもの」を追加したときと同じく、登録した演者・セットはその場面の
舞台へ出す。名前・位置・姿勢・向き・大きさ・色などの情報が指示に無いことを理由に質問で
止めない。MCPが手動追加と同じ既定値で補い、必ず `operations` を1件以上作る。

線引きは次のとおり。

- **情報不足**: 既定値で埋めて `status: "proposed"` にする。
- **参照の取り違え**: 既存の演者・セットに同名候補が複数あり、誤ると既存配置を壊す場合だけ
  `status: "needs_clarification"` とし、`questions` で本人に聞く。
- 存在しない既存名を更新・削除・置換対象として指定した場合は、候補を推測せず入力エラーにする。

### 共通の既定値

- 自動名は `cast` と `sets` の両方を見て、重複しない最小番号にする。
  日本語は `演者1`、`演者2` のように詰め、英語は `Performer 1`、`Performer 2` のように空ける。
  セットも種類名を基に同じ規則を使う（例: `台1` / `Platform 1`）。
- 配色順は手動追加の `nextPieceColor` と同じ
  `#a84b26, #efe7d6, #77865f, #8b98a1, #d3ac59, #6d6657` の循環。
- 駒の `size` は100、`facing` は0。演者の `heightCm` は165、`pose` は `stand`。

### 演者の位置

その場面に既にいる `performer` の数を `count` とする。

```text
u = clamp(0.5 + ((count % 5) - 2) * 0.09, 0.06, 0.94)
v = clamp(0.6 + (count % 3) * 0.07, 0.05, 0.95)
```

色は `nextPieceColor(cast.length)`。

### セット・照明の位置と登録値

その場面に既にいる `performer` 以外（照明を含む）の数を `count` とする。

```text
u = clamp(0.5 + ((count % 5) - 2) * 0.11, 0.06, 0.94)
v = clamp(0.5 + (count % 3) * 0.09, 0.05, 0.95)
```

`kind` が未指定なら `block`。色は照明が `#d3ac59`、それ以外は
`nextPieceColor(sets.length + 2)`。`wires: 2`、`framed: false`、照明の種類は `hang`。
トラピーズとティシューは `flown: true`、それ以外は `false`。

寸法（m）は手動追加の種類別既定値をそのまま使う。

## ブリッジに足すもの

既存の `listEditExports` / `readExport` / `onEditAvailable` / `runAgent` に加えて:

```ts
// 現在のショーをMCPの下書きとして書き出す。既存があれば revision を上げて上書きする。
writeProject(document: object): Promise<{ projectId: string, revision: number }>

// projectId に紐づく最新の編集計画を返す。無ければ null。
latestPlan(projectId: string): Promise<object | null>

// 実行中のAIクライアントを停止する。実行が無ければ false。
stopAgent(): Promise<boolean>
```

`runAgent` は同時に1件だけ実行する。実行中に再度呼ばれた場合は、先の依頼を残したまま
後の呼び出しを `ok: false` で拒否する。停止時も `ok: false` とし、`output` に停止した旨を入れる。

**安全上の制約（既存と同じ）**

- 書き込み先は `.stage-sketch-mcp/projects/` 配下のみ。パス正規化後に範囲外なら拒否
- `writeProject` は舞台スケッチ version 3 の形でなければ拒否する
- JSから任意のファイルパスを渡せないよう、ファイル名は projectId から組み立てる

## パネルの3つの状態

### 1. 待機

- `<textarea>` 1つ。placeholder は `例: 3場面目の円座を、2場面目のものに入れ替えて`
- ボタン「頼む」。**⌘Enter / Ctrl+Enter でも実行**
- 空文字では実行しない

### 2. 実行中

- 表示は **経過秒数と「止める」だけ**。偽の進捗バーを出さない
  （何割終わったか本当に分からないため、分かるふりをしない）
- 文言: `考えています 12秒` — 秒は1秒ごとに更新
- textarea は読み取り専用にする（打ち直しによる取り違えを防ぐ）
- 「止める」でプロセスを終了し、待機へ戻る
- 失敗したら、返ってきたエラー文を**そのまま**出す。丸めない。失敗箇所だけを示す短い接頭辞
  （`ショーの書き出しに失敗しました:` / `AIの起動に失敗しました:` /
  `計画を読めませんでした:`）を前へ付ける

### 3. 下書きあり

- 差分の日本語行（`plan.diff[].lines`）を場面ごとに出す
- 盤面に下書きを重ねる（下記）
- ボタン「採る」「捨てる」。**Escでも捨てる**
- `plan.status === "needs_clarification"` のときは、`questions` を出し、
  **「採る」を出さない**（AIが候補を絞れていないため）
- `plan.warnings` があれば、「採る」の直前に安全の注記を1行出す。既存の安全文言と表現を揃える

## 盤面への重ね方

`render()` の最後、通常の駒を描いた後に下書き層を描く。**正面・平面の両方**に描く。

- **下書きの駒は、通常の駒と同じ描画関数を使い、`globalAlpha` を下げて描く**（0.45）。
  座標変換を書き直さない。書き直すと両ビューでずれる
- 連結線: 現在位置から下書き位置へ、`#9c823f`（`--brass`）の1px破線 `[3,3]`

| change | 見せ方 |
| --- | --- |
| `move` / `replace` / `update` | 現在の駒はそのまま。下書きを薄く描き、破線でつなぐ |
| `add` | 下書きだけを薄く描く。連結線なし |
| `remove` | 現在の駒の上に薄い斜線を重ねる（消える予定を示す） |

- 下書きの駒は**選択できない**（クリックが通らない）
- 下書きが出ている間、盤面の隅に小さく `下書き — まだ保存していません`
- `pieces` が空（場面名・メモだけの変更）なら、盤面には何も重ねない。パネルの文だけで足りる

## 初回の確認

この欄の指示は、作業フォルダのファイルを書き換えられる権限で動く。
**初回の実行前に一度だけ**確認を出し、了解を `localStorage` に記録する。毎回出さない
（毎回出すと読まなくなり、警告として機能しなくなる）。

文言:

> この欄の指示は、AIが作業フォルダのファイルを読み書きできる状態で動きます。
> ショーは承認するまで変わりませんが、指示の内容には注意してください。

## 「採る」の後

- 新しいショーとして棚へ入れる。**元のショーは必ず残る**（本人決定）
- 保存後、`announce` で「新しいショーとして保存しました」と伝える
- 段階Bの読み込み確認モーダルは**出さない**。パネル内で既に差分を見て承認しているため、
  二重確認になる

## やらないこと

- 会話の継続（前の指示を踏まえた追加指示）。まず1往復を完成させる
- 履歴の閲覧UI
- ブラウザ版での表示
- AIによる自動適用（`confirmed` なしの適用経路を作らない）
