## 前提（出典つき）

- 配るのは **舞台スケッチ単独版 `stage.html`**。書斎（`index.html`）は身内用で配らない
  （[P1-6_feature-reachability-table_2026-08-23.md](P1-6_feature-reachability-table_2026-08-23.md) の「二つの製品の区別」）。
- リリース形態は **β版・限られた相手のみ** と本人確定
  （[RELEASE_DECISION_2026-08-26.md](RELEASE_DECISION_2026-08-26.md) 末尾の回答表）。
- 入口は `https://shosai-app.juggler-arata.workers.dev/stage.html`。
  テスターごとに **名前＋パスワード**（`GUEST_ACCOUNTS`、発注書J）でログイン。
- 端末差は**欠落ではなく確定仕様**：iPadに舞台機構・3Dカメラは足さない、楽曲はPC版のみ、
  スマホは閲覧機モード（メモリ `ipad-missing-features-are-intentional` ほか）。

## マニュアルの狙い（design-policy.md の5項目に沿った整理）

1. **誰が・どの場面で**: 招かれたテスターが、自宅や稽古場で自分の演目を1シーン描いてみる。
   または本人のセッションにゲスト参加する。
2. **どんな気分に**: 「説明書を読まされた」ではなく「舞台の道具を渡された」。
   読み終える頃には1シーン描けている構成にする。
3. **固有の核**: 舞台の語彙で書く（上手・下手、転換、盆、袖、板付き）。
   汎用アプリマニュアルの言い回し（「〜機能をタップ」）に寄せない。
4. **踏襲と外し**: 踏襲＝冒頭クイックスタート・末尾Q&A。
   外す＝全機能辞書を先頭に置く構成（リファレンスは後半へ）。
5. **機能条件**: 3端末で読める／βの更新に追従しやすい形式／既知の制限を正直に書く。

## 構成案（10章）

前半＝手を動かす順、後半＝引く順。「読む→試す→困ったら戻る」の二段構え。

| 章 | 内容 | 狙い |
|---|---|---|
| 0 | 表紙・はじめに | β版であること・連絡先を最初に。1/3ページ |
| 1 | 舞台スケッチとは | 「舞台の場面を、正面と真上から描く道具」。3行＋図1枚 |
| 2 | 入り口 | URL・ログイン・**端末ごとの推奨の開き方**（iPadはホーム画面追加の手順を写真つきで） |
| 3 | まず1シーン描く | 10分チュートリアル。ショー作成→劇場を選ぶ→演者を置く→動きの矢印→保存確認まで一本道 |
| 4 | 画面の地図 | 正面/平面/両方、パネルの並び。スクリーンショット1枚に引き出し線 |
| 5 | 機能ガイド | パネル別リファレンス（上のリスト順）。各機能=見出し＋2〜4行＋画像。読み物にしない |
| 6 | 共有セッション | 招かれたときの入り方・「操作中」バナーの意味・切れたときの復帰（最新を取り直す） |
| 7 | 端末による違い | 上の表の読者向け版。**「欠落ではなく設計」を明記**し、問い合わせを減らす |
| 8 | データはあなたの端末の中 | 保存の性質（ブラウザ内保存）・ブラウザのデータ削除で消えること・書き出しでの控えの取り方 |
| 9 | 困ったとき Q&A | ログインできない／オフラインで開かない／音楽が見当たらない（=PC専用）／読込で戻す 等 |
| 10 | β版のお願い | 既知の制限・報告のしかた（**連絡経路が決まり次第記入**）・報告テンプレート（端末・画面・再現手順） |

- 8章は独立させる。テスターのデータ消失は信頼を最も損なう事故で、
  localStorage逼迫（P1-12）がリリース後送りである以上、控え（書き出し）の習慣づけが保険になる。
- チュートリアル（3章）はPC前提で書き、iPad差分は欄外注記にする。二本立てにしない。

## アプリ内「使い方検索」（2026-08-27 本人要望で追加）

「アプリ内にも使い方検索みたいなものを入れて、見られるようにしたい」との要望。
マニュアルと検索結果の食い違い（二重管理）を避けるため、次の一元管理構成を正本とする。

- **本文は構造化データ1本**（`manual-content.js` 想定）。項目ごとに
  `id / 章 / 見出し / 本文HTML / キーワード（言い換え語）` を持つ。
- **`manual.html`** はこのデータを章順に並べて描画する読み物（印刷CSS→PDF書き出しもここから）。
- **アプリ内検索**は同じデータを検索窓で引く軽いオーバーレイ。結果は短い答え＋
  「くわしくはマニュアルの該当章へ」リンク（`manual.html#anchor`）。
- **検索の質はキーワード欄で決まる。** テスターは正式名称で引かない。
  「音が出ない→音楽はPC専用」「消えた→保存・書き出し」「回る→盆」のような
  日常語・症状語の言い換えを各項目に持たせる。
- 実装の分担: 本文データと `manual.html` はClaudeが書く。アプリ内オーバーレイ
  （`stage.html` 側の変更）は仕様確定後にCodexへ発注（別紙発注書。キャッシュ版上げ・
  配信許可リスト・回帰テストを含めること）。**アプリ本体の変更は本人承認後に着手。**
