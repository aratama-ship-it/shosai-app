停止・シークと転換の同期

タイムラインの位置から、その瞬間の移動中の姿を求める。

GitHub版へ公開済み。Cloudflareベータ版への操作は行っていません。

GitHub版を開く 検証記録アプリ修正 1f7e99a

今回の変更

  1. A05・P1：停止後も転換が進む。転換専用の実時間アニメーションをタイムラインから起動せず、再生位置で補間。停止した位置を保ち、再開時もそこから動く。
  2. A08・P1：途中へシークしても移動中の姿にならない。前後・繰り返しのシーク、A/Bループでも絶対位置から再評価。通常シーンは既存の動線・照明フェード・機構の補間を使う。
  3. A06・P1：通常モードの転換時間が100ミリ秒になる。未指定の値を0秒として扱っていた分岐を修正。シーンの転換時間、空欄なら全体のアニメ時間を使う。
  4. ミュージックシンクの再生時計の競合を抑止。タイムラインでは通常モードのフォーメーション再生ループを止め、音源の有無にかかわらず既存の先行・早着・曲線・向きの評価関数を使う。

保存形式・音源の割当ID・通常モードのパネル構成は変更していません。JS参照は472／45、Service Workerキャッシュは467です。

残る課題

この公開で監査全体の完了とはしません。修正対象は転換の時計とシークです。以下は引き続き切り分けが必要です。

  • A07：選択シーンと転換時間の所有。通常シーンの転換では、編集対象の選択が転換開始時に次シーンへ移る挙動が残る。「完了時に次へ入る」基準との統一は未完了。cueSeconds、rehearsal、formationの時間設定の統一も未着手。
  • A18：フォーメーションと本体のデータ所有。タイムライン内の二重再生ループは抑止したが、編集・再反映で持つ座標の二重管理は残る。
  • 連続回転する盆や長い公演の性能。今回検証したのは転換の位置補間。保持中の連続回転・乗っている演者の時計、長時間・大人数の負荷は未検証。
  • 複数楽曲・共有セッション。曲をまたぐ連続再生、キューの曲への所属、参加者側での再生位置の同期は今回の対象外。
  • 公開ページでの音源準備待ち。再読込後、自動で音源準備完了になることだけを待つ試験が2回停止した。再生ボタンを押す利用フローでは成功。自動準備が止まった根本原因は未確定であり、今回の修正済み事項には含めない。
  • ブラウザ・更新。実機の音声出力、Safari音源保存、旧タブと新Service Workerの更新中の全経路は未検証。旧ブリッジ向け経路はシーン切替の互換維持であり、新しい補間を保証しない。

次に進める順序

  1. シーン選択の時点と、転換時間の正本を決める。
  2. セクション・曲・シーン・キューの所有と複数楽曲の切替を整理する。
  3. ミュージックシンクとの読み書き往復、未知フィールドと音源の持ち運びを保護する。
  4. Safari実機、PWA更新、共有セッションで一本の操作フローを確認する。
