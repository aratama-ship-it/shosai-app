# 発注書：舞台機構（動く舞台システム）を表現できるようにする 2026-08-19

Claudeが仕様を決め、Codexが実装し、Claudeが検証する。この文書だけを読んで着手できるように書く。

## 背景

`shosai-app/` は依存なしの静的Webアプリ。舞台スケッチの本体は `stage-sketch.js`。
2026-08-18にセットビルダー（プリミティブを組んで保存）と3Dカメラが入り（commit c999c83）、
その次段階として本人が起票したのが本件。

本人（元サーカスアーティスト・ショー制作者）の要望：
> 既存のショーで実際に使われている舞台システムを再現したい。前幕、シルク・ドゥ・ソレイユ KA の
> 可動デッキ、O の可動プール床のような大がかりな機構。

いまのセットは**静止した箱の集合**しか持てず、時間軸で動く機構（迫り・盆・可動床・幕の開閉・
傾斜デッキ）を表現できない。

## 決定事項（2026-08-19・本人が選択）

1. **汎用の機構部品を先に作り、その上に実在ショー相当のプリセットを載せる**
   （実在ショーを個別実装しない。自分のショー用に新しい機構も組めるようにする）
2. **時間軸は段階1＝状態値のみ**。駒に「傾斜30度」「せり高さ2.4m」「幕70%開」といった
   状態を持たせ、**場面ごとに値を変える**。動きの再生（時間キー・アニメーション）は今回入れない。
3. **前幕・劇場側の要素を含める**（前幕・中割り幕・振り落とし・袖幕・ホリゾント）

## 事実確認とハルシネーション対策（重要）

KAのSand Cliff Deck、Oのプールリフトは、**公表されている正確な寸法・可動角・昇降ストロークの
一次情報が薄い**。したがって：

- **プリセットの寸法を「実在の公式値」として書かない。**
- プリセットは `sourceNote`（根拠メモ）と `confidence`（`"unverified"` 既定）を持つ。
- 画面上でプリセット由来の寸法には「**推定値・要確認**」のバッジを出し、本人がその場で直せるようにする。
- プリセット名に実在の作品名をそのまま使わない。「**傾斜する大型デッキ（KA風・推定）**」のように、
  型を表す名前＋「風・推定」とする。
- Codexは**寸法を自分で調べて埋めない**。この発注書に書いた数値だけを使う。
  ここの数値は「よくある劇場設備の一般的な値」として置いた出発点であり、実在ショーの値ではない。

## 既存の仕組み（ここに乗せる。作り直さない）

### 装置の実体と、場面ごとの駒

- `state.project.sets[]` … **ショー単位の装置名簿**。`{ id, kind, name, ... }`。
  ここに1件登録すれば、**場面をまたいで同一の装置**として扱える（identityは既にある）。
- 各場面 `scene.pieces[]` … その場面に置かれた駒。`piece.setId` で名簿を指す（`pieceSet(piece)`）。
- **駒は場面ごとに別オブジェクト**なので、場面ごとに違う値を持たせられる。

### 状態値の前例＝せり

`seri`（せり）は既に **`piece.seriH`（せり上がり高さ）を駒ごとに持ち**、
「選んだもの」パネルにスライダーが出て、`pieceParts()` がその値から立体を作っている。
**新しい機構の状態値は、すべてこの `seriH` と同じ流儀で足すこと。**
新しい入れ物（`piece.mech = {...}` のようなオブジェクト）は**作らない**。既存データの移行が要らない形にする。

### 描画

- `pieceParts(piece)` … 駒を `{ ox, oz, w, d, h, lift, tint, rotY? }` の**箱の配列**で返す
- `drawSolid()` → `paintBox()` … 2Dの正面図・平面図。`piece.facing`（度）で回転済み
- `stage-first-person.js` の `drawPiece()` / `drawBox()` … 3D一人称・自由カメラ
- `stage-set-model.js` … 組んだセットを箱の配列へ展開する（同じ配列を2Dと3Dが使う＝形を二重に書かない）

**新しい機構も必ず「箱の配列」へ落とすこと。** 2Dと3Dで別々に形を書かない。

## 実装する機構（汎用部品）

`PIECE_TYPES` / `SET_KINDS` / `SET_KIND_ORDER` / `PIECE_METERS` / `DIM_LABELS` へ追加する。
（`stage-sketch.js` 冒頭のコメントどおり、**足す場所は全部足すこと**。落とすと「演者」に落ちる。）

### 1. `revolve`（盆・回り舞台）

- 寸法: `dia`（直径。既定12m、範囲2〜30m）、`h`（せり出す厚み。既定0.15m）
- 状態値: **`piece.spin`**（回転角。度。-180〜180、既定0、刻み1）
- 形: 直径 dia・厚み h の円盤（`stage-set-model.js` の cylinder と同じく、45度ずらした2つの箱で近似）
- **盆の上の駒を一緒に回す（本件の要）**:
  - 新しい関数 `effectivePlacement(piece, scene)` を作る。
    盆の円の内側（中心からの水平距離 ≦ dia/2）にある**他の駒**は、盆の中心まわりに `spin` だけ
    回した位置と、`facing + spin` の向きを返す。盆自身と、床に付いていない吊物（`FLOWN_ONLY`）は対象外。
  - **2Dの描画・3Dの描画・一人称の視点位置・動線矢印の始点終点が、すべてこの関数を通ること。**
    一箇所でも素の `piece.x/y` を使うと、盆を回したときに図がずれる。
  - 盆が二重（内盆・外盆）になる場合は、**盆を2つ置いて重ねる**ことで表現する。
    その場合、内側の盆に乗った駒は内盆にだけ従う（**最も小さい盆＝最も内側の盆にだけ従う**）。
    盆自身も、より大きい盆の上にあれば一緒に回る。

### 2. `deck`（可動デッキ・傾斜デッキ）

- 寸法: `w`（既定12m）、`d`（既定9m）、`h`（デッキの厚み。既定0.4m）
- 状態値: **`piece.tilt`**（傾斜角。度。-60〜60、既定0、刻み0.5。正で客席側が下がる）
  **`piece.deckH`**（床からの高さ。m。-4〜8、既定0、刻み0.01）
- 形: 厚み h の板を、左右軸（客席から見て横向きの軸）まわりに `tilt` 傾け、`deckH` だけ上げる。
  箱の配列で近似するので、**奥行き方向を8枚に刻んだ階段状の箱**として出す
  （1枚ずつ `lift` を変える。`stage-set-model.js` の `ramp` と同じ考え方）。
- **デッキの上の駒は追従させない**（今回の範囲外）。
  代わりに、傾いたデッキと重なる位置に床置きの駒があるとき、
  「選んだもの」パネルに **「デッキの上の駒は自動では傾きません」** と一行出す。嘘の図を出さないため。

### 3. `curtain`（幕）

- 種別 `curtainKind`: `"front"`（前幕・引き割り）／`"traveler"`（中割り幕）／
  `"drop"`（振り落とし・上下する幕）／`"leg"`（袖幕）／`"cyc"`（ホリゾント幕）
- 寸法: `w`（既定は劇場の間口いっぱい。プリセットで与える）、`h`（既定8m）、`lift`（吊り位置）
- 状態値: **`piece.open`**（開き。0〜100%。既定0＝閉じている、刻み1）
  - `front` / `traveler` / `leg`: 左右へ引き分ける。開き100%で左右の端へ寄る
    （残った布は端に**寄せ集まった厚み**として幅 w×0.08 の箱で描く。消さない。実際に袖に布は残る）
  - `drop` / `cyc`: 上へ上がる。開き100%で `lift + h` の位置まで巻き上がる
- 形: 幅 w・厚み0.12m・高さ h の薄い板。開きに応じて左右2枚に割る（`front`/`traveler`/`leg`）。
- **平面図では線として出す**（幕は平面図で見たときの位置が重要なので、閉じている範囲を太線で描く）。
- 幕は視界（一人称）でも**見えなくならないこと**。閉じた前幕の後ろに立てば、幕が視界を塞ぐのが正しい。

### 4. `pool`（水面・可動プール床）

- 寸法: `w`（既定14m）、`d`（既定10m）
- 状態値: **`piece.water`**（水位。m。0〜3、既定0.9、刻み0.01）
  **`piece.poolH`**（プール床の高さ。m。-4〜0、既定-3、刻み0.01。0で水面と同じ＝乾いた床）
- 形: 水面＝半透明の板（`tint` を低くして描く）。プール床＝その下の板。
  **床が水面より上がると水は無くなる**（`poolH >= 0` のとき水面を描かない）。
  これが「乾いた舞台と水面が入れ替わる」の表現。

### 5. `seri`（既存）の拡張

- `piece.seriH` の範囲を **0〜4 → -3〜4** に広げる（沈む＝床下へ落とせるようにする）。
- 負のときは平面図で**破線の輪郭**（床下にある印）にし、正面図では床線より下に描く。
- 既存データは値がそのまま通るので移行不要。

## プリセット（機構の組み合わせ）

`stage-set-builder.js` のライブラリと同じく **端末共通** で持つ。
新しい localStorage キー `shosai-stage-rigs-v1`。
「舞台機構」パネルに**既製プリセット5件**を最初から出す（ライブラリが空でも出る＝読み取り専用の内蔵）。

内蔵プリセットは以下5件。**すべて `confidence: "unverified"`、`sourceNote` に「一般的な劇場設備の
目安から置いた出発点。実在ショーの公表値ではない」と書く。**

1. **前幕ひとそろい**（curtain front 幅18m×高9m ＋ leg 左右2枚 ＋ cyc 奥）
2. **回り舞台（二重盆）**（revolve 直径16m ＋ revolve 直径9m を同心に）
3. **傾斜する大型デッキ（KA風・推定）**（deck 幅16m×奥12m×厚0.6m、tilt既定0、deckH既定0）
4. **水の舞台（O風・推定）**（pool 幅16m×奥12m、poolH -3m、water 1.0m ＋ seri 2枚）
5. **迫り3基（オケピ前・中央・奥）**（seri 幅3m×奥2m を3つ）

プリセットを舞台へ出すと、**含まれる装置がすべて `project.sets` へ登録され、いまの場面へ配置される**。
出したあとは1つずつ自由に動かせる（＝プリセットは「置き方の雛形」であって、束ねた1個の駒ではない）。

## 画面（UI）

1. ツールバーの「舞台セット」の並びに **「舞台機構」** を足す。
   押すと機構の一覧（上の4種＋せり）とプリセット5件が出る。
2. 「選んだもの」パネルに、機構の状態値スライダーを出す（`seriH` のスライダーと同じ作り）。
   - 盆 → 「回転角」／デッキ → 「傾斜角」「高さ」／幕 → 「開き」／プール → 「水位」「床の高さ」
   - **値の横に、実寸のテキストを出す**（「2.40m」「30度」「70%開」）。
3. **場面をまたいだ差分の表示**: 機構を選んでいるとき、パネルに
   「**前の場面: 高さ0.00m → この場面: 2.40m**」の一行を出す。
   段階1では動きを再生しないので、**この一行が「動き」を読む唯一の手がかり**になる。ここは省かない。
4. プリセット由来の寸法には「推定値・要確認」のバッジ。本人が寸法を直したらバッジを消す。

## 作法（このリポジトリの決まり）

- `index.html` が正本。`stage.html` は生成物なので、**触ったら `python3 build_stage.py` を実行**する。
- JSを変えたら **`index.html` の `?v=` を上げ、`stage-sw.js` の `CACHE_NAME` も上げる**
  （現在 `stage-sw.js` は `stage-sketch-pwa-v74`）。上げないとPWAが古いJSを配り続ける。
- 日本語・英語の両方に対応する。文言は `stage-i18n.js` へ（`tm("setKind", ...)` 等の既存経路）。
- 既存テストは `tests/` にある。`node --test tests/` で全通ること。
  **新しいテストを足すこと**（最低限：盆の追従計算、幕の開きと形、プール床と水面の入れ替わり、
  せりの負の値、プリセット展開後に `project.sets` が増えること）。
- ファイルを大きく変える前に既存のバックアップ流儀にならい、`stage-sketch_backup_2026-08-19-before-machinery.js` を作る。
- **削除・移動はしない。**
