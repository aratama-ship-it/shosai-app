# 検討メモ: 矢印を平面図でも描けるようにする（本人要望 2026-08-26）

作成 2026-08-26・Claude。**まだ発注書ではない。** 実装前の下調べ。
本人の言葉:「矢印の記入は平面図でもできるようにしたい」（「あとでもいい」）。

## 調べて分かったこと（コードで確認済みの事実）

### 1. 矢印は**すでに平面図にも描画されている**

`stage-sketch.js:9975` のコメントがそのまま根拠:
> 自由矢印は作図の印なので、駒より手前へ置き、正面・平面の両方へ出す。

`drawArrows(target, L)` は正面・平面の両方の描画経路から呼ばれている。
**足りないのは「描く操作」だけで、表示は既にできている。**

### 2. 床面の矢印は、平面図の座標そのもの → **データ構造の変更は要らない**

`arrowScreenPoints`（`:7938`）と `normalizeArrow`（`:3439`）より:

| plane | 点の意味 | 投影 |
|---|---|---|
| `"floor"`（既定） | `a`=横位置(0-1)、`b`=**奥行き**(0-1) | `stagePoint(a, b, 0, L)` |
| `"air"` | `a`=横位置、`b`=**高さ**(0-12)、`depth`=奥行き（**矢印に1つの固定値**） | `stagePoint(a, depth, b, L)` |

**床面の矢印は `{横, 奥行き}` なので、平面図で描いた線をそのまま格納できる。**
保存済みショーの互換性も壊れない。

### 3. 空中の矢印は上からは描けない

`air` は高さを持ち、奥行きは矢印ごとに1つの固定値しかない。
平面図（真上から）には高さを入力する軸が無く、現に平面図では
**左右方向の直線1本へ潰して表示している**（`:7939-7948`）。

→ **仕様の結論: 平面図で描けるのは床面の矢印だけ。** 空中の矢印は正面図のまま。
これは制限ではなく、むしろ**平面図のほうが素直**である。正面図で床面の矢印を描くとき、
奥行きは図から読めないので `arrowDepthPref()`（スライダーの既定値）に頼っている。
平面図なら**奥行きが図の上で直接決まる。**

## 変更が要る箇所（すべて `stage-sketch.js`）

現状は「正面図のみ」が5箇所にべた書きされている。

| 行 | 内容 |
|---|---|
| `:17432` | 矢印ツールを選ぶ条件が `state.showFront`（正面図が出ていること） |
| `:18078` | ポインタを下ろして描き始めるのが `view === "front"` のときだけ |
| `:18191` | 平面図では矢印ツールが select と同じ扱いへ落ちる |
| `:18074` | **ゲスト**の操作許可が `tool === "arrow" && view === "front"` |
| `:18334` | 同上（カーソル形状の判定） |
| `:8031` | 描いている最中の下書き `arrowDraft` が `!L.plan` のときだけ描かれる |

加えて **平面図の画面座標 →(a, b) の逆写像**が要る。
`stagePoint(a, b, 0, L)` の逆。平面図は真上からの平行投影なので難しくないはずだが、
**既存に名前の付いた逆関数が見つからなかった**（`unplace`/`screenToStage` 等は無い）。
平面図での駒のドラッグが同じ計算をしているはずなので、**発注書を書く前にそこを特定して
再利用する**こと。新しく作ると平面図のズーム（`zoomOf("plan")`）とずれる危険がある。

## 未決の設計判断（発注書を書く前に本人へ聞くこと）

1. **平面図で矢印ツールを選んだとき、「空中」が選ばれていたらどうするか。**
   自動で床面へ切り替える／空中を選べなくする／描けないと知らせる、のどれか。
2. **正面図で描いた床面の矢印を、平面図で掴んで直せるようにするか**（表示はされている）。
   直せると便利だが、当たり判定と選択の扱いが増える。まずは「描けるだけ」でよいか。
3. ゲストにも平面図での矢印を許すか（現状ゲストは正面図の矢印のみ）。
   **許すのが自然**だと思うが、発注書E-3の権限線に触れるので本人確認が要る。
