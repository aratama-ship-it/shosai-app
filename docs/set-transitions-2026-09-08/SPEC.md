## 1. 依頼と設計の核

ユーザー確認済み: 劇団関連からの評価が高く、セット転換強化が急務。必要なのは、①場面別の大道具配置と途中の動き、②誰が・いつ・何を動かすか、の両方。
実際の劇団名、運用人数、端末、対象公演、締切、要望文の詳細は未確認。

推奨: 隣接場面の間に「転換」を置き、平面図と手順表を同じデータから表示する。
最短操作は「前後の場面を作る → 転換を開く → 差分候補に担当・順番を付ける → 途中で止めて見る → 転換表を渡す」。
空の差分でも手順は追加できる。同じ配置へ戻る一時退避や、準備・確認は差分からは分からないため。

### 第一案の前の5つの整理

- 利用者/場面: 演出・舞台監督・転換担当が稽古前後に、位置と段取りを照合する。編集はPC/タブレット、スマホは確認中心を仮置きする。
- 使用感: 動く順番を見て説明でき、変更しても前後の配置が壊れない。複雑なタイムラインを覚えることを入口にしない。
- 固有の核: 舞台の上手/下手・袖、同じ現物の場面またぎ、手運びの段取りと合図、平面図上での途中確認。
- 継承/選別: 既存の舞台図・場面一覧・セット登録を継承。作業の並行/順次を分ける。音響ソフトの全レーンや本番制御は初版へ持ち込まない。
- 条件: オフライン保存、Undo、安定ID、日英、44px操作、停止中の常時再描画なし。自動生成と本人確認を区別する。

## 3. 初版の機能境界

最初の縦切りは、平置きの机・椅子・平台・パネル・組んだセットを対象に、移動/回転/搬出/搬入/待機/作業メモを最後まで扱う。
組んだセットは一体のまま剛体移動する。部材ごとの分解・組立、吊り/せり/回転床とその搭乗者の連動は次段階で設計する。
初版で非対応機構を検出したら行に「機構連動は未対応」を表示し、通常移動へ勝手に変換しない。既存の場面再生へ戻れる。

### 3.1 差分候補と同一物

- 名前や形の類似だけで同一物と確定しない。登録セット1件を現物1個として扱う。
- 「椅子A」「椅子B」のように同形の複数現物を識別する。実装前に同一setIdの複数配置の既存データを監査し、あれば自動対応を停止する。
- 未登録の駒はoriginId/idの一意対応を候補にする。重複/欠落は「対応を選ぶ」。人物や別物へ無理に統合しない。
- 差分種別は移動、回転、搬出、搬入、機構状態変更。初版の表示絞り込みは既存動線の0.25mを確定閾値として流用しない。微調整も一覧で確認できる。
- 差分生成はプレビュー。初回も「候補」と表示し、担当・袖・秒数を自動で確定しない。
- 再生成は追加/変更候補だけ提示する。既存の経路・担当・順序を上書きしない。

### 3.2 手順の構造

順序付きの「まとまり」を採る。まとまりの中の作業は同時開始、次のまとまりは全作業の完了後に開始する。
表示名は「手順1」「手順2」、同時作業は同じ手順内に複数行を並べる。初版では任意の依存グラフを露出しない。

各作業の必須項目:
- 対象となる現物 / 操作（移動・回転・搬入・搬出・待機・作業メモ）
- 担当（複数可、未定可） / 作業内容
- 始点と終点（場面位置・袖待機位置・転換内の途中位置の参照）
- 所要予定秒（null=未定、0=即時の作業メモのみ）

各手順の項目:
- 開始条件: 「転換開始」「前の手順が終わったら」「合図を確認して開始」
- 合図の言葉/台本ページ等の任意短文。台本ファイル自動解析・同期は初版不要。
- 終了後に待つ予定秒（未定可）。同時開始の細かな秒オフセットは後段。

担当は `castId` または名前付き担当枠の `staffId`。初版のstaffIdは「転換係A」などの軽い担当枠で、スタッフ名簿の管理画面は作らない。入力した役割名には再選択できる安定IDを付ける。舞台裏スタッフを演者ロスターへ自動追加しない。
同じ人が複数作業をする場合は同一IDを使い、同時割当を確認対象にする。
複数人で同じ物を運ぶのは1作業に複数担当。人の手・姿勢・歩行を自動生成しない。
担当未定でも設計を保存でき、印刷は「担当未定」が残る。

### 3.3 位置・経路・回転

- 前後の場面の位置は各場面が正本。転換画面では出発/到着を薄い輪郭で見せる。
- 初版の経路は直線または既存の二次曲線。同じ対象が同じまとまり内で途中停止して続行する場合は、1作業の中を「移動区間→待機→移動区間」にする。まとまりを跨ぐ場合だけ別作業とする。
- 「曲げる」「途中で止める」「向きを変える」を区別する。複雑な複数ベジェ編集を必須にしない。
- 袖は会場の実際の舞台領域/待機場所に従う。左右の袖がない会場へ固定の上手/下手入口を作らない。
- 搬入位置未定なら入口候補を仮表示するが、確定経路のように動かさない。搬出後の舞台裏位置も明示し、その後の搬入候補へ参照できる。
- 現行stashedは復帰用の位置控えであり、物理的な舞台裏保管位置と同一視しない。
- 回転は移動と独立したfacing。既定は最短方向。180度ちょうどは時計回り、方向を切替可能。360度以上の複数回転は次段階。
- 最終位置はBと一致させる。「到着位置を変える」はBの編集へ移り、変更範囲を見せる。転換の中間点だけの変更はA/Bを変えない。
- 元と先が同じ位置でも、途中退避/回転/待機作業を手で追加できる。全手順適用後の最終状態がBと不一致なら要修正。

### 3.4 再生

- 再生、一時停止、先頭へ、前/次の手順、時刻スクラブ、0.5/1/2倍。
- 全体予定時間は各手順の最長作業時間＋手順後待ち時間の合計。並行作業を足し算しない。
- 合図待ちは秒数を勝手に埋めない。「動作13秒＋合図待ち」のように表示する。
- 合図待ちに入った対象作業だけが止まる。保留中の合図一覧から「Q13が来たとして進む」等を選ぶと、その合図をいま待っている対象だけを再開する。全体一時停止とは別。実機や他アプリへGOを送らない。
- 任意時刻スクラブは「予定時刻の確認」として待ちを除く座標を求める。境界を跨いでも合図を受信済みとは扱わない。
- 秒数が未定の作業は、手順ごとの前/後表示を使う。全体を正確な秒軸で再生できるようには見せない。
- 作業内は初版では時間に対して同じ経路パラメータで補間する。二次曲線の均一な実速度は保証しない。既存のeaseInOutを実作業速度と断定しない。
- 暗転は客席ビューに反映。作業用平面図には「暗転中」を表示し、図自体は暗くしない。
- 編集中は再生停止。閉じる/切替/Undo/タブ非表示で時計停止、表示用データ解放。途中座標を保存/同期しない。
- 既存の盆の持続回転と二重に時計を持たない。新転換プレビュー中は旧sceneAnim/spinRunを休止し、終了時に規定の場面状態へ戻す。

### 3.5 転換表

初版必須: 転換名、A→B、手順番号、同時/完了後/合図、対象、担当、袖/移動先、所要予定秒、メモ、平面図、版と作成日時。
担当で絞った場合も前提となる他担当の手順を注記し、条件が消えた表を出さない。
HTML印刷からPDFへ。CSVは便利だが初版の合否条件ではない。公開共有URLは既存の権限設計確認後。
紙のチェック欄は稽古用。チェック済みを安全保証/本番完了と同一視しない。

## 4. 保存契約（提案）

`project.transitions[]` を追加し、隣接場面A→Bに1件。場面行の一種にはしない（場面の尺や章構造と混ぜない）。
初版の行動モデルは次の形を起点にする。これは保存済みデータや確定スキーマではない。

```json
{
  "id": "tr-a-b",
  "schemaVersion": 1,
  "fromSceneId": "scene-a",
  "toSceneId": "scene-b",
  "status": "draft",
  "sourceFingerprint": "sha256-of-relevant-inputs",
  "groups": [
    {
      "id": "g-1",
      "start": { "kind": "transitionStart", "label": "暗転の合図" },
      "postWaitSeconds": 0,
      "actions": [
        {
          "id": "a-table-out",
          "target": { "kind": "set", "id": "set-table-a" },
          "operation": "carryOut",
          "assignees": [{ "kind": "staff", "id": "staff-a" }],
          "from": { "kind": "scenePlacement", "sceneId": "scene-a" },
          "to": { "kind": "backstageMark", "id": "mark-shimote-1" },
          "path": { "kind": "linear" },
          "rotation": { "direction": "shortest" },
          "durationSeconds": 6,
          "note": "机が袖内へ入ったことを確認"
        }
      ]
    }
  ]
}
```

- 場面参照はaction.targetと組み合わせて一意に解決する。中間点/舞台裏markは同じu/v規約、実寸はvenueDimsから派生。場面改変検出用のスナップショットは比較専用、編集正本にしない。
- 名前・scene番号をキーにしない。targetはset/cast/origin等の型を明示する。
- groups配列順が順序、actions配列は同時集合。任意依存参照を作らない。隣接手順への移動は1Undo単位。
- schemaVersionは転換内部の形式番号。既存の文書version 4を転換用に流用し直さない。
- 旧クライアントは未知キーを落とし得る。versionを増やすだけでは保護できないため、ファイル・保存・共有・MCPの読書きを同じリリースで対応させる。未対応書込み経路は読み取り限定/明示拒否。
- 初版着手時にエクスポートversion 4への `requiredFeatures` 等の追加可否と、全入口の対応表を固定する。旧ファイルの原本を保存し、新版へ別コピーで移行する。転換を落とす旧版書き出しは明示的な互換コピーに限定する。
- 既存ドキュメントを今回の設計作業では変換しない。

互換性の実装条件を追加する。サーバーは保存済みプロジェクトの必須機能と書込み元の対応機能を照合し、転換を理解しない旧クライアントからの上書きを拒否する。オフラインでは新版用の保存キーへ複製して旧キーを原本として残す。ファイルは旧版へ渡す互換コピーと転換を含む原本を区別する。旧版への読込み実験で未知項目が黙って落ちる入口が残る場合、新版原本の既定書き出しは旧版が既存projectとして受理しない外側のbundle形式にする。このリリース条件を満たすまで新形式の製品保存を有効にしない。

初版の入力上限案は転換1件100手順、手順1件50作業、合計500作業、担当枠100件、作業時間0.1〜3600秒（作業メモのみ0可）、メモ500字。超過は切り詰めて保存せず入力エラー。実例とPROJECT_LIMITSの既存上限・保存サイズを測って初版着手時に確定する。

`sourceFingerprint` の対象はA/Bの対象ID・配置・向き・保持/支持関係・セット寸法・会場寸法/待機位置。場面タイトルや担当表示名の変更だけで全転換を再確認にしない。状態はdraft（作成中）/ready（本人が見積もりを確認）/needsReview（参照が変化）。readyは運搬の可否を示す値ではない。

### 時間の正本

1. 転換未導入の場面: 既存のrehearsal時間と表示アニメを維持。
2. 転換導入済み: group/actionの予定時間から「手順の見積もり」を算出する。別に編集可能なtotalSecondsを持たない。初版は既存の稽古時間の正本を置き換えない（Fable指摘を採用）。
3. 旧rehearsal時間は移行前の値として保持。不一致時は「旧予定20秒／手順13秒＋合図待ち」の比較を出し、上書きしない。
4. 初版のショー合計・稽古exportは既存rehearsal値を継続し、新転換見積もりを加算しない。「この転換の見積もりは稽古時間に未反映」と表示する。将来の統合時は本人確認の後、同じ `resolveTransitionTiming(A,B)` を通してどちらか一方を選ぶ。未定/合図待ちがある合計は「確定分＋未定」と表示し、二重加算しない。
5. cueSecondsとsceneAnimMsは表示速度。新転換の予定時間へ移さない。新転換画面は倍率で見え方を変え、予定秒数を書き換えない。

### 変更・破損・並替え

| 操作 | 規則 |
|---|---|
| 場面の到着位置/物/袖寸法を変更 | 依存箇所だけ再確認。確定した転換を自動で確定扱いに戻さない |
| AとBの間にCを挿入、並替え | A→Bの手順を保存したまま「接続が外れた転換」へ。A→CやC→Bへ推測コピーしない |
| 場面を複製 | 位置は既存clone規則。単一場面コピーで転換を黙って共有しない。複数場面をまとめて複製する場合のみ、内部で完結する転換を新IDへ写し、外部辺は写さない |
| セット/担当が削除済み | IDと最後の表示名を保って「参照先なし」。別の同名へ自動付替えしない |
| 同じ現物へ同時に複数動作 | 保存は下書き可、再生は該当手順を止める。1作業の移動＋回転は許可 |
| 破損JSON/未知の転換形式 | 元ファイルを保持して入力失敗を表示。部分読み込み成功で上書きしない |

## 5. 実装単位と受け入れ条件

日数見積もりは今回未確定。既存の共有/MCP改修との接点確認後に見積もる。

### A. まず1転換を端から端まで（ローカル試作）

対象: 机1台、平台1台、屏風1枚、担当3役。前後2場面。
机搬出6秒 → 合図確認 → 平台搬入7秒と屏風90度回転4秒を同時。動作分は13秒、合図待ちは未定。
ユーザーが実公演へ置き換えて評価するまで採用確定にしない。

合格観察: 説明なしで対象/順番/担当/合図を読み取れる。机を10秒へ変えると後の開始が4秒ずれ、合計17秒へ変わる。途中停止・スクラブ・初期値復帰で前後場面が変わらない。
失敗観察: 同時/完了後を逆に読む、袖の向きが伝わらない、表の担当と図の対象を照合できない、合図待ちを13秒に含むと誤解する。

### B. 製品組込み（設計採用後）

1. 純粋な差分/参照解決/予定時刻/任意時刻評価を `stage-transition-core.js` へ切り出す。
2. 既存stage-sketch.jsへ入口・保存・Undo・描画アダプタを配線。通常の場面送りは現行挙動を保ち、転換編集は専用入口から開く。
3. `stage-first-person.js` は共通評価結果を読む。最初の製品版で途中状態を両ビューへ反映するが、新たな運搬人体アニメは作らない。
4. `index.html` / i18n / style / printを追加。生成物stage.htmlはbuild_stage.py経由。公開配信はpublic-dist境界を守る。
5. MCP stage-model/project-store/edit-plan、共有状態/権限、各import/export入口を更新または未対応書込みを拒否。

必須検証:
- 差分: 同名別ID、ID重複、搬入出、位置不変の回転、一時退避→元へ、何も変わらない場面、参照欠落。
- 時間: 6+max(7,4)=13、10+max(7,4)=17、未定null、0、負数、NaN、合図待ち、全体二重加算なし。
- 評価: t=0/t=endの全対象一致、途中値、逆向きスクラブ、最短回転、180度規約、非表示から復帰、旧rAFと多重再生なし。
- 保存: 旧v3/v4読込み、新形式の保存/再読込、会場同梱、Undo/Redo、共有/MCP往復、同時改変/旧クライアントでの欠落防止。
- UI: 日本語/英語、PC/タブレット/スマホ、キーボード、reduced-motion、印刷改頁、保存失敗から復帰。
- 現場: 実際の1転換を舞台監督と担当者が読み合わせる。自動テストは読みやすさや運搬可否の証明にしない。

### C. 保留

吊物/せり/盆との手順連動、可変開始オフセットと複雑な依存関係、担当の歩行経路、精密な衝突/荷重判定、自動最短化、音響照明への制御送信、同時編集、全公演タイムライン。必要な実例から1件ずつ追加する。
