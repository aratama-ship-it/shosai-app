## 1. 担当：まず人を選び、必要なときに役割を書く

### 通常操作

1. 作業の「担当」を押す。
2. 既存の演者、今回のショーで追加済みの転換担当、未定から選ぶ。
3. 2人で運ぶ場合は「担当を追加」。必要なら各枠へ「机の右側」「机の左側」など役割名を書く。

最初から役職・チーム・権限設定を要求しない。staffは名前だけで追加できる。同名を見て別人/同一人物を自動確定せず、候補を区別して選べる。
演者兼務は演者ロスターの同じcastIdを選ぶ。既に登録済みの演者をstaffへ重複作成する導線は注意を出すが、名前だけで統合しない。

### 担当枠と人数

- 初期は「担当未定」1枠。人を選ぶと担当チップが表示され、枠は内部で作られる。2枠へ同じ人を入れたら重複を知らせる。必要人数の自動算出・充足率の機能は初版へ足さない。
- 枠は作業内の安定IDを持ち、任意のroleLabelとpersonRefを持つ。roleLabel「下手係」は人を識別するIDにしない。
- 例: 机A / 右側:演者A / 左側:転換係B。1作業を2人で行い、作業時間は6秒なら6秒（12秒へ足さない）。
- 未定、同一人物の重複枠は保存可能。「左側の担当が未定」など該当枠を表示する。役割ラベルは詳細へ置くが、重複/未定の要点は作業行にも短く出す。
- 机の位置だけを試す操作を欠員だけで止めない。ただし「担当確認済み」へは進めず、印刷に未定を残す。
- 担当枠を減らすと、削除対象の名前と役割をその場で見せて確認。Undoで1操作を戻す。

### 兼務の確認

| 状況 | 表示 | 動作 |
|---|---|---|
| 同じ人が、同時開始の机搬出と平台搬入へ割当 | 「担当が重なっています：演者A」 | 2作業を並べて示す。配置試し/下書き保存は可。担当確認済みにはしない |
| 同じ作業に、演者Aを2枠割当 | 「同じ人が2枠に入っています」 | 該当2枠を示す。自動で1枠へ縮約しない |
| 後の手順を同じ人が担当 | 重複とはしない | 作業の間の移動/持替えは別に確認する |
| 合図待ちを挟み重なりの有無が決まらない | 「担当が重なる可能性：合図の時点によります」 | 確定衝突と色・文言を分ける。名前・該当作業を示す |
| アプリへ演技/着替え/歩行の予定が未入力 | 空き時間を確定しない | 「登録された転換作業の範囲で確認」と表示 |

「担当なし」と「演者を配置していない」を同一視しない。空の平面図から人が空いているとは推測しない。
準備・持替え・後片付けも必要なら作業として追加する。未記入の所要時間を0へ変換しない。

## 2. 合図：予定するきっかけを、再生中に人が進める

### 入力

必須は合図の内容（例「暗転の合図」「台詞が終わる」）。Q12などの呼び名、出し手のメモ、台本ページは任意。初版の出し手は自由文で、人物IDの割当や兼務判定へ結び付けない。
合図のIDは編集できない内部ID。Q番号や表示名を変更しても作業との接続は保つ。同じ名称の別IDを自動統合しない。
作業が合図を参照しているので「この合図で進む作業」は派生表示できる。受け手の名簿をもう1つ作らない。
合図を削除/参照変更するときは影響する作業を列挙し、確認とUndoを用意する。使われている合図を無言で消さない。

### 始め方

- 転換の最初: 「転換開始」または「合図を確認して開始」。
- 次の手順: 「前の手順の全作業が終了」または「前の手順の全作業が終了＋合図を確認」。
- 作業の途中: 待機区間から、指定の合図を確認して次の区間へ進む。

前の手順完了と合図待ちを排他的な選択にしない。後続手順が先行作業の完了を追い越すことはない。
秒数の待ちと合図は別の値。手順や待機位置に合図の参照を付けるだけで、秒数へ自動変換しない。

### 予定を試す操作

ボタン名は「Q13が来たとして進む」。現場への送信・現場からの受信・本番の完了記録にはしない。
押す前に「机Aが再開」など影響対象を表示する。待っている作業がないときは無効にし、待機位置へ達してから使えることを示す。

| タイミング | 処理 |
|---|---|
| 対象がその合図を待っている | 待機インスタンスを解放。移動の終点へ飛ばず次区間の始点から進む |
| 同じ合図を待つ対象が2件 | 1回で2件とも再開。押す前に対象2件を表示 |
| 対象がまだ移動中で、合図待ちに未到達 | 合図を予約しない。その対象が後で自動再開することはない |
| 再開直後に連打 | 同じ待機に二重適用しない。次の別の待機を先取りしない |
| 後で同じ合図をもう一度待つ | 新しい待機インスタンス。「この合図は前にも通過。今回の待機を再確認して進む」と表示し、以前の通過で自動解放しない |
| 通常の一時停止中 | 合図操作も停止。再開後に押せる。意図しない動作予約を作らない |
| 最初へ戻す、後戻りして再試行 | 通過済みの合図を消し、その回の最初からやり直す |

合図のログは試し進行の揮発状態だけに置く。設計JSONへ受信済み/完了済みを保存しない。
任意時刻のスクラブは「配置確認」へ切り替え、合図の通過には使わない。初版の合図待ちがある転換は「手順から試し直す」を再生再開の入口にして、過去の合図を暗黙に引き継がない。
合図がまだ来ない/出ない場合はそのまま待てる。代替の強制続行を初版へ足さず、設計を編集して試し直す。

## 3. 途中待機：セットが止まる場所と、再開する条件

通常は「移動」1区間。経路上の「ここで待つ」を押すと、1作業の中に次の並びを作る。

`移動3秒 → 待機（途中位置・向き・待ち方）→ 移動5秒`

待機点は曲線を曲げる取っ手と別の形・ラベルにする。ドラッグだけを入口にせず「待機点を追加」から数値位置を選べる。
途中位置と向きだけを編集しても、前後の場面の位置は変えない。移動区間の接続は同じ位置/向きを参照し、停止前後で座標が飛ばない。
一度どけて元に戻す作業も同じ構造で記述できる。前後配置の差分だけからは自動生成しない。

### 待ち方

| 設定 | 意味 | 再開 |
|---|---|---|
| 秒数を決めて待つ | 待機位置へ着いてから指定秒を数える | 経過後に次の移動区間へ |
| 合図まで待つ | 指定した合図を待つ。時間は未定 | 試し進行でその合図を押す |

秒待ちは0.1秒以上、空欄は未定。0秒なら待機を外す提案を出すが勝手に削除しない。
初版の1待機へ「最低2秒かつ合図」等の複合条件は付けない。必要な場合は2秒待ち→合図待ちと分け、早く来た合図を自動記憶しないことを表にも明示する。
理由はメモ（例「客席から見えない位置で待つ」）。メモの文をアプリが条件式として実行しない。

### 途中待機と一時停止

- 途中待機: 対象の作業だけが止まる。並行する平台は動き続ける。
- 再生の一時停止: 転換全体の時計を止める。動作・秒待ち・合図の操作がすべて止まる。
- まとまりの終了: 中のすべての作業が終わってから。机が合図待ちなら次の手順は始まらない。
- 観客側の見え方: 暗転でも作業用平面図は消さない。「途中位置に止まっている」が読める。

### 持つ/置くと担当の扱い（本人回答を反映した更新案）

担当継続を既定にし、区間で離れる・戻る・一部交代・全員交代を表せる設計にする。「実例があれば交代を追加」の保留は撤回する。
「置く」と「担当が離れる」は別。A・Bで机を置いても、Bだけが離れてAは残れる。停止中もセットは待機位置を占有する。
次に検証するのは、A・Bで運ぶ→置く→Bが離れる→Cが到着してA・Cで持ち直す→指定合図で続行、という仮例。手渡しなら旧/新担当が重なる工程を持つ。
置く・持ち直す・担当の移動に必要な所要は入力値か未定。担当の拘束だけが瞬時に切り替わったことにはしない。
作業内の区間担当を正本にし、交代前後の接続・合図と準備の順序・別作業との循環をHANDOFF_NEXT_2026-09-09.mdで検討する。現在のHTMLの操作例は担当継続だけを検証した旧固定例であり、交代の再生は未実装。
全身や手の動きの描画は初版対象外。

## 4. 1枚の転換表に残す内容

見せる列は、作業/対象、担当、始める条件、途中待機、終わり、見積もり。
1作業を常に何行にも分けず、通常表示は「机A：3秒移動 → Q13待ち → 5秒移動」。展開すると区間ごとの位置・向き・担当が見える。
合図には内容を併記し、番号だけにしない。担当に絞っても前提となる他作業の完了条件や、その人が待つ合図を残す。
未定/重複/参照先なしを紙へ出す。動作の試しが完了した印を現場確認済みのチェックへ変換しない。
版、ショー名、A→B、確認範囲を付記。機器間共有や署名承認は初版へ広げない。

## 5. 時間の表示と架空例

Q12の想定合図で同時開始。
- 机A: 演者A＋転換係B / 中央から途中位置まで3秒 / Q13「台詞が終わる」を待つ / 下手袖まで5秒。
- 平台B: 転換係C / 上手袖から舞台中央まで6秒。途中待機なし。

| 試す条件 | 期待する結果 |
|---|---|
| 開始3秒 | 机は途中位置でQ13待ち。平台は移動の半分 |
| Q13を押さず6秒まで進める | 机は同じ位置。平台は到着済み |
| 6秒地点でQ13を想定する | 机が次の5秒移動を開始し、11秒で全作業終了 |
| 待ち方を固定2秒へ変える | 机は3+2+5=10秒、平台は6秒、手順全体は10秒 |
| 平台の担当を演者Aへ変更 | 同時開始の2作業で担当重複を示す。物の動きの見本は試せる |
| 机の2枠を両方とも演者Aへ変更 | 同じ人が2枠に入ったことを知らせる。2人の予定として表示しない |

合図待ちがある一般の全体時間は、各作業の待ちを全部足して求めない。並行区間の最長が変わるため。
初版は「未定の合図待ちを含む」と表示し、この固定例だけでは「合図待ち0秒と仮定した最短8秒」。試し操作でQ13を押した場合の11秒は「今回の試し進行」であって本番の予定値ではない。
旧rehearsalとcueSeconds/sceneAnimMsはそのまま。転換見積もりを自動転記しない。

## 6. 保存モデルへの追加案

前案のgroups/actionsを維持する。担当枠・合図定義・作業内区間を追加し、実際の通過状態は含めない。

```json
{
  "cues": [{"id":"cue-13","label":"Q13","content":"台詞が終わる","callerNote":""}],
  "action": {
    "id":"table-out",
    "target":{"kind":"set","id":"table-a"},
    "assignmentSlots":[
      {"id":"slot-1","roleLabel":"右側","personRef":{"kind":"cast","id":"cast-a"}},
      {"id":"slot-2","roleLabel":"左側","personRef":{"kind":"staff","id":"staff-b"}}
    ],
    "segments":[
      {"id":"seg-1","kind":"move","from":"scene-a-placement","to":"waitmark-1","seconds":3},
      {"id":"seg-2","kind":"wait","at":"waitmark-1","release":{"kind":"cue","cueId":"cue-13"},"assignmentPolicy":"retain"},
      {"id":"seg-3","kind":"move","from":"waitmark-1","to":"shimote-mark","seconds":5}
    ]
  }
}
```

この断片は担当継続だけの初回案。担当交代を含む更新案では担当枠は区間側を正本とし、作業全体の担当は派生表示へ変更する（HANDOFF_NEXT_2026-09-09.md）。既存アプリへimportできる形式ではない。位置参照はSPEC.mdの型付き参照へ落とす。
作業内にsegmentsを持つ場合、作業直下durationSecondsを別の編集正本にしない。区間から求める値か未定を返す。
slotId/segmentIdは複製時に再発行し、内部参照を同時に付替える。cueIdはプロジェクト共通の合図を引き続き使うなら保持する。独立した合図として複製する場合だけcueを複製して対象参照を付替える。未対応形式の旧クライアントへの上書き防止はSPEC.mdの条件を継承。

## 7. 受け入れ条件

- 担当枠: 0/1/複数/未定/同一人物の2枠/同じ名前の別人/演者兼務を区別。
- 同時作業と順次作業で、重複表示の根拠と確度を分ける。未入力の仕事を空き判定に使わない。
- 合図: 早押し、同一cueを待つ2作業、連打、再待機、後戻り、編集、一時停止、参照削除を確認。
- 待機: 位置・向きが固定、前後区間の接続一致、秒待ちの経過、合図待ち未定、別作業継続、次の手順への障壁を確認。
- 合図ありの下限と試し進行時間、合図なしの並行作業最大値、nullと0の区別、旧時間への非転記。
- 印刷と担当別表示でも条件/未定が落ちない。
- 仮例の3秒/6秒/11秒、固定2秒の10秒の状態を、図・表・操作で照合する。

追加の受け入れ条件: HANDOFF_NEXT_2026-09-09.mdの交代・循環・準備不足・手渡し・候補未定の項目。現行固定例の24項目とは別で、未検証。

残る現場確認: 実際の1転換、最初に欲しい担当枠の単位（人名/役割）、合図番号の運用、交代の型と所要。交代の必要性は本人回答で確認済み。未回答でも上記の論理設計と局所の試作検証は進められる。
