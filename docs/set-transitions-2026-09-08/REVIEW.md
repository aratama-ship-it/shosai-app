## 採らなかった点・留保

- Fable提案の「setIdの対応を最短距離で一対一マッチ」: 不採用。距離が近い別の現物へ付替える危険がある。安定IDで一意なら対応、一意でなければ人が選ぶ。既存twinOfの変更は全般の回帰影響があるため、設計案だけで自動変更しない。
- 対象を出発側piece.idだけで参照: 不採用。搬入物には出発側pieceがない。targetを現物IDで指定し、始点/終点の場面参照と組み合わせる。匿名駒はorigin対応を別扱い。
- 倍速の削減案: 試作には残した。秒数の見積もりを変更せず長い転換を短時間に比較でき、固定例では追加の操作負担が小さい。実例で不要なら製品初版から外せる。
- 「小劇団では転換要員=演者が多いはず」: 仮説としてのみ扱う。利用者の実態はまだ不明。
- 「同一setIdの複数台で確実に誤対応」: twinOfのfind先勝ちはコード確認済み。ただし通常UI/正規化でその状態がどれほど存在するかは未監査。実データに不具合があるとは今回断定しない。
