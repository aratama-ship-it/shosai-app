読み取り限定の設計相談です。ファイル探索・編集・実行・外部操作は不要。以下の自己完結した案だけを検討してください。日本語900字以内で具体的な矛盾と最小修正を返してください。
本人はStage Sketchの担当交代の局所試作を「良い、問題ない」と確認し、後で実装する追加要件として①演者に加えて裏方のキャラ②各人物のタイムスケジュール③大道具の設置所要に対して転換枠が短ければ警告、を希望しています。Codex側Astra、あなたは指定済みClaude Code Fable。今回は仕様だけ、製品実装/公開なし。
現在の設計は区間ごとの担当と合図、局所待機/交代、未定と競合の明示、表示アニメ秒数と稽古予定を分離。台本側はPDFへのcueRef/sceneRef/pathRef注釈で、位置付替えは参照編集でGO実行ではない。
新案:
1. 裏方を位置/動線を持つ人物として追加する将来設計。演者/裏方/兼務は人物の役割で、同じ実際の人を二重登録して暇と見なさない。人物のIDは台本の登場役とは分離。既存castId/staff参照は温存し、共通人物参照への移行規約は台本と共同で後日固定する。名簿追加だけで舞台へ自動配置しない。
2. 出番・袖移動・着替え・大道具作業・待機・合図の役割を人物ごとに表示。元は台本/転換の各予定への参照、一人別表は派生表示で二重編集正本にしない。未入力の仕事を空きとしない。PDF順から秒数を推測しない。秒数未定なら順番の表として表示し、同じ時刻基準を確認できた予定のみ秒軸で比較する。
3. 転換に使える枠は予定の開始/完了締切。必要所要は配置移動+設置/固定/確認+持替え/人の移動と前提を考慮。並行できる工程は最大値、同じ人が排他的に行う工程や先行必須工程は順次。ただし仕事の順番をアプリが自動最適化して成立と見せない。
4. 大道具の仮例: 同じ裏方B/Cで搬入8秒→設置6秒→固定4秒=18秒、使える枠12秒なら『入力した所要では6秒不足』。別担当Dの10秒作業が並行できるなら18+10と足さない。これは手入力見積もりであって物理的な不可能の証明ではない。設置見積もりには人数/会場/手順/見積か稽古実測かを紐付け、条件変更時は見直す。実測で予定を自動上書きしない。
5. 警告: 入力条件では不足 / 作業は収まるが設定した予備時間が不足 / 担当や前提の矛盾 / 情報不足で判定不可。枠と所要が同じなら余裕0。未知があっても既知の必須入力工程だけで枠超過なら、その限定した不足を表示。未知を0にして『収まる』とはしない。
6. 直す候補は転換枠を延ばす/事前に設置する/並行や担当案を見直す。人数を増やせば速くなると自動推定しない。値や配置を勝手に変えない。警告には超過を決めた工程と担当と計算前提を出す。
見てほしい点: 「裏方キャラ」を名簿だけへ縮小していないか、人物/登場役/出演配置/台本の二重計上、見積超過を物理的不可能と誤表示、合図依存/未知/人的競合を含む時間判定の抜け。機能を広げる提案より、上記を小さく整合させる指摘を優先してください。
