## 2. 人物と担当枠

| 概念 | 局所試作v1での意味 |
|---|---|
| personId | このショーに参加する実際の人物1人。名前を変更してもIDを保持。演者/裏方のタグは複数可 |
| castId / roleId / staffId | 既存の演者登録、台本役、名前付き担当枠への参照。実在人と自動同一視しない |
| assignment | 1工程の1担当枠。slotId、personIdまたはnull、任意の元参照、対応の確認状態を持つ |
| 配置・動線 | 場面/区間の配置参照。図に置かない人物にも予定を持てる。人物区分だけで可視/不可視や空きを決めない |

人物を選ぶと、その工程のassignmentに同じpersonIdを明示的に記録する。役/担当枠との元参照は対応の根拠であり、名前や元IDから裏でpersonIdを補完しない。
複数工程をまとめて対応付ける場合は、適用する工程を列挙した一つの編集にする。別の出番や交代後の枠まで自動で変更しない。
交代は旧区間のassignment終了と、新区間のassignment開始で表す。手渡しの工程には旧/新担当が同時に参加する。置いて離れる場合はその後の区間へ旧担当を含めない。置いただけで全員の担当を外さない。
同じpersonIdを同一工程の複数枠に入れたら人数不足の可能性として重複を報告し、二人として数えない。
未対応はpersonId:null / resolution:unresolved。判定用の架空人物を生成せず「担当未確定」。同名別IDが同一人物か分からない場合も、空きや競合の確認済みにはしない。

## 3. 予定の正本と参照

予定1回にプロジェクト内で一意のactivityIdを割り当てる。共通で読む値は、表示名、所有元、工程種別、assignment、開始/終了の時点参照、所要の根拠、revision。

| 所有元 | 正本として編集するもの |
|---|---|
| script | 1回の出番等の予定。PDFの頁・注釈・sceneIdから予定を自動生成しない |
| transition | 転換の各区間の運搬・設置・待機・受渡し。区間が担当/手順を所有する |
| personal | 他の元予定に属さない着替え・単独移動・待機 |
| 人物別表示 / 台本注釈 | activityIdを参照して表示。人数、所要、開始/終了を別の編集値として保存しない |

局所fixtureはこれらを一つのactivities配列に載せ、各レコードのownerを残す。これは共通インターフェースの説明用で、製品でも同じ配列配置を必須とする決定ではない。製品で区間が正本なら人物表はその区間から読み、同じ内容の予定をもう一つ保存しない。
同じactivityIdを台本・転換・人物表から参照しても、一つの作業として数える。人物A/Bが同じ作業に参加するとき、AとBの各表へ載るが全体所要を2倍にしない。
同名でも別の回の出番・別の作業は別ID。既存作業へ注釈を付ける操作は参照追加。独立した予定複製は新ID。時間が近い、名前や頁が同じという理由では統合しない。
activityIdと元区間の参照は一対一に解決する。重複IDや同じ元区間に複数の正本が見つかれば解決エラーとし、先勝ち/後勝ちで選ばない。

## 4. 合図と予定の時間

### 4.1 起点と計画の区別

cueIdはプロジェクト共通の合図定義。呼び名Q12や台本アンカーはIDではない。台本なしの転換でもcueを使える。
局所試作は、同じplanContextId内で1 cueIdを一つの計画上の合図起点として扱う。台本の主GOは未割当または1箇所。同じcueが異なる時点に反復する計画はこの試作では非対応と表示し、単一の起点へ畳まない。製品の発生単位は別途設計する。
planContextIdは一つの予定案の時間基準。別案・別稽古の実測・実進行の時計は比較に混ぜない。
originIdはショー開始または特定cueの計画上の起点。fixtureではq12起点を0とし、q13起点がq12から何ms後かを明示入力する。未知はnull。cue番号や台本順から差を生成しない。
異なる起点を変換する場合は同じplanContext内で確認した差を使う。今回の最小試作では一つの基準起点から各起点までの差だけを持ち、任意の複雑な起点ネットワークを自動推定しない。

### 4.2 共通の時点参照

内部単位は整数ミリ秒。差分計算は整数のまま、表示だけ秒へ換算する。表示アニメのsceneAnimMs/cueSeconds、画面の試し進行、測定の原記録は入力元にしない。

時点pointIdは次の4形だけで表す。すべて同じplanContextに属し、IDと所有元を持つ。

| 形 | 意味 |
|---|---|
| anchor(originId, offsetMs) | 確認した起点からの相対時点。出番が合図より前なら負のoffsetも可 |
| after(pointId, estimateId) | 指定時点＋採用した所要。estimateはms値/nullと由来・条件を一度だけ持つ |
| latest(pointIds) | 必須条件が全て揃う、最も遅い時点。未知を0として無視しない |
| unknown(reason) | 起点/所要/時刻が未定。順序と元の参照を保持する |

予定の開始/終了はpointIdを参照する。時間の値はこの時点/所要の正本だけで持ち、人物表や予定行へ計算済み時刻を別保存しない。
開始から終了までを[開始,終了)とする。5秒で終わる作業と5秒に始まる作業は時間重複ではないが、移動/持替えを省略してよいとは判定しない。必要な移動は別の予定として明示する。
同時条件が自然に揃うと待機が0msになる場合は「待機なし」と表す。待機の定義は残し、正の作業時間として計上しない。運搬/設置/受渡しの所要0は無効。負の所要・非有限・整数範囲外も無効。
時点の依存を開始/終了の両方について検査する。参照切れ、別context、循環、終了が開始より前なら、その予定と依存する比較は計算しない。未知や矛盾は別状態で残す。

### 4.3 待機とGO

作業を続ける前提が「前工程完了＋人の到着＋合図」であればlatestで表す。ただしこれは計画上の開始可能時点であり、現場での実行やGO送信ではない。
担当を保持した待機もactivityとして開始から解放までを占有する。離れた担当はその後の待機には含めない。
相手より早く到着した人も、その場で参加を待つ計画なら待機を明示する。局所例ではCの到着〜持直し開始をCの待機とする。通常は0秒、Aの出番が4秒延びた場合は8〜11秒の3秒待機となる。Bの準備待ちはQ12〜運搬開始、Aの到着待ちは机へ歩き終わり〜運搬開始。帯の欠落を手空きと解釈しない。
待機終了が後続開始を参照する場合、後続開始は置き終わり/到着/合図等の独立した条件から決める。待機終了と後続開始が互いを前提にする循環を作らない。
例: Aは置き終わりからC到着まで待つ。A/Cの持直し開始=latest(置き終わり,C到着)。持直し後の合図待ちはlatest(持直し完了,Q13)まで。Q13の予定時刻が未知ならその待機の終了も未知。
局所試し進行は既存HANDOFF_NEXTの契約を継承する。早い合図は予約にならず、準備が揃っても自動実行しない。計画上のlatestの値と「操作して再開した」履歴は分ける。

## 5. 人別の重複と転換枠の比較

- 同じ人物の排他的な2予定で max(start1,start2) < min(end1,end2) なら重複。名前や区分ではなくpersonIdで比較する。
- 両立不明な作業は要確認。合図の出し手/受け手という参照だけから拘束区間を生成せず、注意や操作に必要な時間を別に登録する。
- 未対応の人物、比較不能の時刻、未登録の予定がある場合は「入力した予定の範囲」の結果と確認不足を併記する。確認項目は人物・対象期間・予定案revisionを持ち、全ショーへ一般化しない。
- 時刻を固定した重複予定を勝手に並べ直さない。after/latestが表す、本人が入力した順序や前提の計算だけを行う。

転換枠windowIdは開始point、締切point、達成する完了pointの一覧、対象条件（設置完了/人の退避まで等）、任意の予備時間を持つ。
終了=達成すべき完了の最も遅い時点。不足=max(0,終了-締切)、作業後の余裕=締切-終了。未知の締切から数値の不足を出さない。
枠開始から後に必要な工程だけを比較する。事前作業を無言で枠外へ移さない。枠内で並行できる作業は足さない。
担当競合、時間不足、予備不足、未確認は複数同時に表示できる。担当矛盾があっても、独立した既知の必須工程だけで枠を超える根拠は限定して示せる。最終結果一個で他の理由を隠さない。
余裕0は「入力上は枠内／余裕0秒」。予備時間未指定なら不足警告にしない。未知は0ではない。見積もり不足を物理的不可能と表現しない。

## 6. 修正・参照切れ・保存

| 変更 | 保持するもの / 再確認するもの |
|---|---|
| 人名・Q番号の表示変更 | ID/対応/時間条件を保持。表示だけ更新 |
| assignmentの担当変更・人数・手順・所要条件変更 | 関係する所要根拠、人物の重複、時間枠を再確認。無関係な配置は保持 |
| 合図の意味/主GOの変更、予定の開始/完了変更 | その起点/予定に依存する時間・担当の確認を失効 |
| 紙面位置のみ変更し意味/順序が同じと確認 | 位置確認を更新。無関係な時間や配置の確認は保持 |
| 紙面位置変更の意味が不明 | 注釈を未解決とし、依存する起点/条件の確認を保留。元の所要数値は保持 |
| 人物・cue・予定・台本位置が参照切れ | 元ID/表示名/所要根拠を残す。影響する参照を未解決とし、0/空きにしない |

対象データのrevisionと依存先revisionの組を確認記録へ結び付ける。ここでrevisionは判定に効く条件の改訂番号で、表示名だけの変更では条件revisionを増やさない。時点/起点/所要/枠にも改訂番号を持たせる。変更した値を表示しながら旧revisionの「確認済み」を流用しない。数値の解決と条件の確認済みは別の状態とする。
独立した予定複製は新activityIdと、新たに所有するpoint/assignmentを作り、内部参照を対応付ける。共通person/cueは同じ対象を使うならIDを維持。別案は新planContextとして時間/確認記録を混在させない。
プロジェクト全体の複製はプロジェクト内の参照関係を保つ。未知のキーや壊れた参照を削って保存成功にしない。

局所fixtureのkindはstage-people-time-contract-fixture、contractVersionは1。製品のkind/versionへ偽装せず、現行の読込み・棚・共有・MCPには渡さない。
製品接続前にnormalize/restore、Undo/Redo、ファイル、棚/セッション、共有、MCP、旧クライアントの各読書き経路を共同監査する。未対応クライアントの書込みで新情報を失う状態では保存を有効にしない。具体的なschema版・保存位置・移行コードは未確定のまま残す。

架空のA（演者兼裏方）、B/C（裏方）を使う。基準はQ12=0、Q13=10秒の計画値。移動/所要は説明用の仮値。

| 人 | 共通時刻での予定（秒） |
|---|---|
| A | 出番 -4〜0 → 机へ歩く0〜2 → Bと運ぶ2〜5 → 置く5〜7 → Cを待つ7〜8 → Cと持直す8〜10 → 搬出10〜15 |
| B | 運搬開始を待つ0〜2 → Aと運ぶ2〜5 → 置く5〜7 → 別作業へ移動7〜8 → 別作業8〜12 |
| C | 平台を置く0〜6 → 机へ歩く6〜8 → Aと持直す8〜10 → 搬出10〜15 |

Q13待ち10〜10、通常のC到着待ち8〜8、A到着待ち2〜2は「待機なし」。Aの机へ歩く予定と出番は別の入力元、運ぶ/置く/持直す/搬出は各2人で同じactivityを参照する。待っている間の人物を空き扱いしない。
枠0〜15、達成対象は机の搬出完了（他の退避は含めない）。この入力では完了15秒、余裕0秒。Bの別作業4秒を搬出へ足さない。説明例の予定外の仕事がないことは仮定であり、現場確認済みではない。

1. 人物表・台本注釈・転換表が同じactivityを一度だけ参照し、A/Bの共通運搬を二重計上しない。
