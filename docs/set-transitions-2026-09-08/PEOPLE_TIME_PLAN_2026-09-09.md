## 本人確認と今回の範囲

本人は担当交代の局所試作を「良いですね。問題ありません」と確認した。
追加の希望は、演者に加えて裏方のキャラ、台本キューも含む各人物のタイムスケジュール、大道具の設置所要に対して転換枠が短い場合の警告。
今回は要件と接続方針を文書化する。人物/時間警告の機能は実装しない。本番公開は未許可。既存のhandoff試作は変更しない。

## 1. 裏方を配置・動線のある人物として扱う

- 裏方も人物として登録し、作業用の舞台図に置き、袖/待機場所/移動先を持たせられる設計にする。名簿だけの追加に留めない。図に置かなくても予定や担当へ割り当てられる。
- 実際の人物の区分は演者/裏方/兼務。一人が出番後に転換を行っても同じ人物として扱い、同時に二人分の仕事へ割り当てない。
- 台本上の登場役・演じる実際の人物・場面の配置は別。複数の役を一人が演じる場合も、人の時間は一人分。同名だけで人物を自動統合しない。
- 人物の登録、役割、図に置くこと、観客視点で見せることを別の設定にする。裏方登録だけで舞台上へ自動配置しない。役割が裏方でも出方によって客席から見える場合があるため、区分だけで自動的に隠さない。
- 既存のcastIdと転換側のstaff参照は削除・置換しない。staffIdは「転換係A」等の名前付き担当枠を表す場合があり、一律に実在人物1人へ昇格させない。castIdの意味も現物と台本側で確認し、登場役/担当枠から実際の人物への対応を人が明示する。
- 共通の人物参照を設ける案とし、同一人物として束ねる鍵は名前ではなく、この明示的な対応とする。担当交代があれば工程/区間ごとに担当枠と人物の対応を持つ。担当枠全体を永久に一人へ固定しない。
- 人物への対応が不明なら「担当未確定／同一人か未確認」として残す。未対応の出番と作業を別人として空き扱いせず、同一人とも競合確定とも断定しない。この対応規約を人物別の成立判定の前提とし、製品への保存形式と既存値の移行方法は共同確定する。
- 人物は既存案の区間担当へ手動で割り当て、待機・離脱・交代と配置/動線をつなぐ。人物登録だけで担当や動線を自動生成しない。

## 2. 人物別の予定表は、元の予定を一つにして見せる

出番、袖への移動、着替え、待機、運搬、設置/固定、受渡し、合図への関与を人ごとに並べる。
正本は台本/転換/人物作業の各予定。人別表示は参照から生成する。台本のQ13にも転換表にも同じ受渡しが載っていても、同一予定として一度だけ計上する。
人別表からの編集は元の予定を対象にし、変更が他の図や表へ及ぶ範囲を見せる。別の編集値を人物表へ二重保存しない。

台本/転換に属さない着替え・単独移動・待機は、ショー内の「人物の予定」を入力元として一つ持つ。人物、内容、開始/終了または順序、所要、場所、時間の根拠を記録する。出番なら台本予定、転換内の移動なら転換工程が元の予定となる。同じ移動を人物の予定へ複製せず、必要なら既存予定への参照を付ける。人物別表示から追加するときも、どの元予定へ追加するかを明示する。

| 状況 | 表示案 |
|---|---|
| 秒数と基準が分かる | 同じショー内の相対時刻で、出番と作業を比較 |
| 合図や台詞の時刻が未定 | Q12→出番終了→袖へ→転換補助等、順序で表示。正確な秒幅の帯を作らない |
| 待機が続き、担当を離れていない | 待機もその人の担当区間に含む |
| 担当を離れた | その工程の担当は終了。ただし別の予定が未入力なら「空いている」と断定しない |
| 合図の出し手/受け手だけが記録されている | まず関与する合図として表示。必要な準備・注意・操作時間は別に指定 |
| 同じ場所で両立できるか不明な作業 | 一律に不可能とせず要確認。重い物を同時に別方向へ運ぶ等の排他的作業と区別 |

「台本に役名がある」「場面に演者のコマがある」だけで、出番の開始/終了秒数や全場面中の拘束を決めない。時刻根拠が確認できる予定同士だけを秒で比較する。
タイムスケジュールはショー内の予定を対象とし、勤務管理やカレンダー予約へ広げない。

## 3. 使える転換枠と、必要所要を比較する

使える枠は「転換開始」から「この状態まで完了しておく締切」。机の設置完了が締切なのか、担当の退避まで含むのかを明示する。
必要所要は担当/区間/前提工程から求める。対象を動かす時間だけでなく、置く、組立/設置、固定、確認、持ち直し、担当の移動や前の出番終了を含む。

- 順次必須の工程は足す。
- 前提と担当の条件を満たして並行できる工程は、終了が遅い方を使う。全工程の秒数や人数分を足さない。
- 同じ人の排他的な作業は同時に行えない。順番が決まっていなければアプリが勝手に順序付けして「収まる」としない。
- 合図が遅く来る/前の出番が長引くなら開始可能時点が遅れる。合図待ちを常に0秒として確定所要を表示しない。
- 既存rehearsalの予定、表示アニメのsceneAnimMs/cueSeconds、実測、試し進行の時計は区別する。既存の値を無言で転換枠や必要所要の正本へ移さない。
- 設定した転換枠の参照先が台本改訂などで未解決になったら、以前の「収まる」を維持せず、その比較だけ再確認にする。

### 時間の基準と判定の前提

比較には明示された計画上の時間基準を使う。ショー開始からの相対秒、または特定の合図からの相対秒を識別し、同じ基準または確認済みの差で変換できる予定同士だけを比較する。表示アニメのsceneAnimMs/cueSecondsや画面の再生速度は判定入力に使わない。既存の稽古予定を使う場合も意味と起点を確認して参照し、暗黙に流用しない。

- 「Q12で開始、Q12から12秒以内に設置完了」なら、Q12の絶対時刻が未定でも相対12秒の枠として比較できる。ただし担当の前の出番との時間関係は別に確認する。
- 「Q12で開始、Q13までに設置完了」で両合図の間隔が不明なら、枠の秒数は判定できない。順序だけを残す。
- 担当の出番や別作業が既知で重なる場合は、担当/前提の矛盾として示す。予定が不足している場合は「担当の空きは未確認」とする。所要だけの比較は条件付きで出せるが、計画全体が収まるとは表示しない。

## 4. 警告の具体例（全数値は仮定）

裏方B・Cが同じ大道具を順に扱う: 搬入8秒 → 設置6秒 → 固定4秒 = 18秒。
例の基準は「開始合図を0秒、12秒後を固定完了の締切」。B/C/Dは各作業中に他の出番・作業がなく、開始位置に準備済みと仮定する。実際に確認した条件ではない。担当の退避はこの例の締切に含めていない。
転換枠12秒なら、表示案は「入力した所要では6秒不足。搬入8秒＋設置6秒＋固定4秒が締切に間に合いません」。
別担当Dの10秒の作業が同時にでき、他の前提もなければ、18＋10=28秒にはしない。手順全体の入力上の所要は18秒。
これらの所要が手入力の見積もりなら、警告もその見積もりを前提にする。物理的な不可能を測定・証明した表示にはしない。

| 判定 | 表示する内容 |
|---|---|
| 入力した所要が枠を超える | 不足秒数と、超過を決める一連の工程・担当・比較した開始/締切 |
| 作業は収まるが予備時間が足りない | 作業の不足と分け、指定された予備時間が何秒足りないか |
| 枠と所要が等しい | 「入力上は枠内／余裕0秒」。予備時間未指定なら時間不足の警告にしない。予備時間を指定した場合はその不足を別表示 |
| 担当重複・循環・参照不明 | 計画の矛盾/未解決箇所。単なる秒数不足に変換しない |
| 所要や合図時点が未定 | 判定できる範囲と未定の工程を示す。未定を0秒にして適合としない |
| 未定があるが既知の必須工程だけで枠を超える | 「既知の入力工程だけでも6秒不足」等、限定した根拠で不足を出す |
| 入力範囲で収まる | 入力した条件での残り時間と、未確認の予定・条件の有無を示す |

予備時間は本人が指定した場合だけ別項目で計上する。全ケースへ一律の安全率を勝手に足さない。
対処候補は「転換枠を延ばす」「事前に置ける工程を見直す」「担当/並行作業案を見直す」。採用は人が決め、時間・合図・配置をアプリが自動で変更しない。
人数を増やしたら比例して速くなるとは推定しない。

## 5. 所要の根拠を持つ

見積もりは対象の設置方法、担当人数/割当、場所/経路などの条件と結び付ける。重さ・距離だけから標準時間を生成する機能は今回の要件に含めない。
値には「手入力見積もり」「稽古での計測」等の由来を残す。計測値と計画へ採用した値は分離し、稽古の1回の結果で予定を自動上書きしない。
条件が変わった場合、その所要と依存する比較を要確認にする。名前変更だけで無関係な幾何・全予定を失効させない。

## 6. 台本キュー側との接続

PDF注釈のドラッグ＆ドロップは参照位置の割当/付替え。共通人物や合図の実行、転換の配置変更へ変換しない。
共同で決める対象は、人物参照、同一予定を識別する参照、時刻/順序の根拠、合図と開始/完了締切の関係、改訂時の再確認範囲。
台本側へ新要件と上記の分離方針を共有した。製品schemaはまだ共同確定していない。
台本側からの確認を反映し、staffIdを人物へ一律に変換する案は採らず、担当枠と人物の明示的な対応を前提にした。PDF注釈の位置変更だけから予定時刻や担当の空きを推定しない。

## 7. 後の実装順序と確認ケース

1. 裏方を含む人物参照、担当枠/役と人物の手動対応、個人予定の入力元、台本/転換の共通保存・時間基準の契約。
2. 人物ごとの順序表。既知の時刻だけを使った秒軸、移動/着替え/転換/キューの重複確認。
3. 転換枠と必要所要の比較、警告と根拠への移動。

受け入れ例: 演者兼裏方を二重に空き扱いしない/役の掛持ちで人が増えない/同一作業を台本と転換で二重計上しない/18秒対12秒で入力上6秒不足/別担当の10秒を足さない/設置に参加する人の出番終了が遅ければ反映/所要未定から適合を出さない/枠18秒なら余裕0/予備時間だけの不足を区別/改訂で未解決の時刻から以前の適合を引き継がない。
これらは設計上の確認条件で、現在のhandoff試作の20+30項目に含まれない。

追加の受け入れ条件: 名前付き担当枠を実在人と自動同一視しない/交代前後で枠の担当人物を切り替えられる/未対応の演者と裏方を別人として適合にしない/着替えの入力元が一つだけ/同一合図から12秒の枠は比較できる/間隔未定の別合図までの枠を12秒等へ捏造しない/担当の空きが仮定か確認済みかを区別する。

## 8. レビュー反映と確認範囲

Claude Code Fableには提示仕様だけを読み取り限定で確認依頼した。人物への手動対応、個人予定の入力元、計画時間の基準、例の担当条件、余裕0秒の分類を具体化した。時間基準は「稽古予定だけ」へ限定せず、起点が確認できる計画上の共通/相対基準とし、表示アニメ秒数を除外する形で統合した。
