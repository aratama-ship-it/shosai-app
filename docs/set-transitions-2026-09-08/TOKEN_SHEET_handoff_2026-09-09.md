# 担当交代の局所試作：設計とトークン

対象: handoff-2026-09-09.html、handoff-core-2026-09-09.mjs、handoff-ui-2026-09-09.mjs。
Astra実装、既存Fableレビューの区間担当・前提工程・循環検出を採用。製品へ接続しない。

## 設計メモ

利用者は転換を検討する本人/劇団。机の担当交代が成立するかを、セット図と人別の今の作業で照合する。
安心の断定ではなく、未定と重複の場所が分かり、担当や秒数を替えて試し直せる感触を目指す。
固有の核は「置く」と「担当終了」の違い、残る人と加わる人、合図待ちと全体停止の違い。
既存の紙色/舞台図/手順表を継承。編集は折りたたみ、主操作→舞台図→人別→区間表の順。前案同様、全面的なタイムライン編集や人員自動最適化は導入しない。
候補は説明だけの追補、全部の経路を編集する画面、固定例の区間状態を試す画面。今回の判断に直接使える最後の案を採用。
参照方針はSPEC.mdと既存TOKEN_SHEET_operations_2026-09-09.mdを継承。新しい外部意匠は追加しない。

## 固定例の仮定

机を運ぶ3秒、置く2秒、平台を運んで置く6秒、Cの移動2秒、持ち直し2秒、机後半5秒。
離れた旧担当の別作業へ移動1秒、別作業4秒。Dを使う場合、前作業7秒+机への移動1秒。
手渡しの場合、置く代わりに旧担当が持って待ち、受渡し2秒に旧/新担当が同時参加する。
全数値は架空。空欄は未定。印刷・画面に固定例と未確認範囲を明記。
