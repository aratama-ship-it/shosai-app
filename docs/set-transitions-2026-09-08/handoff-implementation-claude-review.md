## 確認できた問題（コード読解上、確実に再現する）

**1. advance の1ms丸めが刻み依存（観点5）**
`advance` は `Math.round(seconds*1000)` で毎回丸めるため、端数が持ち越されません。最小の実行反例:
```js
const a=run(), b=run();
for(let i=0;i<6;i++) a.advance(0.0006); // 各回1msに切り上げ → 6ms
b.advance(0.0036);                       // → 4ms
// a.time=6, b.time=4。さらに advance(0.0004) はN回呼んでも常に0で進まない
```
工程の最小所要が0.1秒なので工程状態までは変わりませんが、snapshot の time 一致（テスト19の趣旨）が1ms未満の刻みで崩れます。修正案: `seconds<0.001` を Invalid advance として弾く（1行）か、丸め前の端数msを内部に持ち越す。

**2. returnB が無言で無効化される場合がある（観点3）**
`makePlan({returnB:true})`（既定の right:'C' のまま）だと `returning=false` となり、returnB は診断もなく完全に無視され、通常プランと同一になります。direct×returnB は throw する（handoff-core-2026-09-09.mjs:15）のに、この組合せだけ黙認するのは「未定・無効を黙って扱わない」方針と不整合です。修正案: 同様に throw するか、「returnB は B が再開後担当のときのみ有効」という assignment 診断を追加。

**3. 候補の中身が文言に固定**
診断文「候補（BまたはC）」（同:59）と `nameOf` の「候補B/C」は固定文字列で、候補リストをデータに持ちません。設計文書側の例は「AまたはC」であり、画面・印刷接続時に食い違います。修正案: 候補配列を config に持たせ、診断はそこから生成。

**軽微:** ①所要null と担当未定が併発した工程のブロック文言が「所要が未定」だけになる（同:92）。②done 後の `cue()` が false でなく undefined を返す。
