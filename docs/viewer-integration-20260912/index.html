Stage Sketch Viewer
組み込み・公開プラン

おすすめは「共通ソースへ組み込み → ベータ先行公開」です。今回の調査では、UIの差し替えだけで両サービスを更新できる状態ではありませんでした。

そのまま公開できない理由

  • 端末確認用プレビューは通信を模擬しています。本物の招待リンク・保存・失効・メモ共有を接続し、検証する必要があります。
  • 現在のベータのViewer入口は、未ログインのアクセスに401を返します。公開体験版にはViewerがありません（404）。
  • 9月10日の公開記録では、正式製品版は「共通ソース更新済み・サービス未公開」です。公開体験版とは別物です。

今回はアプリの変更・新たなデプロイ・Twitter投稿はしていません。

進める順序

  1. 採用済みUIを共通ソースへ移す。
    青色と名称、余白、折りたたみ、縦横対応、客席視点切り替え、不要パネル削除、ピンチ操作を維持。サンプル専用の通信処理は移しません。
  2. 本物の招待で一巡する。
    作成→演者が開く→個人メモ→明示的な共有→所有者が確認→更新→リンク失効。別の公演や個人メモが漏れないことも確認します。
  3. ベータ版を先に公開する。
    既存のログインと配信を保ち、必要な保存機能だけ追加。公開後の動作とiPhone／iPad実機を確認して告知します。
  4. 製品版は公開条件を整えて反映する。
    UIは共通化。実サービスのURL・利用権限・無料演者アカウントの認証を整えてから公開します。

確認したい判断は1つ

「製品版へ組み込む」は共通ソースへの反映まででよいか、正式サービスの新規公開まで含めるか。

実装範囲・検証・根拠

既存の公開Workerと配信アセットを基準に、独立した作業場所で必要な差分だけを統合します。共有作業中の全変更をまとめて公開しません。戻す場合も新しく保存したデータは削除しません。

UIの数値は採用済みの設計を継承：見出し帯は縦52px／横44px、操作対象44px以上、横向きレール64px、拡大率1〜4倍。安全領域とキーボード表示も検証します。

PCブラウザの自動検証、実際のサーバーとの連携、iPhone Safariの実機確認、公開先の検証は別々に記録します。
