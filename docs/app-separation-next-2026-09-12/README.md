# 制作の書斎 / 舞台スケッチ 分離の次段階

2026-09-12時点のローカル判断資料です。公開、DNS変更、Workerデプロイ、既存Mac配布物の削除は行っていません。

## この段階で固定すること

- 決定済み: 制作の書斎と舞台スケッチは別アプリとして扱う。
- 決定済み: 制作の書斎の画面・導線に舞台スケッチを含めない。
- 推奨: `stagesketch.pygmix.com` は舞台スケッチ専用として維持する。
- 推奨: 制作の書斎は新しい公開先が必要になるまでローカル専用とする。
- 推奨: 現在のネイティブMac版は舞台機能が中心なので、舞台スケッチへ帰属させる。

## なぜ実装を一度に切り替えないか

現在の共有ツリーでは `worker.js`、`wrangler.toml`、`mac.html` と舞台本体に未コミットの更新が重なっています。HTML入口の分離は完了していますが、配信WorkerとMac版の識別子を同時に変更すると、進行中の舞台スケッチ更新・保存データ・認証Cookie・既存Mac設定を巻き込む可能性があります。

先にこの資料と読み取り専用チェックで境界を固定し、次の実装では対象ファイルの基準値を取り直してから、次の順で進めます。

1. 舞台ドメインから制作の書斎の静的資材を配らない。
2. 舞台用の配布ディレクトリをリポジトリ直下から分離する。
3. Mac版を舞台スケッチ名・新しい識別子・並行ZIPへ移し、旧配布物は削除しない。
4. 制作の書斎はローカル起動を維持し、公開先は必要になった時点で別途決める。

## 検査

```sh
node docs/app-separation-next-2026-09-12/check.mjs
```

終了コード `2` は、壊れたという意味ではなく「次段階の分離条件がまだ未達」を示します。現在はHTML入口だけが分離済みなので、未達項目があるのが想定結果です。
