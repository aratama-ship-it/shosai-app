# 発注書：3Dカメラ（自由に動き回るモード） 2026-08-18

Claudeが仕様を決め、Codexが実装し、Claudeが検証する。この文書だけを読んで着手できるように書く。

## 背景（別マシンのエージェントでも分かるように）

`shosai-app/` は依存なしの静的Webアプリ。舞台スケッチの本体は `stage-sketch.js`、
一人称の3D透視オーバーレイは `stage-first-person.js`（以下FPV）。
FPVは既にカメラ基底・透視投影・箱描画・演者スケルトン・ミニマップ・正面/平面の浮動小窓を持つが、
**カメラは「選んだ演者の目」か「客席」に固定**で、ドラッグで見回すだけ。移動できない。

本人（元サーカスアーティスト・ショー制作者）の要望：
> 演者目線の他に3Dカメラという機能で、ステージ上、もしくは客席も含めてどのようにみえるのかを
> 見るために自由に動き回れるモードが欲しい。動かし方はキーボードでいい。

決定事項（2026-08-18・本人が選択）：**FPS式・飛行あり**。
WASD＋上下移動＋マウスドラッグ見回し＋プリセット視点。**視点の名前付き保存は今回やらない**。

## やること

### 1. 自由カメラという第3の視点を足す

`state.view.type` に `"free"` を追加する（既存は `"performer"` と `"audience"`）。
FPVオーバーレイ上部の視点チップ列の**先頭**に「自由カメラ」チップを置く。
チップの色は既存の客席チップと区別できる色（例 `#d3ac59` 系ではなく `#7f9bb0` 等）にする。

自由カメラの位置と角度は `state.free = { x, y, z, yaw, pitch }`（ワールド座標・メートル、角度は度）に持つ。

- **他の視点から自由カメラへ切り替えたとき**、直前に見ていた位置と角度をそのまま引き継ぐ
  （演者の目の位置・その時のyaw/pitch）。ここで視点が飛ぶと、何を見ていたか分からなくなる。
- 自由カメラから他の視点へ移り、また自由カメラへ戻ったときは、**離れたときの位置を覚えている**
  （`state.free` を保持する）。オーバーレイを閉じると忘れてよい＝保存はしない。

### 2. キーボード操作

`onKeyDown` は現在 Escape と ←→ しか見ていない。**キーの押しっぱなしを扱う**必要があるので、
`keydown`/`keyup` で押されているキーの集合 `pressed` を持ち、毎フレーム移動を積分する。

| キー | 動き |
|---|---|
| W / S | 視線の水平投影方向へ 前 / 後 |
| A / D | 左 / 右（水平） |
| E | 上昇 |
| Q | 下降 |
| Shift（押しながら） | ダッシュ（速度3倍） |
| R | 客席中央プリセットへ戻す |
| ← / → | **既存のまま場面送り**（変えない） |
| Escape | **既存のまま閉じる** |

- 移動速度は既定 **2.4 m/s**、Shift併用で **7.2 m/s**。フレーム間の実時間（秒）を掛けて積分する
  （フレームレートで速さが変わってはいけない）。
- 日本語入力中など `event.isComposing` のときは無視する。
- キーは `event.code`（`KeyW` 等）で見る。JIS/US配列やCapsLockで壊れないため。
- **`view.type !== "free"` のときは WASD/QE/R を拾わない**（演者目線では移動しない）。
- オーバーレイを閉じるとき・ウィンドウがフォーカスを失ったとき（`blur`）は `pressed` を空にする。
  押しっぱなしのまま抜けると、戻ったときに勝手に動き続ける。

見回しは既存のポインタドラッグをそのまま使う（自由カメラでも同じ）。

### 3. 動ける範囲（クランプ）

無限に飛べると迷子になる。舞台幅 `W`・奥行き `D`・高さ `CEIL` から次の箱に収める。

- `x`: `-(W/2 + 12)` 〜 `+(W/2 + 12)`
- `z`: `-(D/2 + 8)` 〜 `+(D/2 + 22)`（＋側が客席方向。既存 `toWorld` の向きに合わせる）
- `y`: `0.2` 〜 `CEIL + 6`

### 4. プリセット視点

視点チップ列の下に、小さなボタン列で置く。押すと位置とyaw/pitchが決まる。

| 名前 | 位置 | 向き |
|---|---|---|
| 客席中央 | x=0, y=1.35, z=D/2+9 | 舞台を向く（yaw=180, pitch=-2） |
| 最前列 | x=0, y=1.2, z=D/2+1.2 | yaw=180, pitch=2 |
| 上手袖 | x=W/2+1.5, y=1.6, z=0 | 舞台中心を向く |
| 下手袖 | x=-(W/2+1.5), y=1.6, z=0 | 舞台中心を向く |
| 真上 | x=0, y=CEIL+4, z=0 | yaw=180, pitch=-88 |
| 舞台奥 | x=0, y=1.6, z=-(D/2+1) | yaw=0（客席を向く）, pitch=0 |

プリセットを押すと `view.type` は `"free"` になる（プリセットは自由カメラの初期位置という位置づけ）。

### 5. 画面表示

- **HUD**：自由カメラのときだけ、現在位置を舞台中心からの相対で出す。
  例 `前後 +9.0m ／ 左右 0.0m ／ 高さ 1.35m`。英語も出す。
  「舞台の中か客席側か」といった言葉での説明は不要。数字だけでよい。
- **操作ヒント**：既存の `hint` 要素を流用し、自由カメラのときは
  `W/A/S/D 移動・E/Q 上下・Shift 速く・ドラッグ 見回し・R 戻す` を出す。
  一度ドラッグかキー入力があったら既存と同じく消す。
- ミニマップに自由カメラの位置と向きを出す（既存の演者マーカーと別の色で）。

### 6. 舞台スケッチ本体からの入口

現在FPVへは「演者を選ぶ →『この人の視界』」でしか入れない。
**演者を選ばなくても3Dカメラへ入れる入口**を足す。

- `index.html` の「選んだもの」パネルではなく、**演者選択に依存しない場所**へ
  `id="stage-freecam-open"` のボタン「3Dカメラ」を置く。置き場所は
  `stage-fpv-open`（この人の視界）と同じ操作のまとまりでよいが、`hidden` の出し分けはしない＝常に出す。
- 押すと FPV を `initialView: "free"` で開く。既存の `fpv.open(bridge)` に
  `initialView` を足して受け取る（省略時は今までどおり）。
- `index.html` が正本。**`stage.html` は生成物なので直接編集せず、`python3 build_stage.py` を実行して作り直す。**

### 8. テスト（`tests/stage-first-person.test.mjs` へ追加）

FPVは `window.SHOSAI_STAGE_FPV._geom` に純関数を出してテストしている。同じやり方で足す。

`_geom` へ次を追加して公開すること：

- `moveFree(pos, forward, right, keys, dtSeconds, speed)` → 新しい `{x,y,z}` を返す純関数。
  `keys` は `{ forward, back, left, right, up, down }` の真偽値。
  - 前後は**視線の水平投影**を使う（真下を向いていても前進で沈まない）。
  - 斜め移動で速くならないこと（正規化する）。
- `clampFree(pos, W, D, CEIL)` → 上記3節の箱に収めた `{x,y,z}`。
- `freePresets(W, D, CEIL)` → 上記4節の表を返す。

書くテスト（最低限）：
1. `moveFree` で W だけ1秒 2.4m/s なら 2.4m 進む。
2. 前＋右の同時押しでも移動距離が 2.4m を超えない（斜めで速くならない）。
3. pitch が -88度（ほぼ真下）でも W の前進で y が変わらない。
4. `clampFree` が x/z/y をそれぞれ上下限で止める。
5. `freePresets` の「客席中央」が舞台を向いている（yaw=180）こと、「真上」の y が `CEIL+4` であること。
6. `moveFree` に dt=0 を渡しても位置が動かない（NaNにならない）。
