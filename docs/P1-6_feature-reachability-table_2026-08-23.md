## まず前提：分岐は「端末」ではなく「開き方」で決まる

到達性を左右するのは画面幅だけではなく、次の3つのコード分岐。

1. **`standaloneStagePage`**（`stage-sketch.js:938`）＝ `.topnav` が無いページかどうか。
   書斎アプリ本体 `index.html` は常に `.topnav` を持つため **false 固定**。
   これが true になるのは、単独配布用の `stage.html`（生成物。crew等へ共有する用途）を
   直接開いたときだけ。
2. **`tabletPwaActive`**（`stage-pwa.js`）＝ `stage.html` を**ホーム画面に追加してPWAとして起動**、
   かつ画面短辺600px以上のタッチ端末（iPad想定）。**`index.html`側にはこの分岐用スクリプト
   （`stage-pwa.js`）自体が読み込まれていない**ため、書斎アプリ本体をどうインストールしても
   このモードには入らない。
3. **`phoneViewerActive`**（`stage-sketch.js:943`）＝ 上の `standaloneStagePage` が true、かつ
   `tabletPwaActive` が false、かつ短辺600px以下のタッチ端末。つまり**「閲覧機」モードに
   落ちるのは stage.html 単独版をスマホで開いたときだけ**で、書斎アプリ本体をスマホで開いても
   発動しない。

**結論**: 今日のQA（`https://shosai-app.juggler-arata.workers.dev` ＝書斎アプリ本体）で
iPad/iPhoneのSafariを触る限り、レビュー資料が懸念していた「iPad専用メニューの機能欠落」
「スマホの閲覧機モード」はどちらも発動しない。これらが発動するのは、別途 `stage.html` の
共有リンクを開いた場合に限られる。

### ★Service Workerは stage.html にしか無い（2026-08-23 確認・QA計画に影響）

`serviceWorker.register` を持つのは `stage-pwa.js` のみで、それを読み込むのは `stage.html` だけ
（`index.html` の `<script>` 一覧 1976〜2001行に無い）。`index.html` は
`shosai-app.webmanifest` を持つのでホーム画面追加とスタンドアロン起動はできるが、
**キャッシュが無いためオフラインでは動かない**。

したがってQA項目「オフライン初回起動・更新直後の挙動」は、**公開URL直下(index.html)では
検証できず、`/stage.html` でのみ成立する**。

### ★リリース範囲の決定（2026-08-23・本人確定）

**`stage.html` 単独版を今回のリリースの品質基準・実機QAの対象に含める。**
（`build_stage.py` の記述どおりテスター配布用であり、`.assetsignore` に無いため公開バンドルに
含まれ、Basic認証の内側で `/stage.html` として到達可能。PWA・オフラインを検証できる唯一の入口。）
よって本表の右2列（iPad PWA／スマホ閲覧機）はリリース前の判断対象として有効。

### ★P1-6 の最終判定（2026-08-23・本人確定）※判断が一度覆っている

**判断の経緯を残す。同じ問いを繰り返さないため。**

1. 当初、舞台機構・3Dカメラの2件は**現状維持**と判断された。理由は
   「iPadは現場での確認機で、機構編集・3D確認はPCで行う」という役割分担。
2. その後、**「書斎アプリは限定的な身内用途、舞台スケッチは将来的に汎用リリースアプリ」**
   という前提が示された。
3. これを受けて**「入口を足す」へ判断が覆った。** 身内の道具としてなら
   「うちはPCでやる」で筋が通るが、配布物としては同じ前提を外部利用者と共有できないため。

**教訓**: 到達性の欠落をどう扱うかは「誰が使うのか」で答えが変わる。
身内用か配布物かを先に確認してから判断を仰ぐこと。

**確定した対応:**

| 対象 | 対応 |
|---|---|
| 舞台機構（#6） | iPad PWAに入口を足す（`TABLET_MENU_GROUPS` へ登録） |
| 3Dカメラ（#14） | iPad PWAで押せるようにする（ツール退避対象へ追加） |
| AI指示（#13） | **足さない。** Macアプリ専用機能であり、現状で正常 |

### ★二つの製品の区別（2026-08-23・本人確定）

- **舞台スケッチ**（`stage.html`）＝ 将来の**汎用リリースアプリ**。配る。品質基準は高い。
- **書斎**（`index.html`）＝ 資料棚・名簿・制作机。**限定的な身内用途。配らない。**

舞台スケッチは書斎の中からも使えるが、人へ渡すのは単独版のほう。
この区別は機能一覧UI（`docs/feature-matrix-preview.html`）にも反映済み。

**意図的と確認できたもの（変更不要）**: 閲覧機モードでの光の意図重ね非表示、
閲覧機モードでのツール制限（コード内コメントに設計意図が明記されている）。

**判断の余地が残るもの**: iPad PWAの3ウェイ表示切替（#15）。単一ビュー化自体は意図的な設計に
見えるが、本番で「正面と平面を同時に見たい」場面があるなら再検討の対象。
