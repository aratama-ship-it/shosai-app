# ロミオとジュリエット — 舞台スケッチ全体サンプル v1

2026-09-11時点の通し稿から作った、後で編集する前提の開発用サンプルです。本人の最終推敲・実会場での稽古は未実施。

人間向け入口は `index.html` または `ロミオとジュリエット_舞台スケッチ用サンプル_オフライン.html`。単体で移しても読み込み用JSON・対応JSONを保存できます。

## 読み込むファイル

`romeo-juliet-full-show.stage-sketch.json`

- `kind: shosai-stage-sketch`, `version: 3`。現行アプリの「ショー → 詳細設定 → 読み込む」で選択し、「別のショーとして開く」。
- 3大場面はdepth 0のsection、28配置はdepth 1のscene。物語の場面数を増やしたのではありません。
- 10名を固定castIdで識別。匿名群衆を兼ねるときは駒の色と場面説明で示す。名簿の名前は役を担当するスロット名で、実際の演者は未割当。
- 13セット＝仮面10枚、バー・カウンター、背面棚の見立て、低い腰掛け。2つの舞踏会配置では仮面を各演者の顔へ装着。
- 照明は `lightingIntent`。音源・灯体、仮面以外の小道具の駒は未配置。
- 仮尺1745秒（29:05）。転換時間はhold内に計上し、`transitionToNextSeconds=0`。物理的に転換が瞬時という意味ではありません。配置間の仮配分は元の動作ブロック数による。`cueSeconds`（画面の補間再生）はnull。
- 舞台12m×9m、既定の高さ8m、身長165cm、セット寸法は表示用仮値。実測の会場寸法や人体測定値ではありません。

## 一緒に渡すファイル

`romeo-juliet-full-show.handoff.json`

- 3大場面・19キュー・28配置と、アプリのsection/scene/cast/pieceのIDを対応させる。
- 74動作・47台詞、提案／既存下訳の区別、元の台詞ID、演出・音楽構想・小道具の流れを全文保持。
- `sourceShow` は元稿のスナップショット。舞台図の生の色は古い値を含むため、描画時は `familyPalette` を適用する。正規化済みの色は読み込み用JSONまたはframes.roleAssignments.nativeColorを使用する。
- 原図は0°=奥、アプリは0°=客席。`(180-sourceFacing)%360` で変換。背中はstand+180°、横たわる姿は現行ブラウザのsupine。古いMCP入力定義のlie_backは現行ブラウザではstandに戻るため使わない。
- 直線動線は制御点を中点に明記。省略するとアプリが0.5/0.5を補い、図の直線が変わる。
- 現行アプリの説明欄は編集時200文字まで。本文を詰めると編集時に消えるため、native scene.noteは短い要約のみ。全文はこのJSONと付属HTMLに置く。台本キュー機能そのものの実装は含まない。
- 共有キューの `project.cues` は現行の読み込み正規化で保持されない。未対応フィールドをnative JSONへ混ぜない。台本のページ／行／文字範囲アンカーを推測生成しない。

## 後から修正する場合

アプリで変更したデータはアプリから新しいJSONとして保存してください。`build_sample.py` は元稿から派生物を再生成するもので、アプリでの編集を取り込む処理ではありません。元稿も変える場合、再生成前にアプリでの変更を退避し、対応IDで差分を確認します。

「別のショーとして開く」ではproject.idが変わります。配置IDとcastIdは保持されるため、開発側は対応表からそれらを参照してください。手動複製で新しくなった配置IDは改めて対応付ける必要があります。

## 生成・検証

このフォルダで実行：

```sh
python3 build_sample.py
node validate_sample.mjs
```

生成元は `../../full-show/show.json` と `../../stage-visuals/layouts.json`。元稿が古い場合は入力ハッシュの検査で停止します。出力のハッシュと確認したアプリコードのハッシュは対応JSONに記録。

ブラウザ検証にはPlaywrightが必要です。このMacでは `/Users/arata/.venvs/design-lint/bin/python` に導入済み。リポジトリを127.0.0.1で配信し、`RJ_QA_BASE_URL=http://127.0.0.1:18759` を指定して `check_sample.py` を実行します。新規ブラウザコンテキストで検証し、本人の既存ショーには書き込みません。
