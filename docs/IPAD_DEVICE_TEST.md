## 実装済みの前提（コード確認済み・2026-08-03更新）

実機テストの前に、何が既にあるかを把握しておく。

- **1本指ドラッグと2本指ピンチは同じCanvas上で共存する設計。** Pointer Eventsで指を`touches`
  というMapに集め、2本目が触れた瞬間に駒のドラッグを解除してピンチ（ズーム）へ切り替える
  （`stage-sketch.js` 9985〜10030行付近の `pinchPair`/`beginPinch`/`movePinch`）。
  「2本目が置かれた時点で、拡大の操作へ移る」とコード内コメントにある。
- Canvas・ドラッグ用グリップには `touch-action: none` が指定済み（ブラウザの既定スクロール/ズーム
  ジェスチャーとの衝突を避ける狙い）。
- ズームは押しボタン（`stage-plan-zoom-in`/`-out`）とピンチの両方から呼べる。
- `pointerType === "touch"` を特定の3箇所だけで分岐している。**Apple
  Pencil（`pointerType === "pen"`）を特別扱いするコードは無い** ため、Pencilでの単発タップ・
  ドラッグは通常のマウス的ポインタとして扱われるはずだが、確認されていない。
- **モーダルは7つ**（2026-08-03に2つ追加された）: `stage-export-modal` / `stage-import-modal` /
  `stage-map-modal` / `stage-prefs-modal` / `stage-rehearsal-export-modal` / `stage-about-modal`
  （「このアプリについて」。日英の長文が入るので、iPadでの縦スクロールが特に効いてくる）／
  `stage-beat-templates`（「構成テンプレートから作る」。10種のカードが縦に並ぶ一覧で、
  既存モーダルより中身が長い。スクロールと個々のカード内ボタンのタップ域を両方見る）
- ファイル読み込みは標準の `<input type="file" hidden>` 2箇所（JSON読み込み・写真読み込み）。
  iPad標準のFiles/Photosピッカーに委ねる作りで、独自UIは無い。
- **ボタンの最小高さが44pt未満の箇所が多数ある。** `style.css` の `min-height` 指定を数えると
  22px〜32px台が大半で、Appleの推奨タップ域44ptを満たさない箇所が広く残っている
  （例: 6482行 `.stage-center-bar button { min-height: 27px; }`）。**改修は今回の範囲外。
  実機でどこが本当に押しにくいかを特定するのがこのテストの役目。**
- **縦横画面（orientation）専用のCSSは無い。** 幅ベースのブレークポイント（`max-width`）のみで、
  `orientation: portrait/landscape` の指定は見つからなかった。iPadを回転したときの挙動は
  幅の変化にどれだけ追従するか次第。
