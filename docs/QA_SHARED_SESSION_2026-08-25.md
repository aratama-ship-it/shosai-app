## 何を確認するか（3項目）

工程表より。特に③が最重要（クッキーログイン移行後に新設した中継経路の確認）。

1. ホストが何も触っていないのに、他の画面へ「いま操作中: ◯◯」バナーが出続けないか
2. ゲストの操作（演者・道具の移動、矢印）が、ホストの保存やdoc再配信のたびにリセットされないか
3. **ゲストAの操作が、ホスト経由でゲストBの画面にも反映されるか**（ゲスト→ホスト→他ゲストの中継）

**★Macアプリ（制作の書斎）からは開始できない**（2026-08-25 実測。HTTP 404）。
Macアプリはページをローカルのファイルから読み込むため、Cloudflare上にしかない
セッションAPI（`/session/new`）へ届かない。ホストも必ずブラウザで公開URLを開くこと。

## 準備するもの

- ブラウザタブ3枚（同一端末でも可。別々のプロファイル/プライベートウィンドウ推奨。
  同じCookieを共有すると3枚とも同じログイン状態になり見分けが付きにくいため）
- ホスト用ログイン: 本人のID/パスワード（SITE_USER/SITE_PASS）
- ゲスト用ログイン: GUEST_USER/GUEST_PASS（Cloudflare Secretsに設定済み。値は本人のみ）
- 公開URL: `https://shosai-app.juggler-arata.workers.dev`

**注意**: `REALTIME_SESSION_DESIGN.md` の使い方欄はBasic認証時代の記述のまま（未更新）。
2026-08-24〜25にクッキーログインへ移行済みなので、実際は下記の手順（`/sign-in` 画面に
ID/パスワードを入力する形）になる。Basic認証のポップアップは出ない。

## 手順

### 1. ホスト（タブ1）

1. `https://shosai-app.juggler-arata.workers.dev/stage.html` を開く
2. `/sign-in` 画面が出るので、本人のID/パスワードでログイン
3. 適当なショーを開く（新規でも既存でもよい）
4. 左下あたりの「リアルタイム共有（会議用）」パネルを開く
5. 表示名を入れて「セッションを開始」
6. 「招待URL」が表示されるので「コピー」（`stage.html#session=` から始まるURL）

### 2. ゲストA（タブ2）・ゲストB（タブ3）

1. コピーした招待URLを開く
2. `/sign-in` 画面が出るので、**ゲスト用ID/パスワード**（GUEST_USER/GUEST_PASS）でログイン
   （本人用IDでログインすると自分のショーが開いてしまうので使わない）
3. 表示名を聞かれるので、タブ2は「ゲストA」、タブ3は「ゲストB」など区別できる名前を入れる
4. 参加すると自分の作業（あれば）が自動でショー一覧へ退避される旨の案内が出る

### 3. 確認①: 「操作中」バナーの張り付き

1. 3タブとも数十秒、誰も何も操作せず放置する
2. ホスト・ゲストA・ゲストB、どの画面にも「いま操作中: ◯◯」バナーが**出続けていない**ことを確認
   - 誰かが操作した直後の約3秒だけ出るのが正しい挙動。ずっと出ている・消えないのはNG

### 4. 確認②: ゲストの操作が消えないか

1. ゲストA（タブ2）で、演者か道具を舞台上でドラッグして動かす
2. ホスト（タブ1）で、何かしら軽い変更をして保存する（例: シーンの説明を1文字変える→自動保存、
   または「書き出す」ではなく通常の編集操作でよい。doc再配信が起きればよい）
3. ゲストA（タブ2）の画面に戻り、**手順1で動かした演者・道具の位置がリセットされていない**ことを確認
   - ホストのdoc再配信でゲストの未反映操作が消えるのがNG。消えていなければ正しい

### 5. 確認③(最重要): ゲストAの操作がゲストBに見えるか

1. ゲストB（タブ3）の画面を見ながら、ゲストA（タブ2）で演者をドラッグして動かす
2. **ゲストB（タブ3）の画面上でも、ゲストAが動かした演者が同じ位置に動くこと**を確認
   （ホスト経由の中継。数秒以内に反映されるはず）
3. 同様に、ゲストAで矢印を描いてみて、ゲストBの画面にも矢印が出るか確認
4. 逆方向（ゲストB→ゲストA）も同様に確認しておくとより確実

### 6. 後片付け

- 3タブとも閉じるか、ホストでセッションを終了する（全員退出後10分で自動消滅）
- ゲスト用ログインのCookieが端末に残るのが気になる場合は、そのブラウザプロファイル/
  プライベートウィンドウを閉じればよい（`/sign-out` でも可）

## 結果の記録（2026-08-25 本人実施・完了）

構成: ホスト=Macアプリ（発注書Dのネイティブ中継）、ゲスト=Safari＋Chrome。

- ①バナー張り付き: **問題なし**
- ②ゲスト操作のリセット: **問題なし**
- ③ゲストA→ゲストBの中継: **問題なし**（641a27dの修正が実機で効いていることを確認）

### 検証中に見つかった別件（発注書Eへ）

1. **初回ログインで招待URLの `#session=` が落ちる**（Chromeで発生）。
   フラグメントはサーバーへ送られないため `next` に含まれず、ログイン後に
   セッション番号なしの stage.html へ着地して初回チュートリアルが始まる。
   2回目はログイン済みのため直行でき、直ったように見える。
2. **ホストのシーン切替時、ゲスト側で転換アニメーションが再生されない**（瞬間移動になる）。
3. **ゲスト表示と権限**: ゲストであることを大きく表示したい。操作は
   **レーザーポインタ＋矢印のみ**へ絞る（駒の移動を外す）と本人確定（2026-08-25）。
