# 制作の書斎（Phase 0 プロトタイプ）

ショー・演出リファレンスを、制作の問い・場面案・ビジュアル試作へつなぐ個人用の作業空間。

- メイン: **資料棚** — 作品データベースの閲覧（一覧・検索・詳細＋関連作品/関連表現の自動集約）
- サブ: **制作会社**（公式根拠つきの探索地図）／**名簿**（スカウティングレポートの演者名簿・要合言葉）／**制作机**（場面スタディ・ビジュアル比較）／**舞台スケッチ**（劇場形式5種・規模プリセット・正面/平面・PNG書き出し）／**スクラップブック**（種火を配る＋紙面へ貼って残す）／**場面問答**（判断のエクササイズ）

## 名簿タブ（個人情報を扱う）

- データは**書斎側に置かない**。同一オリジンの `scouting-report-app/data/data.enc` を読み、合言葉で復号する。週次タスクでシートが更新されればこちらにも反映される
- 防御は画面を隠すことではなく**暗号化そのもの**（AES-256-GCM / PBKDF2-SHA256 15万回）。合言葉がなければ `data.enc` を直接落としても読めない
- 合言葉の端末保存キー `scout_pass` はスカウトアプリと共有する。どちらかで解錠すればもう一方も開く。**この共有があるため、書斎アプリへ外部スクリプト（CDN・解析タグ）を持ち込まない**
- `file://` では動かない（fetchがブロックされる）。名簿タブだけは公開URLから開く
- 名簿は読むだけ。ここから編集・追記はしない（元アプリとシートが正）

## 使い方

`index.html` をブラウザで開くだけ（静的・依存なし）。

## データ

- `db.js` は正本データ（`../show-reference/data/*.json`、リポジトリ外）から生成した読み取り専用の索引
- 正本更新後の再生成: `python3 build_db.py`
- コード変更時は `index.html` 内の `?v=` を上げる（キャッシュ対策）
- **コード変更のコミットと、索引再生成のコミットは分ける**（履歴でコードの変更を追えるようにするため）
- 索引を何度も再生成した後は `git gc` で回収する（looseオブジェクトが溜まると .git が数十MBに膨らむ。gc後は全履歴込みで約5MB）
